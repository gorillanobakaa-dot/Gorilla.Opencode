# Gorilla Opencode v0.1.90 — the program stops burning your battery, your permissions follow you, and the bill is stated out loud

Released 17 August 2026, eight commits after v0.1.89. This is the release where
the research feature stopped being a demonstration and started being honest
about what it costs. Four faults were found by running it for real, measuring
the result, and comparing it against what the screen said: the program burned a
third of a CPU core doing nothing, permission approvals did not carry between
helpers, a helper waiting for an answer that never came waited forever, and the
token counter that should have warned about a large run was structurally
incapable of moving.

Alongside those, the intelligence dossier was renamed to what it actually is and
given a published judgement standard, and two commands that had been built and
finished were made reachable.

This is the same document in two registers. The plain-language track assumes no
prior knowledge and omits nothing significant. The developer track is precise
enough to audit and rebuild from. Both end with a claim-source table saying
which statements this release measured and which it inferred — see
[PHILOSOPHY.md](../PHILOSOPHY.md) for why.

## Plain-language track

### Why This Release Exists

Four things were wrong, and every one of them was found by measuring rather than
by reading code.

**The program was busy when it was doing nothing.** A brand-new instance, in an
empty folder, with no conversation at all, used 35% of a processor core just
sitting there. With a real conversation loaded it used 59%. On a laptop that is
your battery draining while you read the screen; on an old machine it is the fan
running for no reason.

**Approving something once was not enough.** When the research feature runs, it
starts several helpers, and each helper is treated as a separate conversation.
Approving "allow for this session" in one helper told the others nothing. In a
run with ten helpers, the same question could be asked ten times. It was seen
live: the same web search asked for permission at 19:43, again at 19:45, and
again at 19:49.

**A helper that asked a question nobody answered stopped forever.** The code even
had a comment saying it waited "with a timeout". There was no timeout. Three
helpers stopped at 19:43 and 19:53 and were still being counted as running at
20:09 — no network activity, nothing written for fifteen minutes, and no way to
tell from the screen.

**The counter that should have warned about a big run never moved.** Eight
helpers used 248,122 tokens of input and 32,622 of output — 280,744 in total —
while the status bar said "13.3K in / 630 out, spent $0.00" and stayed there.
Tokens are the thing you are billed for. A number that cannot change is not a
safeguard.

### What You Will Notice

**the program at rest**
- Before: 35% of a processor core with nothing open, 59% with a conversation loaded.
- After:  9% idle. The spinning "working" indicator now only ticks while it is actually on screen.
- Affects: everyone, most on laptops and older machines

**typing while helpers are running**
- Before: With eight helpers streaming, keystrokes queued up behind the backlog. Escape and the arrow keys appeared not to work and the program looked frozen.
- After:  The same cause is gone, so input is not competing with a redraw eight times a second.
- Affects: anyone running the research feature

**permission prompts during a research run**
- Before: Approving in one helper did nothing for the others; the same prompt could return several times in one run.
- After:  An approval covers the whole conversation, including every helper it started. It does not become a wider permission: the tool, the action and the path still have to match exactly, and an approval in one conversation cannot cover a different one.
- Affects: anyone running the research feature

**a helper that gets stuck waiting**
- Before: It waited for an answer forever, and the screen said "3 helper(s)" and "Waiting for tool response…" — both true, neither useful.
- After:  It waits at most ten minutes, then refuses the request and records it, so the lane fails visibly instead of hanging. Killing a helper now also releases it immediately.
- Affects: anyone running the research feature

**the running total**
- Before: Helper tokens were never added up anywhere, and because every helper's cost on a free or flat-rate plan is genuinely £0.00, the code that wrote the total skipped writing anything at all.
- After:  Helper input and output tokens are added to the session, and writing the total no longer depends on the cost being above zero.
- Affects: everyone, and most of all anyone on a plan where they pay per token

**the warning screen before an intelligence run**
- Before: It told you the cost per minute and compared it to "12 ordinary questions' worth". Both true, and both read as reassuring. The screen was also a fixed 110 columns wide, so on a narrow terminal it was cut off.
- After:  It states the size of the run in the unit that matters. From the measured rate — 21,596 tokens a minute across eight helpers — a ten-helper supervised run works out at roughly **2.9 million tokens an hour**. That is about $13 an hour at Claude-Sonnet-class pricing, or about $6.70 at GPT-5-class. The screen says these figures are measured, not modelled, and it now fits the terminal it is drawn in.
- Affects: anyone about to start an intelligence run

**`/compact` and `/init`**
- Before: Both were finished and working, and typing them answered "Unknown command". They existed only in the ctrl+k command palette.
- After:  Both are typeable and documented. `/compact` shortens a long conversation so it keeps fitting; on the small, free models this project is built for, that is the difference between a session that survives and one that quietly degrades.
- Affects: everyone, most on small-context models

**a new command, `/yolo`**
- Before: Every permission prompt needed a person at the keyboard, so a long research run could not be left alone.
- After:  `/yolo` (also `/auto` and `/autopilot`) approves everything for the conversation you are in, so helpers run unattended. `/goal <task>` turns it on and sends the task in one line. It is limited on purpose: one conversation only, never written to disk, switched off by typing `/yolo` again, and a red "☢ YOLO — auto-approving" sits in the status bar on every frame while it is on. The warning appears whichever way you turn it on.
- Affects: anyone who wants to start a long run and walk away

**a heartbeat while helpers work**
- Before: A silent screen looked identical to a crash.
- After:  Every 90 seconds, while helpers are actually running, one of four rotating lines reports how many are running and how long the longest has been at it. It ticks only while helpers run, so it does not become a second reason for the program to be busy at rest.
- Affects: anyone running helpers, especially on slow models or slow links

**the intelligence feature's name**
- Before: Both rows said OSINT and nobody could tell which was which.
- After:  The heavyweight one is "OSINT All-Source — /osint" and the everyday one went back to "Research helpers — /research", which it should never have stopped being.
- Affects: anyone opening `/context`

**how findings are worded**
- Before: An AI answer states everything in the same steady voice, whether it is certain or guessing.
- After:  Helpers now follow the UK Government's published standard for all-source intelligence assessment. Likelihood must be one of seven fixed phrases with published percentage bands — remote chance, highly unlikely, unlikely, realistic possibility, likely/probable, highly likely, almost certain — and inventing a percentage is forbidden by name. Separately from that, each judgement carries a confidence rating of HIGH, MODERATE or LOW. Keeping the two apart matters: "highly likely, LOW confidence" is a real and useful thing to say. Every line is marked FACT, INFERENCE or ASSUMPTION.
- Affects: anyone using `/osint`

**more places to look**
- Before: arXiv, bioRxiv and medRxiv were in the 985-source registry but missing from the one-page map helpers actually carry, so a helper had to already know arXiv existed to reach for it.
- After:  All three are on the map, labelled as preprints that have not been peer-reviewed.
- Affects: anyone researching scientific or medical topics

**what a research run costs, honestly**
- Before: A run that burned 507,935 tokens across seventeen helper sessions reported 44,688 in the status bar, and $0.00. On a free plan the cost can only ever read zero however much you burn, and helper usage was never counted at all.
- After:  The number counts the whole run — the conversation and every helper under it. It is worked out when it is displayed rather than stored, which is why it is also correct for runs that already happened. Measured on the developer's own machine: 58,551 before, 851,996 after, for the same conversation.
- Affects: anyone who runs `/research` or `/osint`

**your research survives the write-up failing**
- Before: If the program ran out of room while writing the assessment, everything was lost. It happened: a two-hour run that verified three claims by hand announced "writing the dossier now" and wrote nothing at all.
- After:  Every helper's graded report is saved to a file the moment the run finishes — by the program, before the AI is asked to do anything with it. The file says plainly that it is not the finished assessment and how to turn it into one.
- Affects: anyone doing long research, especially on a slow connection

### Deliberately Not Done

- **Restarting a helper that has died was designed and then abandoned.** The plan
  was a fixed inactivity threshold — if a lane says nothing for N minutes,
  restart it. Then a lane went silent for 23 minutes and came back with 19,118
  tokens of real work. Any threshold that sounded reasonable — three minutes,
  five, ten — would have killed that lane and paid to redo work already on its
  way. It needs a signal that is not the clock, and there isn't one yet, so
  nothing was built on the guess.
- **One stuck lane still holds up a whole run.** Supervision only starts after
  every helper in the first wave has finished.
- **The stranded-lines report from the Arch/CachyOS tester is still open.** The
  v0.1.89 fix was a plausible cause and remains unconfirmed against his machine.

### How to Install

```bash
sudo apt install ./gorilla-opencode_0.1.90_amd64.deb        # Debian/Ubuntu
sudo pacman -U gorilla-opencode-0.1.90-1-x86_64.pkg.tar.zst # Arch/CachyOS
```

Use `apt` rather than `dpkg -i` so the `lynx` dependency is resolved.

**After installing, close the program and start it again.** Installing a new
build does nothing to a copy that is already running. This caused real confusion
during testing: a fix was confirmed installed and then tested against a process
started minutes earlier, so it looked as though nothing had changed.

### Bottom Line

The program is quieter at rest, stops asking you the same question, cannot hang
silently on a question nobody answered, and states the real size of an expensive
run before you start it. The honest part is not the fixes; it is the number on
the warning screen. Roughly 2.9 million tokens an hour is not a reassuring
figure, and it was previously described in units that made it sound like small
change.

## Developer track

### Summary

Eight commits.

**`tui`: spinner lifetime.** bubbles' spinner schedules its next tick from inside
`Update`, so the command chain started at `Init()` ran for the life of the
process — 8 ticks/second, each a `tea.Msg`, each forcing a full `View()` over
the whole UI. Cost therefore scaled with transcript size, which is why an empty
instance cost 35% of a core and a loaded one 59%. The spinner is only DRAWN
while the agent is working, so the chain now lives exactly as long as it is
visible: `Init` no longer starts it, work starts it, and declining to forward a
tick lets it lapse. Measured result 9% idle. The input starvation reported as
"esc and the arrow keys don't work" with 8 helpers running was the same cause,
not a key-handling bug.

**`permission`: grants resolve to the session tree root.** A remembered grant
matched on the session id that asked, and every research helper runs in its own
session (`CreateTaskSession`, one per lane). The service now records parentage
(`RegisterChildSession`, called by both the research tool and the sub-agent
tool) and resolves a request to the root of that tree before checking grants.
Scope is unchanged: tool, action and path still match exactly and a grant in one
conversation cannot cover another, both pinned by tests.

**`permission`: the wait is bounded and a kill releases it.** A bare `resp :=
<-respCh` under a comment promising a timeout. Now a 10-minute bounded wait —
generous, because people walk away mid-prompt — that DENIES and logs on expiry
so the lane fails loudly. Separately, killing a helper releases whatever it was
blocked on immediately: cancelling the context was never sufficient, because a
tool parked on the permission channel does not watch `ctx`. `CancelSession` is
scoped to one conversation; the first version swept every pending request in the
process, which would have cancelled other conversations' prompts.

**`research`: token rollup, and the gate states the real size.** Two stacked
failures. Helper tokens were never aggregated anywhere — only cost was. And on a
free or flat tier every helper's cost is legitimately 0.00, so the rollup's
`if total > 0` guard skipped the write entirely; the one number capable of
warning was structurally incapable of changing. The parent session now
accumulates helper prompt AND completion tokens, and the write no longer depends
on cost being non-zero. `helperSpend` carries cost and both token counts
together so they cannot drift apart again. The gate prints the projected
2.9M-tokens/hour figure with its per-session rate, labelled measured rather than
modelled, and is now full-width (it was `min(110, …)`).

**`commands`: palette entries are not commands.** `/compact` and `/init` were
registered in the ctrl+k palette only; typing them returned "Unknown command".
Third instance of a trap CLAUDE.md already records for `/usage`.
`TestEveryPaletteCommandIsAlsoTypeable` now reads both lists and fails if a
palette entry is not typeable AND documented in `/help`; proven non-vacuous by
unhooking `/compact`, which the test then names.

**`commands`: `/yolo`, `/auto`, `/autopilot`, `/goal`.** Grants everything for
the current conversation. Deliberate limits: scoped to one conversation, never
written to disk so impatience cannot become a standing grant, reversible with a
second `/yolo`, and a red `☢ YOLO — auto-approving` in the status bar on every
frame while it is on. `/goal <task>` arms and sends in one line; the warning
fires either way, because a warning that can be skipped by adding an argument is
not a warning.

**`tui`: still-alive heartbeat.** Every 90 seconds while helpers are running,
four rotating lines report the count and the longest running time. Ticks only
while helpers run and lapses otherwise — the same discipline the spinner now
follows, because a heartbeat burning CPU at rest would undo the earlier fix.

**`osint`: rename and the UK PHIA judgement standard.** The row reads "OSINT
All-Source — /osint"; the everyday tool returns to "Research helpers —
/research". Ported into the helper prompts: the PHIA Probability Yardstick
verbatim (seven terms, published bands, deliberate gaps preserved, self-invented
percentages forbidden by name); the Analytical Confidence Rating (HIGH/MODERATE/
LOW against information base, analytical rigour, complexity and volatility) kept
SEPARATE from likelihood; FACT/INFERENCE/ASSUMPTION labelling; multiple
distinct, plausible, falsifiable hypotheses with assumptions challenged; and
analytical integrity. Admiralty grading (ATP 2-22.9) and the yardstick are
complementary and both appear — the letter+digit grades a SOURCE at collection
time, the yardstick and confidence express the JUDGEMENT built on it. Credited
under the Open Government Licence v3.0 with the explicit statement that this
project is not endorsed by, affiliated with, or connected to the UK Government,
PHIA, or any government body, which that licence requires. `AllSourceProductName`
is now the single source of the name; the `/osint` page had carried a
hand-typed second copy.

**Also in the cycle.** `+RUN` marker and legend on `/context`, because a row
labelled expensive sat beside the screen's smallest number in a different unit.
`DossierSchemaTokens` measured BY DIFFERENCE between the two real schemas —
summing the strings under-reported by 5 tokens, and calibration had measured the
research tool WITHOUT the doctrine block, so armed, the same tokens were counted
in two rows. arXiv, bioRxiv and medRxiv added to the embedded source atlas,
labelled unreviewed.

### Known Alternatives Considered

- **A fixed inactivity watchdog for dead helpers.** Designed, then abandoned
  against measurement: a healthy lane was silent for 23 minutes. Any threshold
  that reads as reasonable would have killed it and doubled its cost redoing
  work already in flight. Fixed thresholds are wrong on these models. Deferred
  until a signal exists that is not the clock.
- **Sweeping all pending permission requests on cancel.** Written first, then
  rejected: it would have cancelled other conversations' prompts. `CancelSession`
  is scoped to one conversation.
- **Widening the grant to cover any helper.** Rejected. Parentage resolution
  gives the same ergonomics without loosening what a grant means; tool, action
  and path still match exactly.
- **Keeping the gate's per-minute framing.** Rejected. "About $0.03/min" and "12
  ordinary questions' worth" are both true and both read as reassuring. The unit
  had to be the one that hurts.

### Late Additions After This Document Was First Drafted

Two changes landed after the body above was written, both from live use:

**Token totals are COMPUTED, not stored.** The first implementation added helper
tokens into the parent session's `PromptTokens`. It was wiped within seconds,
every turn, because `internal/llm/agent` ASSIGNS that field
(`sess.PromptTokens = usage.InputTokens`, not `+=`) at the end of each turn —
observed as 522,261 followed by 44,688. The total is now one SQL sum over the
conversation and its children (`internal/db/helper_totals.go`, hand-written so
an sqlc regeneration cannot drop it), filled in on `Get` and before publishing
an update, exposed as `Session.TotalTokens()`. Nothing writes it, so nothing can
overwrite it, and it is correct retroactively.

**Findings are salvaged to disk by the program.** `research_salvage.go` writes
every lane's graded report — including `LANE UNCOVERED` markers and supervisor
audits — to `config.DossierDir()` the instant a run completes, before the
orchestrator is asked to assemble anything. The tool's report tells the model
where they went and instructs it to say so plainly if it runs out of context
rather than quietly producing a shortened dossier. A write failure is logged and
survivable: a run that produced good findings is never reported as failed
because a disk write went wrong.

### Architecture Impact

The permission service gains a session-parentage map and resolves to a tree root
before matching; this is the first time the permission model has acknowledged
sub-agents, which post-date it. Every ticker in the TUI now follows one rule:
a periodic command exists only while the thing it drives is on screen or
running. `helperSpend` becomes the single carrier of cost and tokens together.
Dialogs may not draw wider or taller than the terminal — `/context` was a fixed
106 columns and the `/osint` gate a fixed 110. `internal/llm/agent` gains
`configtest.Isolate`; its tests had written through to the developer's real
`loadout.json` and armed the dossier row on his machine — the fourth time that
class has bitten. Both packaging scripts now refuse a binary whose `--version`
disagrees with the requested version.

### Known Issues

**[high]** A long research run can fail at the final write-up, and the failure gets MORE likely the better the research went.
- Cause: Assembling the assessment is the most context-hungry moment of a run, and the agent doing it is the same one whose context is already full of the research. Measured 2026-08-17: a run reached 145% of the model's window and wrote nothing. The findings themselves were only ~15,045 tokens; what filled the window was tool traffic, a raw JSON dump and two hours of reasoning.
- Remedy: The graded findings are now saved to disk automatically before that step, so the work survives. Re-assembling them into a polished dossier from a clean context (`/osint --recover`) is designed and NOT yet built — it is the next piece of work.

**[high]** A running process does not pick up a newly installed binary.
- Cause: Installing a package replaces the file on disk; an already-running process keeps executing the image it started with. This is ordinary operating-system behaviour, not a defect in this program, but it defeats verification.
- Remedy: Restart the program after installing. During this cycle, fixes were confirmed installed and then tested against a process started minutes earlier, so results looked unchanged.

**[medium]** Restart-on-death for a dead helper is not built.
- Cause: A fixed inactivity threshold was designed and abandoned as unsafe — on these models a healthy lane was silent for 23 minutes, so any plausible threshold would have killed working lanes and doubled their cost.
- Remedy: Needs a liveness signal that is not the clock. None exists yet, so nothing was built on the guess. The 90-second heartbeat is observability, not recovery.

**[medium]** One stuck lane holds the whole run.
- Cause: Supervision begins only after every first-wave lane has finished.
- Remedy: The 10-minute permission timeout removes one way a lane can stall indefinitely. It does not make supervision incremental.

**[medium]** Stranded frame lines on an Arch/CachyOS tester's terminal. (reported on v0.1.87, still open)
- Cause: Unknown. v0.1.89 fixed a bug of the same class and remains the leading hypothesis; nothing in this release reproduced his report.
- Remedy: Needs his terminal emulator, font, `$TERM`, terminal width, and whether a dialog was open.

**[low]** The `/osint` cost forecast rests on assumptions.
- Cause: The 2.9M-tokens/hour projection extrapolates one measured rate (21,596 tokens/minute across 8 helpers) to 18 sessions. Model, prompt length and how much a run reads all move it.
- Remedy: The three assumptions are printed beside the number, and the per-session rate is shown so the figure can be recomputed rather than trusted.

**[medium]** Old conversations are missing from the history list. (deferred to unscheduled)
- Cause: Unchanged from v0.1.85: the session store moved and the previous files were not migrated.
- Remedy: The old files remain in the old location. No migration exists.

**[low]** `TestExactLongPromptWrapsAtTerminalWidth` passes against a reverted fix. (deferred to unscheduled)
- Cause: Unchanged from v0.1.86: the test is vacuous with respect to `measuredRows()`.
- Remedy: Write a screen-driven regression test. v0.1.89 found a second vacuous test by the same reasoning; the class is still worth a sweep.
