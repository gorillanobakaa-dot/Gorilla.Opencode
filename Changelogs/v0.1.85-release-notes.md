# Gorilla Opencode v0.1.85 — the fork takes its own name, and the prompt stops hiding your words

Released 16 August 2026. Replaces v0.1.84.

Two documents cover this release in full: this one, and the plain-language and developer
session records linked at the end. Neither track below is a summary of the other.

---

## Plain-language track

### What you could see

Type a long sentence into the chat box and it stayed on one line. When the sentence
reached the right-hand edge of the screen it slid sideways instead of wrapping downwards,
so the beginning disappeared off the left while you were still typing the end. The words
were never lost — pressing Enter sent all of them — but you could not read back what you
had written. That is fixed: the box now grows downwards and keeps everything visible.

### What you could not see

This program is a fork: a copy of a project called OpenCode, taken in a different
direction. It had kept the original's habit of naming everything it saved — settings,
saved conversations, scratch files — after *that* project. On a computer running both,
two different programs were writing folders with the same name.

That is not a tidiness complaint. During development, while clearing out the older
program's leftovers, this project's own folders were very nearly thrown away with them,
including a fix that existed in no other copy. It was caught and recovered. This release
is the response.

Every file now carries the name `gorilla-opencode` and lives in the standard Linux
locations: settings in `~/.config`, saved conversations in `~/.local/share`, downloaded
model lists in `~/.cache`, logs in `~/.local/state`. Previously a hidden folder was created
inside *every project folder you ever opened*; that no longer happens. Crash logs, which
used to land in whatever directory you launched from — and could be committed to a
repository by accident — now go to one place set aside for them.

### What it will cost you on upgrade

**Nothing is deleted. Nothing is carried across either, and the program will not say so.**
On first launch of v0.1.85: your conversation history is empty, your custom slash commands
are missing from the menu, any per-project settings file is ignored, and your `/context`
switches are back to their defaults. Every one of those files is still on disk, untouched,
in the old location. The new version simply does not read them.

Two side-effects came with the same change, neither of them a deliberate decision: every
project now shares **one** conversation history rather than having its own, and the "shall
I set this project up?" question is now asked once on the whole machine rather than once
per project.

### Why three earlier attempts failed

Worth recording, because it looks like carelessness and was not. The symptom — text
sliding leftwards — looks like a width problem, so the first attempts fixed width
problems, and found real ones: the box had been capped at half the window even with rows
to spare, and had not been told the terminal's true width. Both were genuine bugs and both
fixes were kept. Neither touched this one. A box that measures itself as one line tall
will not grow no matter how much room you give it.

The tests written to catch it passed while the bug was still present, because a test builds
a *fresh* text box, and a fresh box has no stale measurement to reuse. Three times, a green
tick reported a fix that had not happened. It was found by running the real program with the
numbers printed on screen and watching the text grow past 600 characters while the measured
height stayed at 1.

## Developer track

### The defect

`editor.go` derived its own height from `wrappedRows(m.textarea.Value(), m.textarea.Width())`
— a lipgloss width estimate evaluated against the **live** bubbles textarea, whose viewport
was still one row and whose soft-wrapped line cache is built against the viewport height it
was last configured with. The measurement therefore asked a one-row object how many rows it
needed and was told "one", permanently. With height pinned at 1, bubbles falls back to
horizontal scrolling within the row, which produced the visible symptom.

Two conditions on the same path made it worse: in scrollback mode the layout is never
rendered, so nothing propagated the real terminal width down to the bordered editor child;
and `container.View()` rendered that child inside a fixed `Height(c.height)` carried from the
previous frame, clipping the first newly-wrapped row even when the child did produce two.

### The fix

`measuredRows()` (`internal/tui/components/chat/editor.go:200-226`) takes a by-value copy of
the textarea as a throwaway probe, calls `SetHeight(editorBufferLines)`, then re-applies
`SetValue(m.textarea.Value())` — the load-bearing step, since re-applying the value forces
bubbles to rebuild its wrapped-line cache at the probe's height instead of reusing the live
one-row snapshot. It renders `probe.View()`, strips ANSI, trims trailing blank rows, counts
lines, floors at `minEditorHeight`, restores the live viewport height so measurement cannot
itself resize the field, and discards the probe. Both call sites — `desiredHeight` and
`hiddenLines` — now use it.

Supporting changes: `container.go:53-65` renders the child first and expands when
`contentHeight + VerticalChrome()` exceeds the stale allocation; `chat.go:56-75` propagates
the current footer width before `FooterView` measures; `tui.go:1685-1696` replaces
`budget := a.height / 2` with `a.height - lipgloss.Height(status)`.

### Naming and storage

`appName` becomes `gorilla-opencode` and `defaultDataDirectory` is deleted
(`config.go:182-184`). `store.go` gains `DataBase()`, `CacheBase()` and `StateBase()` beside
the existing `ConfigBase()`, each honouring its `XDG_*` variable with a Linux fallback.
`data.directory` now defaults to the absolute `DataBase()` rather than the relative
`.opencode`; the database filename becomes `gorilla-opencode.db`; the viper env prefix
becomes `GORILLA_OPENCODE`, as do the four standalone feature variables. Both legacy
migrations — `migrateLegacyConfig` and the loadout mover — are deleted outright, a
deliberate clean break for a test machine that needs no upstream compatibility.

### Honest state of verification

**The regression test does not guard the fix it appears to guard.**
`TestExactLongPromptWrapsAtTerminalWidth` passes — and it also passes with the
`measuredRows` call at `editor.go:180` reverted to the old estimator, because a textarea
constructed inside a test has no stale one-row viewport to reuse. It covers the width and
wrap boundary; it does not cover the stale-cache mechanism. The only evidence for the
measurement fix is a live instrumented run. A non-vacuous test would construct the textarea
at height 1, drive the long value through the live model, and assert `measuredRows() >= 2`.
That test does not exist yet, and per this project's own standard — a test that passes
against the bug is worse than none — writing it is outstanding work.

None of the path or rename changes has any test coverage: greps for `DataBase()`,
`CacheBase()`, `StateBase()`, `gorilla-opencode.db` and the renamed artifacts across
`*_test.go` return nothing.

Verified: `go build ./...` exits 0 (checked via `PIPESTATUS`); `go test ./...` passes; the
release binary reports `v0.1.85`; `dpkg-deb` and `zstd -t` validate both packages; the
published assets' sha256 sums match `SHA256SUMS-v0.1.85.txt` on recomputation.

### Known defects shipping in this release

| Defect | Effect |
|---|---|
| `install` requests `gorilla-opencode-linux-x86_64.tar.gz` | The project publishes no tarball; the script cannot succeed. |
| `PKGBUILD` instructions name 0.1.85 to download, 0.1.84 to install | Copy-pasting installs the previous version. |
| `README.md` and `system-prompts/README.md` document `OPENCODE_*` variables | Those names are now ignored by the binary. |
| `settings.go` layman string still reads "Folder inside your project" | `data.directory` is now global, so the description is false. |
| `docs/SETTINGS.md` hardcodes `/home/gorilla/...` as the documented default | A build machine's home directory leaked into generated documentation. |
| No migration exists for sessions, commands, project config or loadout | Silent loss of visible state on upgrade, described above. |
| `.opencode` removed from the ignored-directory list | Leftover old data directories are now walked by file search and `@`-completion. |

### Repository state

`origin/main` is four commits ahead of the `v0.1.85` tag; the four are documentation only,
but a source tarball built from the tag will not contain the documents the release body
links to. The tag exists only on the remote and is lightweight, unlike v0.1.78–v0.1.84
which are annotated. The working tree carried unrelated pre-existing changes at release
time, including a pending deletion of `release_docs_v0.1.35/RELEASE-NOTES-v0.1.35.md` that
should be reverted or quarantined rather than committed.
