# First Linux execution of the windows-port work: six platform-assumption test failures, zero product defects, three UI faults found from screenshots

**Version:** v0.1.132
**Date:** 2026-09-03

---

## Summary

v0.1.130 shipped as a Windows build with GOOS=linux go build and go vet passing as the whole of its Linux evidence; nothing had been executed. Running it produced six test failures, all of them tests or harnesses asserting Windows-only facts, and no product code changed to fix any. Three were false passes, not plain failures: tests/smoke.sh invoked the binary as `env -i ... runbin "$BIN"`, and since env(1) execs a program while runbin is a shell function, every one of those runs exited 127 having started nothing, and three checks graded env's own error string. Separately, patch_port's GNU patch fuzz fallback, the single genuine platform dependency, was verified on distro patch. Three UI faults were then found by photographing the running program: /help capped at 84 columns, /context capped at 140, and an overlay height fault that pushed both dialogs' headers off the top of the terminal, the last of which was introduced in this release while fixing the first.

## Known Alternatives Considered

Recorded in the source. For the /help layout, filling columns strictly in newspaper order was implemented first and rejected: with 37 rows in a 45-row terminal the left column took all of them and the right half rendered empty, which is the same wasted-window complaint moved to the other side of the screen, so columns balance while everything fits and only fill in order once the list scrolls. For the low-bandwidth notice, a transient toast already existed and was kept, but was insufficient on its own because the state persists after the message fades; the persistent line was added beside it and the toast kept. For the clipboard dependency, Recommends was rejected in favour of Depends on the precedent recorded in CLAUDE.md that gdebi ignores Recommends, so a graphical install would silently skip it. For the deferred-loading patch_port gap, adding catalogue prose was tried in an earlier cycle, measured 0/2 before and 0/3 after across five runs, cost 63 tokens per turn, and was removed; it is not retried here.

## Architecture Impact

No architectural change. Two invariants are newly enforced, not newly created: overlay dialogs must render strictly shorter than the terminal, because placeOverlay grows the canvas by the overlay's full height and draws the prompt and footer below it; and patch_port's permission gate is now pinned by tests, having previously been a single unasserted condition.

## Subsystem Changes

**TUI:** Both full-width dialogs lose their RoundedBorder. Box-drawing characters are East Asian Ambiguous, width 1 normally and 2 on a CJK-configured terminal, so they are the one decoration whose width can change on another machine; and at full width the box frames an edge the terminal already has, for 2 columns and 2 rows of a fixed budget.

**TUI:** New shared guard drives both overlay dialogs from the same sizedDialogs registry the overflow ratchet uses, not a second list, because /context acquired the overlay height bug precisely because /help was fixed alone.

**OTHER:** Packaging declares a clipboard utility for the first time: .deb takes the alternation xclip | xsel | wl-clipboard; pacman has no alternation syntax so the Arch recipes name xclip, which serves X11 and, through XWayland, most Wayland desktops.

## Known Issues

**[medium]** makepkg -si refuses with a checksum mismatch on the source tarball. (deferred to the commit immediately following the tag push)
- Cause: sha256sums in packaging/PKGBUILD still carries the previous release's value. The sum covers the tarball of the tag, and that tarball contains the PKGBUILD, so writing the correct hash changes the file the hash covers. It is a fixed point with no self-consistent value.
- Remedy: The documented procedure puts it in the commit after the tag: push the tag, download archive/refs/tags/v0.1.132.tar.gz, hash it, commit to main, re-download and verify. README install route 1 clones the default branch, not the tag, so main's copy is the one users actually run.

**[low]** /copy reports it could not reach the clipboard.
- Cause: No clipboard helper present. Installing with dpkg -i instead of apt resolves no dependencies, or the session is pure Wayland with no XWayland so xclip cannot function.
- Remedy: Install with apt, or install wl-clipboard on a pure Wayland session.

**[medium]** A small model never invokes patch_port when asked whether a patch series would apply.
- Cause: With tool.tool_search enabled, deferral is reliable for capabilities a request NAMES and unreliable for capabilities it only IMPLIES. Offline scoring returns patch_port as the top hit for the relevant phrasings, so this is not a retrieval failure: the model never enters the search path.
- Remedy: Leave deferred tool loading off, which is how it ships. Measured 0/5 with it on against Gemma 4 E2B.

**[medium]** A dialog's title is missing from the top of the screen.
- Cause: The frame rendered as tall as the terminal. placeOverlay grows the canvas by the overlay's full height and draws the prompt and footer below it, so the view scrolls and the top is what leaves.
- Remedy: Fixed by overlayFooterReserve and loadoutFooterReserve, and guarded by TestOverlaysLeaveRoomForWhatIsUnderThem.
