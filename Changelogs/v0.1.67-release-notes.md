# Gorilla OpenCode v0.1.67 — the provider picker stops cutting names in half

*Track 1 of 2 — written for anyone. The developer track follows below.*

> **Note on this document.** These notes were written after the fact, on
> 2026-08-04, during the v0.1.68 release. v0.1.67 shipped without them — no
> changelog entry, and no release notes inside the package. That was an
> oversight, not a decision, and this file exists so the release is not a hole in
> the record. The code it describes is unchanged.

## Why This Release Exists

The menu that asks which provider you want to use — the one that appears every
time the app starts — was squeezing itself into 76 characters wide no matter how
big your terminal was. On a wide window that meant provider names and their
descriptions were chopped off mid-word:

```
> Antigravity free tier - Claude + GPT-OSS + Gemini (Gmail sign-..
  Google - Code Assist free tier (Gemini only, Gmail sign-in, nok.
```

You could still pick things; you just could not read them. The same applied to
the extras/toggles screen.

## What You'll Actually Notice

Provider names and descriptions now use the full width of your terminal and wrap
at a sensible place instead of being truncated. If your terminal is narrow,
nothing changes — the old width was already the whole screen.

## Decisions & Why

The 76 was not arbitrary — it was a **fallback** for the moment before the
terminal has told the program how big it is. That part is still needed and is
still there. The bug was using it as a **ceiling** as well: once the real width
arrived, it was ignored. The fallback now applies only when the width is genuinely
unknown.

## Risks, Backup & Recovery

Display-only change to two startup screens. No settings, keys, sessions or
network behaviour are touched. The previous package remains on the releases page.

## Bottom Line

The provider picker is readable on a big screen. That is the whole release.

# v0.1.67 — remove a fallback used as a cap in the startup screens

*Track 2 of 2 — for developers.*

## Architecture & Footprint

One commit, `ef317b5`, two files: `internal/tui/startup/provider.go` and
`internal/tui/startup/extras.go`, 8 insertions and 2 deletions.

## The defect

`contentWidth()` in both files read:

```go
return max(minimum, min(fallback, m.width-chrome))
```

with `fallback = 76`. `min(fallback, …)` made the fallback a hard ceiling, so a
terminal reporting 150+ columns still rendered content at 76 and the row
renderer clipped the remainder mid-word.

## The fix

```go
// before
return max(minimum, min(fallback, m.width-chrome))
// after
return max(minimum, m.width-chrome)
```

`fallback` is now returned only on the `m.width <= 0` branch — genuinely unknown
size, before the first `tea.WindowSizeMsg`. Descriptions already pass through
`wrapTo()`, so they wrap at the real width with no truncation.

## Verification

Existing startup render assertions cover the width invariant (no frame line
wider than the terminal). Full suite green at the tagged commit.

## Deployment

Tagged `v0.1.67` at `main`, built with the version ldflag, packaged, published
non-draft with binary, `.deb` and `checksums.txt`.

**Known gap, recorded honestly:** because these notes did not exist at release
time, the v0.1.67 `.deb` does **not** contain them — its
`/usr/share/doc/gorilla-opencode/` stops at `v0.1.66-release-notes.md`. The
v0.1.68 package carries both this file and its own.
