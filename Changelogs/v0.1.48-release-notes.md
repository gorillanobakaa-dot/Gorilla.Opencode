# Gorilla OpenCode v0.1.48 — The program tells you what it is again

*Track 1 of 2 — written for anyone. The developer track follows below.*

## Why This Release Exists

After v0.1.47 the program stopped saying its own name. The version, the repository
address, the folder it was pointed at and the model answering you had all
disappeared. Turning the font size down to look for them under the frame found
nothing, because they were not there.

Nothing was broken. That block had always been drawn by the right-hand sidebar, and
v0.1.47 stopped drawing the sidebar — the conversation moved into your terminal's
own scrollback, and a side panel has no place in a layout that is only a prompt.
The information had nowhere left to be. This release gives it somewhere.

## What You'll Actually Notice

**A banner at the start of every session**, the way Antigravity CLI and Gemini CLI
announce themselves:

```
Gorilla OpenCode  v0.1.48
https://github.com/gorillanobakaa-dot/Gorilla.Opencode
folder  /home/gorilla/Documents/Debian.Kernel.Work
model   DeepSeek V4 Pro

This conversation is ordinary terminal output: scroll it, select it, copy it.
```

That last line is there deliberately. If you upgraded into v0.1.47 there was no way
to discover that the conversation had become selectable and copyable — the change
was invisible until you happened to try it.

**The name and version now sit at the right-hand end of the footer**, in the empty
space that was doing nothing:

```
in Debian.Kernel.Work  ·  context 10.7K (1%)  ·  spent $0.05    Gorilla OpenCode v0.1.48
tokens 10.6K in / 87 out  ·  mcp none  ·  lsp all 9 off  ·  changed no files
```

On a narrow window the version is **dropped rather than cut in half** — a truncated
version number is worse than no version number, and the figures on the left are the
ones that actually change.

## Decisions & Why

**The banner is printed, not kept on screen.** It could have been another footer
row, but the footer is redrawn on every keystroke and an identity block has no
reason to be redrawn at all. Printing it once also means it is copied out with the
rest of the session, which a permanently-redrawn row is not.

**It prints once, and only after the window has been scrolled.** Both matter. Text
printed to a terminal cannot be withdrawn, so a second copy would sit in your
scrollback for the rest of the session. And the program scrolls the window once at
startup to put the prompt on the bottom row — anything printed before that scroll
is pushed straight out of view, which would have reproduced the exact "where did it
go" this release is fixing.

**Nothing changed for the alternate-screen interface.** If you have that setting on,
the sidebar still shows all of this and the banner is not printed, because it would
be discarded anyway.

## Deliberately Not Done

- **The 400 Bad Request** on questions that use the web-fetch tool is still not
  fixed. Still understood only well enough to rule out the reasoning setting.
- **Numbered lists still collapse onto one line** in replies. Standard Markdown
  behaviour, unchanged since long before any of this, and changing it changes the
  formatting of every reply — so it waits for a decision rather than arriving as a
  surprise.

## Privacy & Security

No change. No new network calls, no new files written, no new dependencies. The
banner reads only configuration that was already loaded.

## Risks, Backup & Recovery

Small release, small risk: one new printed block and one right-aligned label.
Sessions, configuration and keys are untouched. Downgrade with `sudo dpkg -i` on the
v0.1.47 package, which stays on the releases page.

## How To Install

```sh
sha256sum -c checksums.txt
sudo dpkg -i gorilla-opencode_0.1.48_amd64.deb
gorilla-opencode --version && dpkg -l gorilla-opencode | tail -1
```

Both must say `0.1.48`. Quit any running copy first.

## What's Still Broken

Everything listed under v0.1.47 that was not addressed here: the 400 Bad Request,
Markdown collapsing single line breaks, the alternate-screen interface getting far
less exercise now that it is not the default, the size sweep covering 8 of roughly
15 dialog surfaces, and tool descriptions still costing about 3,680 tokens against
the system prompt's 464 with no evaluation suite to prove a cut is safe.

## Common Questions

**Why is the banner above a screenful of blank space?** The blank rows are the
startup scroll that puts the prompt on the bottom line. The banner is printed after
it, so it sits directly above your first message.

**Can I turn the banner off?** Not yet. It is four lines, printed once. If it
becomes annoying it should become a setting rather than a habit of scrolling past
it.

**Where did the sidebar go?** It is still there if you switch the alternate screen
back on in `/settings`, along with the old full-screen interface — and with the loss
of scrolling, selection and copying that comes with it.

## Bottom Line

One commit. The program says what it is, where it is pointed and which model is
answering — at the start of the session and, briefly, in the corner of the footer.

# v0.1.48 — restore the identity block the sidebar used to carry

*Track 2 of 2 — for developers.*

## Architecture & Footprint

One functional commit (`28d5f77`), 5 files, 22 packages of tests passing, `go vet`
clean.

The information was never removed; its only renderer was. `sidebarCmp.View()` called
`header(width, base)` and the sidebar is not attached in scrollback mode, so
`logo`/`repo`/`cwd` had no caller. Two new surfaces replace it.

## Code Changes

**`internal/tui/components/chat/banner.go`** (new) — `SessionBanner(width)` returns
the identity block: name, `version.Version`, repository, `cfg.WorkingDir`, the coder
agent's model resolved through `models.SupportedModels` for its display name, and
one line stating that the conversation is copyable. Returns `""` at a non-positive
width, for the same reason nothing else prints then: the terminal would wrap it at a
width we did not choose and printed output cannot be recalled. Every line is
truncated to the width, because an over-wide line wraps into rows the renderer never
counted and puts every later erase in the wrong place.

**`internal/tui/pin_bottom.go`** — `bannerCmd()` emits it exactly once, gated on
`scrollback && !bannerShown && pinnedOnce && width > 0`, called from the
`WindowSizeMsg` branch immediately after `pinCmd`.

Kept as a separate function rather than batched into `pinCmd`. The first attempt
returned `tea.Sequence(pinToBottom(rows), tea.Println(banner))`, which broke
`TestTheFrameIsPinnedOnceNotOnEveryResize` while the behaviour was still correct:
that test measures how many newlines the command emits, and a `sequenceMsg` carries
none. One function, one contract.

**`internal/tui/components/chat/footerinfo.go`** — `joinWithTrailer` pins a field to
the right edge and fills the gap. `join` now returns unpadded output at width 0 so
it can compose. If the gap would be under two columns the trailer is dropped, not
truncated.

## Test Coverage

`banner_test.go`: the banner names the program and its version, mentions
copyability, refuses an unknown width, and fits its width at 30/60/100 columns.
`TestFooterCarriesTheVersionOnTheRight` checks the trailer is present, the line is
exactly full width, the trailer STARTS near the right edge, and that a 40-column
footer drops it entirely while both rows stay exactly 40 wide.

`pin_bottom_test.go`: `TestBannerIsPrintedOnceAndOnlyAfterPinning` covers all four
gates — not before pinning, exactly once, never on the alternate screen, never at an
unknown width.

Seven mutations checked, all caught: banner at unknown width, banner without the
version, trailer not right-pinned, trailer kept when it would collide, banner
printed more than once, banner printed before pinning, banner printed on the
alternate screen.

Two of those initially escaped, and one was a weak assertion rather than missing
coverage. Asserting that the footer trailer *ends* at the right edge passes
trivially, because the line is padded to full width afterwards — a version sitting
immediately after the left-hand fields still "ends" at the edge. The assertion now
checks the column the trailer STARTS at.

## Security Posture

Unchanged. No new network paths, dependencies or writes.

## Deployment & Verification

Same protocol: tag at `main`, build the binary stamped with `-ldflags
-X .../version.Version=v0.1.48`, package, then extract the `.deb` and confirm the
**inner binary** agrees with the control file — the check that caught a v0.1.46
package whose control said `0.1.46` around a `v0.1.45` binary. Publish, confirm
`isDraft` is false, download the artifacts back, verify checksums, purge, and
install from the downloaded package rather than the built one.
