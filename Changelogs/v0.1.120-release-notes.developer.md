# Windows port: shell default, PowerShell result reporting, prefix-cache invalidation and its visibility, IsAbs path guards, local-model discovery, and four cursor-and-geometry rendering faults

**Version:** 0.1.120
**Date:** 2026-09-02

---

## Summary

The program had never functionally run on Windows. The root cause was internal/config/config.go setDefaults, which set shell.path unconditionally from SHELL with a /bin/bash fallback; because that default was always applied first, the existing Windows shell-detection code was unreachable. Measured before the fix: 0 of 10 bash tool invocations succeeded. Fixing it exposed internal/llm/tools/shell/shell.go, which drove PowerShell but parsed results as bash -- exit codes always 0, stderr always empty, a UTF-8 BOM written into the file recording the working directory. That package had zero tests, which is why the faults shipped; it now has 15. The remainder falls into six groups: two path-comparison security guards that relied on filepath.IsAbs and were bypassable on Windows; a prompt-cache invalidation caused by per-turn mutable content in the system prefix, and the fact that nothing reported whether caching worked; build reproducibility, where CRLF checkout changed the bytes of go:embed'd prompt text; local-model discovery, which hid vision models, discarded load state and counted one server as two; four rendering faults, three in cursor arithmetic and one in window geometry; and two faults about what a weak model can infer from a tool result. Scope: this is the WINDOWS build. Linux behaviour is preserved and two Linux regressions introduced during the shell rewrite were caught and reverted before release.

## Known Alternatives Considered

Documented in source comments. For the alternate-screen fault, keeping the buffer switch and resetting the renderer's line counter on exit was considered and rejected: the counter is private to bubbletea and neither repaint() nor clearScreen() resets it. For the resize fault, reading window-resize records off the console input handle was rejected because bubbletea owns that handle for keyboard input and a second reader would steal keystrokes; polling GetConsoleScreenBufferInfo touches nothing it is using. For unknown tool parameters, a hard error was rejected in favour of a note appended to the result: a model that keeps attaching a harmless field would loop forever. For context pressure, trimming the ~4,700 tokens of tool descriptions was rejected, because two faults in this same release were fixed by giving the model MORE guidance; raising the window costs 0.9 GB and cutting guidance costs correctness paid for. For cache visibility, persisting the figures in the session row was rejected: sqlc is not installed here so a schema change would mean hand-editing generated code, and /context describes the live session. For load/eject from the picker, building it was rejected: POST /api/v1/models/load is not idempotent and starts a second copy of a resident model, measured, and the unload endpoint rejects every payload shape tried with a bare HTTP 400 and an empty body.

## Architecture Impact

Seven invariants changed. (1) Dialogs no longer imply an alternate-screen round trip. (2) Every printed line must begin with a carriage return: the renderer emits one for the frame but never for queued Println lines, and CursorUp changes the row without the column. (3) The terminal size must be polled on Windows, because bubbletea's listenForResize is an empty function there. (4) The system prompt prefix must be byte-stable across turns. (5) The working tree is pinned to LF. (6) A local model is a legitimate agent fallback, so a local-only configuration is no longer a startup failure. (7) Endpoint identity is decided by a canonical URL instead of a raw string. Two smaller ones: overlay compositing is centralised in one placeOverlay helper instead of duplicated at 28 call sites, and 'the provider reported no cache figures' is now representable and distinct from 'nothing was cached'.

## Subsystem Changes

**TUI:** Dialogs composited inline; every printed line begins at column 0; the terminal size is polled on Windows; overlay placement centralised; ctrl+a copies the transcript; ctrl+r re-scans local runtimes; /context reports cache reuse.

**OTHER:** Shell execution rewritten for PowerShell with truthful exit codes and stderr, and a stated exit code on silent success. Tool errors name the remedy. Unknown tool parameters are reported back to the model.

**AUTH:** Two workspace path guards that used filepath.IsAbs were bypassable on Windows and now resolve rooted paths against the working volume. API keys containing control characters are rejected at load.

**NETWORK:** Local model probing moved off http.DefaultClient onto a client with a timeout. Endpoint identity is decided by canonical URL, so loopback spellings are one server.

**STORAGE:** No schema change. Cache figures are held in memory deliberately: sqlc is not installed here, and /context describes the live session.

## Security Posture

Attack surface reduced. Two workspace-escape guards bypassable on Windows via a POSIX-style rooted path are closed; both failed open on Windows only and were correct on Linux. API keys containing control characters are rejected before use instead of transmitted -- this was live, with a stored key of nine NUL bytes. No CVEs are involved and no permission or telemetry behaviour changed. github.com/atotto/clipboard moved from indirect to direct; it was already in the module graph and no new module was introduced.

## Known Issues

**[medium]** /review fails; TestEveryModuleTheToolkitImportsIsEmbedded fails with "open toolkit/code_review.py: file does not exist". (deferred to unscheduled -- blocked on obtaining the file)
- Cause: The analyser was removed by .gitignore's *.py rule before it was ever committed. Confirmed absent from every branch of the public repository and from all local history, so it exists only on a developer machine.
- Remedy: Restore it from that machine and commit it. The ignore rule was fixed in 401315e.

**[low]** /context reports that the endpoint does not report cache reuse.
- Cause: The provider sends no cache figures. LM Studio returns no prompt_tokens_details at all, measured across two identical requests, while demonstrably reusing the prefix.
- Remedy: None. This is deliberately distinct from a reported zero, which would mean caching genuinely did not happen. Conflating the two would report working caching as broken.

**[low]** gofmt -l reports every file in the tree as unformatted. (deferred to a separate renormalisation commit)
- Cause: The working tree still holds CRLF from a checkout predating .gitattributes. The files are correctly formatted; only line endings differ.
- Remedy: Compare ignoring line endings, or run git add --renormalize . in a dedicated commit. Deliberately not done here because it would touch nearly every file.

**[low]** TestASlowStreamIsNeverCut fails during a full-suite run. (deferred to unscheduled)
- Cause: The stall guard is timing-sensitive and the assertion is missed when the machine is loaded. Passed 3 of 3 in isolation on a machine also hosting a model server.
- Remedy: Re-run the package alone before treating it as a regression. Root cause not investigated.

**[low]** The bottom row of the window sits behind the Windows taskbar.
- Cause: The usable desktop height is not an integer multiple of the console cell height -- 1032 px at 16 px per row is 64.5 rows -- and maximising rounds the row count up. The console reports the rounded-up count and the program believes it.
- Remedy: Drag-resize instead of maximise; the console snaps to whole cells. Or choose a font size dividing the usable height exactly. Not detectable from inside the program.

**[low]** Prefill on a local model is slower than a parameter count suggests.
- Cause: Prefill does not scale with active parameters. Four predictions were made from parameter counts and all four were wrong, one by 2.5x; the model with the fewest active parameters was not the fastest. Thread count is also nearly flat: 1 thread 33.96 tok/s, 4 threads 41.29.
- Remedy: Measure on the target hardware. No speed claim in this project may be derived from a parameter count, an architecture name, or another model's measurement.
