# A model list you can finally curate, and a measurement that had never once run — Plain Language

> Session record generated 2026-08-20

---

## What happened

Some providers offer hundreds of models. The list they produce is long enough to be useless, and it contained no way to prune it. You could bookmark models one at a time, but you could not remove one, could not refresh the list to see what a provider actually serves today, and could not start again from a clean slate.

This release adds all four: mark several models at once, add them to your list in one action, hide the ones you never want to see, and empty or refresh the downloaded lists. Hiding is permanent until you undo it - a refresh will not bring back something you rejected, which is the point. Without that, clearing the list on Monday would find it full again on Tuesday.

It also fixes something embarrassing. The speed estimate added two releases ago never ran. Not once. The code that measured your connection was written, tested and shipped, and nothing ever called it - so the picker said 'nothing measured yet' forever and the feature that was supposed to suggest a profile could never suggest anything.

## Honest state of play

Done and tested: multi-select, hiding with a review screen, /purge, /update, the full-window picker, the repaired speed measurement, and a message telling you what changed when you switch connection profile. Thirty test packages pass and both the Debian and Arch packages were opened and checked.

Published but not acted on: measurements showing some AI models run tools nobody asked for. The findings and the script are in the repository. We did NOT label those models in the picker, because five of the models we wanted to test could not be reached and we could not tell whether they were broken or whether our own API allowance had run out. Labelling a model on that basis would be a guess wearing the authority of a test.

Not changed, deliberately: the instructions given to the AI. We checked whether they cause the unrequested tool calls. They do not - other models read the same instructions and behave correctly.

## Worst case if something is wrong

Hiding is the risk worth naming. If you hide a model by mistake it disappears from every list, and someone who did not know about the review screen could conclude it had been deleted. That is why a HIDDEN column appears the moment anything is hidden, why the key that hides is the same key that restores, and why nothing is ever hidden automatically - a provider having a bad afternoon is not evidence a model is finished.

## What you can do now

- Mark several models with x and add them all to your list with a.
- Hide models you never want to see again with d; they stay hidden even after a refresh.
- Review and restore anything you hid, from the HIDDEN column - press H.
- Empty the downloaded model lists with /purge, and fetch them again with /update.
- Use the whole window when picking a model instead of a 30-row slice of it.
- See a real estimate of your connection speed, which until now never actually measured anything.

## What is still missing

- **Models that run tools unasked are not labelled in the picker** — You have to read the findings page to know which ones behave badly.
- **Five models could not be tested** — The comparison covers four models, not nine.
- **Diagnostics from the code checker stay in the conversation forever** — Errors you fixed long ago are still being re-sent on every message, costing data.

## Should you be concerned?

One thing deserves saying plainly. The connection speed estimate shipped in two releases without ever running. Nothing was damaged and nothing was at risk - the feature did nothing while appearing to be present, and the release notes described it as working. It was found by checking a file on disk that should have contained measurements and did not.

The lesson has been applied instead of noted: the repair comes with a test that sends a real request through the real code and fails if no measurement is recorded. The earlier tests passed because they called the measuring function directly - proving it worked, while never asking whether anything used it.

## Glossary

**Provider** — A company or server that serves AI models, such as OpenRouter or NVIDIA.

**Bookmark list** — Your own shortlist of models, kept separately from the provider lists.

**Purge** — Empty the downloaded lists so only the models built into the app remain.

**Tool call** — The AI running something on your behalf - reading a file, searching the web.
