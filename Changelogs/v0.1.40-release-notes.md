# v0.1.40 — /cd actually narrows the workspace, and the new dialogs use the whole screen

Follow-up to v0.1.39, fixing two things reported from real use.

---

# Plain language

## The important one: `/cd` was refusing the only thing it was for

v0.1.39 shipped `/add-dir` built on a wrong assumption — that workspace roots are
about *adding* scope. They are not. The purpose is the opposite.

An AI agent started in a home directory walks everything under it looking for
files. On a machine holding a kernel tree and a Firefox tree, that is **over a
million files across deeply nested folders**. Measured on the developer's machine:

| Workspace root | Files the file-completion walk covers |
|---|---:|
| `/home/gorilla` | **1,327,750** |
| after `/cd ~/Documents/ai-tooling/opencode/Gorilla.Opencode` | **305** |

That is the entire point of the feature: pointing the agent at **one** project so
it stops discovering — and charging you for — everything else.

v0.1.39 got this backwards in three ways:

1. **`/cd <path>` did not work at all.** The command took no argument. The whole
   line became the command name, so anything with a path fell through to
   "Unknown command".
2. **Switching to a subdirectory was refused** with "is already covered by the
   root /home/gorilla". True, and useless — you were not asking about coverage,
   you were asking to work in that directory. The only route to a subdirectory
   was add-then-promote, and the add step was the one that refused.
3. **Even when it worked, it kept the old root.** Narrowing from a home directory
   into one project retained the home directory as a second root, so the million
   files stayed in scope while the program reported success. A narrowing that
   does not narrow is worse than a refusal.

All three fixed. `/cd ~/some/project` now works in one step, accepts a
subdirectory, and drops the wider tree it came from.

## The cosmetic one: the new dialogs were too narrow

`/settings`, `/prompts`, `/add-dir` and `/reset` capped their width, so on a wide
terminal every description was truncated with an ellipsis while a black margin sat
unused beside the box. They now fill the terminal like `/context` always has.
Checked at three terminal sizes; all four use 100% of the width and none spills
off the screen.

## What to do

Nothing beyond installing. If your workspace is currently a home directory, the
one command worth running is:

```
/cd /path/to/the/project/you/are/actually/working/on
```

## Rolling back

`sudo dpkg -i gorilla-opencode_0.1.39_amd64.deb` — on the v0.1.39 release page
with checksums. Configuration is compatible both ways.

## The two narrowing rules

Deliberately separate. Conflating them either keeps the broad tree or discards
unrelated work — both were hit while writing this, and both are now test cases:

1. **If the old primary CONTAINS the new one, `keepOld` is ignored.** Retaining
   the parent leaves its context files, its permission scope and its
   `@`-completion ripgrep walk all in place.
2. **Any EXTRA root containing the new primary is dropped regardless.** Leaving a
   parent in the extras list is the same defeat by another route. Unrelated
   extras survive.

First attempt checked only the old primary and missed a broad tree held as an
extra. Second attempt checked every root and threw away an unrelated sibling.

## Why width mattered

`loadout.go` has always used `termWidth - 6` with no cap. The new dialogs added
chrome on top of a content width instead of subtracting it from the terminal —
the same arithmetic error as the v0.1.38 invisible input box. The floor is now 30
columns and applies only where the dialog cannot fit at all.

## Tests

`internal/config/narrowing_test.go`, 7 cases: parent dropped on narrowing;
containing extra dropped; sideways move honours `keepOld`; sideways without
`keepOld` drops it; the refusal message names `narrow` and `/cd`; the path
`AddDir` refuses is exactly the path `SetWorkingDir` accepts (the pairing that
was broken); and narrowing strictly shrinks `Roots()`, which is the list handed
to ripgrep.

Render assertions extended to 197x48, 120x30 and 80x24 for all four dialogs.

Full suite and `-race` clean. Verified end to end by counting the files ripgrep
would walk before and after a real `/cd` on the developer's machine: 1,327,750 →
305.
