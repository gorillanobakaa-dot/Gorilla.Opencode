### Job 02: Job Objects, interrupts, ConPTY (f8c4033)

- `internal/procjob` (new), adapted from hcsshim v0.15.0 `internal/jobobject` (MIT, notice copied, pinned in `third_party/PINS.md`): job with `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`; `Start` creates the process `CREATE_SUSPENDED`, assigns, resumes (`NtResumeProcess`); `KillAllBut(pid)` spares the shell and its `conhost.exe`/`OpenConsole.exe`; handle never inheritable, so a crash of this process kills the tree. No-op outside Windows.
- Shell: started in a job; interrupt = `KillAllBut(shellPid)` (fallback `taskkill /T`); job closed when the shell ends.
- Gap #10: `GorillaStop` (Add-Type) waits on a per-shell named event (`Local\gorilla-opencode-stop-<pid>-<n>`) and calls the internal `Runspace.GetCurrentlyRunningPipeline()` by reflection, then `StopAsync()`. Wrapper is one try/finally; a stop writes exit code 130 and "The command was stopped before it finished."; `GorillaStop.Requested()` tells a stop from `exit`/top-level `break`.
- LSP: `procjob.StartContext`; `Close` closes the job. `CloseAllFiles` used `debugLSPEnabled()` (see c88ddde for the rest).
- MCP: the process is assigned right after mcp-go starts it (`mcpJobs`); abandon/close close the job. Hooks: job per hook.
- ConPTY (`shell/conpty_windows.go`, from hcsshim `internal/conpty`): `RunInConsole`, 200x50, `STARTF_USESTDHANDLES` with empty handles, `-EncodedCommand`, CR line ends, VT stripped, 1 MiB cap. Bash tool gains `console` and `input` (Windows only).

## Known alternatives considered

- ConPTY as the default transport: rejected; its output is a screen drawing, and the file-based session protocol would have to be rebuilt on it. Opt-in per command.
- `PROC_THREAD_ATTRIBUTE_JOB_LIST`: `os/exec` takes no attribute list; suspended-assign-resume gives the same guarantee. One job for the whole program: cannot stop one shell's tree alone.
- `GenerateConsoleCtrlEvent` for gap #10: needs a shared console; none exists headless.
- `golang.org/x/text/encoding/charmap` for view: every code page, but a new import; Windows-1252 is a 32-entry table.
- Helpers beside the .exe in the zip: rejected by the owner (one file). Hash as file name: the shell could not call helpers by name. zstd/xz: not in Go's standard library.
- Shelling out to `vswhere.exe`/`pwsh -v`/`reg query` for the probe: a process per start; pure Go chosen. Cards in the prompt: ~3,000 tokens per turn. A separate `howto` tool: one more schema per turn.
- IFileOperation (COM) for the Recycle Bin: needs COM plumbing without cgo.
- Windows Credential Manager instead of DPAPI files: one more API, and the file names other tools look for would disappear.
- A go-winmd WinRT binding for OCR: a code generator and a NuGet download for one call PowerShell 5.1 makes natively.
- `microsoft/wmi`: not evaluated by job 04, so not used. EvtQuery via syscall: more code. `schtasks /query /fo csv`: localized headers.
- Web reader on by default, or web search off on Windows until lynx exists: the default is the owner's open decision.

```sh
gh release download v0.1.155 --repo gorillanobakaa-dot/Gorilla.Opencode
sha256sum -c SHA256SUMS-v0.1.155.txt --ignore-missing
gorilla-opencode --version
# Expected: v0.1.155
```

New optional settings: `"webSearchBuiltin": true` in config.json or `GORILLA_OPENCODE_WEB_READER=builtin`; `GORILLA_SIGN_CERT_SHA1` for `build-toolbox.ps1`. Sign-in files are resealed with DPAPI on the next write; a downgrade cannot read them.

## Not verified

- PowerShell 7: not installed on the development laptop. `HookPowerShell`, the session setup, the `&&` guidance and `GetCurrentlyRunningPipeline` on 7 are covered by unit tests only (the CI Windows runner has pwsh 7; 7272737 made the shell tests version-aware). If the reflection target is absent, a stop ends the shell and says so.
- UNC: tested as text (path to URI to path), never against a real share. Network shares, ReFS and FAT drives without a Recycle Bin not exercised.
- No real language server (gopls) on Windows against the new URIs; real LSP and MCP launchers (gopls, npx, uvx) not run; their trees are modeled with cmd and ping.
- Windows-1252 heuristic: a BOM-less file in another ANSI code page (Cyrillic, Greek) is shown as Western European letters, labeled.
- MCP servers are assigned to the job after mcp-go starts them; a child spawned in the first microseconds would escape. The suspended-start race closure has no test.
- pfind-rs: the musl Linux binary was built, never run; macOS not built; options outside the parity cases (`--pre`, `--encoding`, `--null-data`, `--crlf`, `--one-file-system`, `--stdin` and others listed in PFIND-RS) not compared; very large trees not benchmarked.
- Toolbox: the six third-party helpers were built from source on the owner's second machine, not rebuilt on Windows; their lack of network code is from that build report (Cargo.lock and source grep), not a traffic capture. No Linux/macOS embeds; windows-arm64 helpers not built.
- files tool on Linux/macOS: CI on Linux only; the `gio`/`trash-put`/Finder route never ran; the real-run robocopy exit >= 8 after a clean dry run not exercised.
- Host probe: PowerToys and Sysinternals detection tested with synthetic folders only.
- Acceptance: one full run on GPT-6-Luna; the local model only 3 scenarios; the owner's real config (Fieldkit MCP loaded) rather than a clean one; the h/l replay path unit-tested only; the ChatGPT retry tested with a fake transport only.
- macOS: zombie MCP detection (82a820d) built and vetted for darwin, never run on a Mac. No macOS CI job.
- `windows` tool: Windows 10, domain-joined machines, non-English Windows (event level text is localized), the Security log path (needs administrator) not triggered.
- DPAPI downgrade (expected: the older version asks for a new sign-in) not tried.
- A real Authenticode signature: no certificate exists. The web reader's Ecosia, Mojeek and Marginalia fallbacks not seen live; only Brave answered.

## Known issues

- Background programs started through the agent die with their session (by design).
- Console mode: no resize, no back-and-forth; answers typed up front. VT stripping is pattern-based.
- `GorillaStop` reaches an internal PowerShell method by reflection.
- Plain `$x = 1` never persisted between commands (each runs as a script block); `$env:` does.
- Toolbox verify-before-exec is by name: a helper called only indirectly is checked at shell start, not per command. `Dirs()` extracts every helper at shell start.
- `chatgpt.go` still uses `http.DefaultClient`, not `resilientHTTPClient`; only never-connected errors are retried.
- `GatedLineTokens("prompt.localtools")` counts `os.linux` lines on Windows (~60 tokens over-estimate in `/context`).
- The built-in reader and lynx share `lynxEngines`; an engine changing its HTML breaks both.
- Not built yet: 7za, the jq/yq `data` action, a Windows rebuild script for the six helpers, compress/encrypt and ACL changes in the files tool.
- Owner items: web reader default; code-signing certificate; the repository pre-commit hook's WinError 206 and its absence in worktrees.
- Carried from the v0.1.154 notes (not re-checked here): the trash record is in memory only; claim guard English only.
