# Gorilla OpenCode (Windows) 0.1.120 — The Windows version: a shell that never worked, a memory thrown away every turn, and ten faults only real use could find

**Date:** 2026-09-02
**Previous version:** 0.1.119

---

## Why This Release Exists

This program was written on Linux and had never really run on Windows. It started, it drew its interface, and then almost everything it tried to do failed — quietly, and in ways that made it look like the AI was at fault instead of the program.

The cause turned out to be one line of configuration. On startup the program decided which shell to run commands through, and it always chose a Linux one. That file does not exist on Windows. There was already code that knew how to find the Windows equivalent, but it never ran, because this decision was made first and never reconsidered. Measured before the fix: none of ten commands succeeded.

Underneath that was something worse. The program was driving the Windows shell but reading the results as though it were the Linux one, so it reported that failed commands had succeeded and threw away every error message. The AI was being told its work had succeeded when it had not, and then built on those false results.

The first half of this release came from reading the code and running the tests. The second half came from the owner using the finished program against a slow model on his own machine and telling us what he saw. Ten more faults were found that way, and the automated tests were passing for most of them. That is worth saying plainly, because it is the more useful lesson: the tests check what the program says, and almost none of these faults were about what it said.

## What You Will Notice

**Running any command**
- Before: Every command failed. The program looked for a Linux shell that does not exist on Windows.
- After:  Commands run through PowerShell. Measured before the fix: 0 of 10 succeeded.
- Affects: everyone on Windows

**Being told the truth about a failure**
- Before: A failed command was reported as successful, with no error text. The AI believed it had worked.
- After:  The real exit code and the full error message come back. A command that succeeds silently now says so too, instead of leaving the AI to guess.
- Affects: everyone on Windows

**Waiting for a reply**
- Before: Every message re-sent the whole conversation for reprocessing, because a clock reading inside the prompt changed each turn and threw away the saved work.
- After:  Measured on the owner's machine: a second message took 15 seconds instead of 8 minutes 14 seconds.
- Affects: everyone, and most of all people running a model on their own computer

**Seeing whether that saving is working**
- Before: Nothing anywhere showed it. The fault above went unnoticed for exactly that reason.
- After:  The /context screen reports how much of the prompt was reused. Where your model cannot report it, the screen says so outright instead of showing a zero that would look like a fault.
- Affects: everyone

**The window**
- Before: The program drew for the small window it opened in and never noticed you had maximised it, so text used half the width and the prompt sat in the middle of the screen.
- After:  It opens maximised and follows the window as you drag it.
- Affects: everyone on Windows

**Approving a command**
- Before: The screen went blank while the approval box waited, and afterwards the conversation above it had been erased.
- After:  The box appears above your conversation, which stays where it is.
- Affects: everyone on Windows

**The display staying intact**
- Before: A stray copy of the status bar could appear stranded in the middle of the screen, with one letter clipped off, and text printed underneath it.
- After:  Every printed line now starts at the left edge, which is what was wrong.
- Affects: everyone

**Finding your own models**
- Before: Models that can also read images were filtered out and never shown, with nothing saying so. The same server could appear twice under two names.
- After:  All your models are listed once each, marked as loaded or on disk, and ctrl+r looks again.
- Affects: anyone running models on their own machine

**Deleting a model**
- Before: If you deleted the model the program was set to use, it would not start at all.
- After:  It falls back to another model you have.
- Affects: anyone whose only models are on their own machine

**Copying the conversation**
- Before: Ctrl+A did nothing. On Linux the terminal window answers that key itself; on Windows it cannot.
- After:  Ctrl+A, or the new /copy command, puts the whole conversation on your clipboard.
- Affects: everyone on Windows

**When the AI makes a mistake**
- Before: Errors said what was wrong and not what to do, and a made-up option was ignored in silence, so the AI could not learn from either.
- After:  Errors name the tool that would have worked, and a made-up option is named back to the AI along with the real ones.
- Affects: everyone, and most of all people using a smaller model

**Installing**
- Before: There was no Windows installer, and the program demanded administrator permission to start.
- After:  Desktop and Start menu shortcuts are created, and it starts as a normal user.
- Affects: everyone on Windows

## Deliberately Not Done

- **The /review command still cannot run.** — It needs a Python file that an ignore rule quietly deleted before it was ever saved. Checked: it is in no branch on the project's public repository and in no past version, so it exists only on the owner's other computer. It has to come from there.
- **The program does not load or unload models for you.** — The model server's own load command is not safe to call twice: asked to load something already in memory it starts a SECOND copy, which was measured — two copies of one model, twice the memory used, and no warning given. A button that could silently double your memory use is not worth having until that is understood.
- **The tool instructions were not shortened, even though they take up most of the space.** — They are about three quarters of what gets sent before you type anything. But two of the faults fixed here were fixed by giving the AI MORE explanation, not less. Smaller models need the detail precisely because they cannot work things out for themselves, and they are the same models with the least room to spare. Buying more room costs under a gigabyte of memory. Cutting the explanations costs correctness that was paid for.
- **The cache figure is not saved between runs.** — It describes the turn that happened moments ago, so a number that resets when you restart is the honest shape for it. Storing it would also mean changing the database, using a tool that is not installed here, for something no one would read afterwards.
- **One test occasionally fails when the machine is busy.** — It measures timing, and it passes every time when run on its own. Left alone instead of papered over, and written down here instead of left for someone to rediscover.

## Privacy & Security

Two security checks were repaired. Both were meant to stop a file outside your project folder being read or written, and both could be got around on Windows because of a quirk in how Windows decides what counts as a full path: a path beginning with a forward slash is treated as incomplete instead of absolute, so the check waved it through. They now work as intended. Separately, the program refuses an API key containing invisible control characters instead of sending it — the owner had a stored key that was nine invisible bytes, and it was being transmitted. Nothing about what is collected or sent anywhere has changed, because nothing is collected.

## How to Install

**Before you start:**
- Windows 10 or Windows 11. This is the Windows build; the Linux one is a different download and the two are not interchangeable.
- No administrator rights are needed. If something asks for an admin password, that is not this program.
- No WSL, Git Bash, MSYS or Cygwin. It uses PowerShell, which you already have.
- To use a model on your own computer, install Ollama or LM Studio first and start it.

**Step 1:** Download the file marked windows-amd64 from the releases page. Close Gorilla OpenCode if it is already running — Windows will not overwrite a program that is open.
✓ You have gorilla-opencode.exe and no Gorilla window is open.

**Step 2:** Open PowerShell where you saved it and run the installer.
```
.\gorilla-opencode.exe install
```
✓ It reports the folder it installed into and the shortcuts it created.

**Step 3:** Start it from the Desktop shortcut. It should open maximised.
✓ The banner reads v0.1.120 and the text uses the full width of the window.

**Step 4:** If you use a model on your own computer, type /model and choose one. Models already in memory are marked as loaded. Press ctrl+r to look again if you have started one.
✓ Your model appears once in the list, marked loaded.

**To go back:** Run the installer from an older copy of the program; it overwrites what this one installed. Your conversations are stored separately and are not touched by installing or uninstalling, so going back does not lose them.

## If Something Goes Wrong

**The first reply takes a minute or more when using a model on your own computer.**
Your computer has to read the whole conversation before it can begin answering. On a low-power laptop that is genuinely slow. It is not stuck. Later messages in the same conversation are much quicker, because the reading is saved and reused.
What to do: Leave your model server running between sessions — the saved reading belongs to that program, not this one. Do not paste whole files or build logs; paste the error and the twenty lines around it. Type /context to see whether the reuse is working.
Status: not a fault — it is the speed of the processor

**/context says your model does not report cache reuse.**
Some model servers, including LM Studio, do not send that figure at all. That is not the same as nothing being reused — it usually is being reused, the server does not say by how much.
What to do: None needed. The screen says which of the two it is, instead of showing a zero you would reasonably read as a fault.
Status: working as intended

**The conversation fills up and the program says it is too big to send.**
Models hold a fixed amount, and yours may be set far below what it is capable of. The fixed instructions take about a third of a small window before you type anything.
What to do: Raise the context length in Ollama or LM Studio and restart the model — the limit is a setting, not a licence. Going from 20,000 to 131,000 was measured at under a gigabyte of extra memory. Or use /compact to summarise and carry on.
Status: improved — the message tells you how much was needed and what to do

**The bottom line of the window is cut off behind the taskbar.**
The usable height of your screen is not a whole number of text rows, so the last row is half hidden. Maximising rounds up; dragging does not.
What to do: Drag the window to fill the screen instead of maximising, and it will snap to whole rows. Alternatively change the console font size.
Status: not something the program can detect — it is told how many rows it has and believes it

**The AI says it cannot do something it plainly can.**
Smaller models sometimes reason about a task instead of attempting it.
What to do: Tell it directly to use the tool. It generally will, and then works correctly. This says something about the model you chose instead of about the program.
Status: depends on the model

**/review does not work.**
A file it depends on is missing from the project and from the public repository.
What to do: None. Ask the AI to look at your code directly instead.
Status: deferred — the missing file has to be restored from another machine

## Common Questions

**Q: Is this the Windows version or does it work everywhere?**
A: This is the Windows build, and the download is marked windows-amd64. The Linux build is a separate file. They are not interchangeable: the program is compiled for one operating system at a time, so the Windows version contains no Linux code and the reverse. Linux behaviour is intact — two Linux problems were accidentally introduced during this work and both were found and fixed before release.

**Q: Do I need WSL, Git Bash or anything Unix-like?**
A: No. It uses PowerShell, which is already on your machine. The AI has been told there is no Unix toolset present, so it will not reach for programs that are not there.

**Q: Why did so many of these only turn up in real use?**
A: Because the automated tests check what the program SAYS, and most of these were about something else. Three were about where text landed on the screen instead of what the text was. Four only appear when your only models are on your own machine, which is not how the tests are set up. Three were about what a smaller AI model guesses when it is not told enough, which nothing automated can check at all.

**Q: Do I need the bash tool switched on if I am on Windows?**
A: Yes. It is named bash for historical reasons but runs PowerShell on Windows. Switching it off leaves the AI unable to run anything.

**Q: My model is slow. Would a smaller one be faster?**
A: Not reliably, and this was measured instead of assumed. Four predictions were made from model sizes during this work and all four were wrong, one by two and a half times. The model with the fewest working parts was not the fastest. The only way to know is to try it on your machine.

**Q: Why did my conversation disappear when I approved a command?**
A: The approval box was drawn on a separate screen, and coming back the program miscounted how many lines to erase — so it erased about sixty lines of your conversation. Boxes are now drawn in place, above the conversation, and nothing is erased.

## Bottom Line

This release makes the program work on Windows, and most of what it fixes was invisible instead of obvious. The worst fault was not that commands failed — it was that failures were reported as successes, so the AI kept building on results it had never got. That kind of bug does not announce itself; it makes a program seem unreliable for reasons nobody can point at. The speed improvement is real and measured on the owner's own machine, from 8 minutes 14 seconds down to 15 seconds for a second message, but it is a saving on repeated reading and does not make the hardware faster: a first message on a home model on an older laptop still takes a minute or more. The more useful lesson is where the second half came from. Ten faults were found by one person using the program against a slow model and reporting what he saw, while the automated tests stayed green — they were about where text landed, about setups the tests never had, and about what a smaller AI guesses when it is not told enough. One command, /review, is still broken and is listed as broken instead of quietly left to fail.
