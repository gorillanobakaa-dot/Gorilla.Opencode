# gorilla-opencode v0.1.75 — release notes

Released 2026-08-08.

Two changes. The agent can search the open web for the first time, and the
system prompt stops telling it about tools that are switched off.

---

## Plain-language version

Until now this program could look things up in academic and reference databases
— papers, books, Wikipedia — but it had no way to search the ordinary web. If
you asked it about something that lives on a normal website and you did not give
it a link, it had nothing to work with.

It can now search the open web, but only if you run your own copy of a search
engine called SearXNG on your machine. That is a deliberate choice and not a
limitation we are apologising for: every commercial search API either shut its
doors to new users, retired, or now wants a credit card. Running your own costs
nothing, needs no account, and nobody logs what you searched for.

If you have not set that up, the agent is told plainly that web search is off,
and told to ask you for a link rather than guess. That refusal matters more than
it sounds. The single worst thing this program has ever done was invent a table
of academic citations when it could not search — real-looking links that led to
completely different papers. A tool that says "I could not search" is safe. A
tool that quietly returns nothing teaches the agent that nothing exists.

The second change fixes a quieter version of the same problem. This program lets
you switch individual tools off to save bandwidth, and there is a one-key
"low bandwidth" mode that switches off five at once. But the agent's
instructions were written as if every tool were always present. So in low
bandwidth mode the agent was still being told "you can open web pages — never
say you cannot reach a page", at the exact moment it could not. That is an
instruction to make something up. Those instruction lines now disappear along
with the tools they describe.

## Technical detail

### `web_search` gains `source: web`

Backed by a self-hosted SearXNG instance, configured with `searxngURL` in
`config.json` or the `SEARXNG_URL` environment variable. Empty means off.

**Why SearXNG and nothing else.** Every alternative was checked on 2026-08-08:

| Backend | Status |
|---|---|
| Google Custom Search JSON API | discontinued for new customers, sunset 2027-01-01 |
| Bing Search API | retired by Microsoft |
| Brave Search API | credit card required even for the free credit |
| Mojeek | no self-serve tier, sales-gated |
| DuckDuckGo HTML | serves block pages — banned since the tool was written |

SearXNG is the only general-web backend left that needs no key, no account and
no card.

**Why it fits this codebase specifically.** Its JSON response carries
`unresponsive_engines`, a per-query list of which upstream engines failed. That
gives the one signal no grounding API provides: the difference between "nothing
matched" and "everything that could have answered was blocked". Zero results
with every engine dead is returned as an **error**, never as an empty result
set, because a model told "nothing found" concludes the thing does not exist —
and that conclusion is where fabrication starts.

Partial degradation is surfaced too: results still come back, with a `PARTIAL`
line naming the engines that failed, and the "no results" message says outright
that coverage was incomplete so absence is unproven.

**Refusal comes before the permission prompt.** An unconfigured web search is
refused with setup instructions without asking you to approve anything. Asking
someone to approve a search that cannot happen trains them to approve without
reading, and no answer would change the outcome.

**SSRF note.** The SearXNG client deliberately does not use the SSRF-safe client
that every other backend uses. That guard refuses loopback and RFC1918 addresses
— correctly, because it exists to stop a *model-chosen* URL reaching a cloud
metadata service or an internal admin page. SearXNG is meant to run on exactly
those addresses. The exemption is justified by **provenance, not address**: the
host comes from your config file or environment, and the model can only fill in
the query string, which is URL-escaped. Redirects are refused outright rather
than followed, so a misconfigured or hostile instance cannot bounce the request
somewhere else and inherit the exemption.

A response that is 200 but not JSON is refused with the reason (`format=json`
not enabled), rather than parsed hopefully — the same rule that keeps DuckDuckGo
out of this tool.

### Prompt lines are gated on the tools they describe

Prompt lines may now carry a `[[needs tool.x]]` marker. The line is kept only if
that component is enabled in the loadout, and the marker is always stripped
before the prompt is sent.

Previously, sections were gated by *section* and tools by *tool*, with nothing
connecting the two. Turning a tool off removed its schema and left the prompt
still describing it. The `web_fetch` line was the worst case: it says "never say
you cannot reach a page", which becomes an instruction to fabricate the moment
`tool.fetch` is off. `ApplyLowBandwidthLoadout` — one keypress in `/context` —
switches off `tool.fetch`, `tool.websearch`, `tool.patch`, `tool.diagnostics`
and `tool.agent` together, so this was reachable by accident, not only by
someone pruning the loadout deliberately.

A section reduced to a bare header by gating is dropped entirely; a lone
`# delegation` implies content that is missing.

Line markers rather than more sections: `/context` lists one row per section
with a "what you lose" line, and splitting these out would have added one-line
rows duplicating the tool toggles already in that menu.

## Verification

**Verified:**

- Whole `./internal/...` tree passes with `-count=1`.
- The all-engines-dead branch was disabled and its test re-run to confirm it
  fails against the bug (`got nil with 0 hits`), then restored — the test is
  non-vacuous.
- An inverse guard exists: empty results with *healthy* engines must not error,
  so the test above cannot be satisfied by code that errors on every empty
  response.
- Driven end-to-end against a real SearXNG run from source: 8 hits and a genuine
  degradation warning (`startpage (Suspended: CAPTCHA)`) caught and surfaced.
  The live response confirmed the assumed JSON shape exactly.
- Prompt gating asserted in both directions — the line disappears when its tool
  is off *and* is present when on, so the test cannot pass against code that
  deletes the line unconditionally.

**Not verified:**

- Never driven through the TUI or a live agent loop. Interactive TUIs cannot be
  driven from an agent shell in this environment.
- The behavioural effect of the prompt change on a real model is unmeasured.
  Only its assembly is tested.
- Tested against one SearXNG version, on one machine, over one connection. No
  measurement of behaviour on a slow link.
- No measurement of how often upstream engines fail in normal use, so the
  practical frequency of `PARTIAL` results is unknown.

## Setting up SearXNG

No container required — it is a Python application and runs from source.
Verified on Debian 13 with Python 3.13:

```sh
git clone --depth 1 https://github.com/searxng/searxng.git
python3 -m venv searxvenv
./searxvenv/bin/pip install pyyaml -r searxng/requirements.txt
```

Write a `settings.yml`:

```yaml
use_default_settings: true
server:
  secret_key: "change-me"
  limiter: false          # the bot limiter 429s local automation
  bind_address: "127.0.0.1"
  port: 8888
search:
  formats: [html, json]   # json is OFF by default; without it you get 403
```

Run it:

```sh
SEARXNG_SETTINGS_PATH=$PWD/settings.yml PYTHONPATH=$PWD/searxng \
  ./searxvenv/bin/python -m searx.webapp
```

Then set `searxngURL` to `http://127.0.0.1:8888` in
`~/.config/gorilla-opencode/config.json`, or export `SEARXNG_URL`.

Two traps, both hit during development: do **not** `pip install -e .` — its
build requires `msgspec` and `pyyaml` to be present first, and running from
source with `PYTHONPATH` avoids the packaging step entirely. And `json` is not
in `search.formats` by default, which is why public SearXNG instances answer
`403` to this tool and are not a substitute for your own.

## Upgrade notes

Nothing breaks. `source: web` is additive; every existing source behaves as
before. If you never configure SearXNG, the only visible change is that the
agent now says web search is unavailable instead of not knowing the option
exists.
