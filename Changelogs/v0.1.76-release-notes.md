# gorilla-opencode v0.1.76 — release notes

Released 2026-08-09.

v0.1.75 made web search possible. This release makes it happen — the assistant
now offers to set it up for you, instead of explaining how and leaving you to it.

---

## Plain-language version

Last release added web search, but only if you ran your own copy of a search
engine called SearXNG. Which meant, realistically, almost nobody had it.

Now the assistant offers. Ask it something it needs the web for, and instead of
"web search is not configured, here are some instructions", it says it can set
it up for you — no account, no API key, no card, all on your own machine, a
couple of minutes. Say yes and it runs one installer. Say no and it asks you for
a link instead, as before.

The installer is a script we ship, not something the assistant improvises. That
distinction matters more than it sounds. When we handed an earlier version of
those setup instructions to a model as plain text and asked it to pass them on,
it quietly dropped one word — `pyyaml` — from one line. That single omission
makes the install fail with a confusing error. A model doing the installation
itself would make the same class of mistake and then tell you it had worked. So
the assistant's job is now to ask you and run one command; every decision that
could go wrong is made once, in a script that does not improvise.

The script also checks its own work. It doesn't finish by saying "installed" —
it runs a real search and requires real results back before it reports success.

## Technical detail

### The agent offers, a script installs

`packaging/setup-searxng.sh`, shipped in the .deb at
`/usr/share/gorilla-opencode/setup-searxng.sh`.

The `web_search` refusal text now instructs the model to offer the setup, to run
that one path if the user agrees, and explicitly **not** to improvise the steps
or retype them from memory. If the user declines, the existing rule stands: ask
for a URL, use `web_fetch`, invent nothing.

What the script encodes, so nobody has to remember it:

- **Do not `pip install -e .`** — SearXNG's build backend imports `msgspec` and
  `yaml` before either is installed, so metadata generation fails. It runs from
  source via `PYTHONPATH` and skips packaging entirely.
- **`json` is not in `search.formats` by default**, which is exactly why public
  SearXNG instances answer `403` to an API request and are not a substitute for
  your own.
- **The bot limiter `429`s local automation**, so it is off — for an instance
  bound to loopback only.
- A **systemd user service**, so it survives a reboot. No root: SearXNG is not
  packaged in Debian, so this is a git clone and a venv in your own home. The
  single `apt` call is guarded and only fires if `python3-venv` is genuinely
  missing.
- `searxngURL` written into `config.json` **preserving every other key**.

Then it **verifies with a live query** and requires results back. It exits
non-zero naming the step that failed rather than reporting "probably fine",
because an installer that reports success without checking is guessing, and a
half-working SearXNG is worse than none — it answers, and the agent summarises
whatever it answered with.

### A test-isolation bug this exposed

`internal/llm/tools`' `TestMain` called `config.Load` without redirecting
`XDG_CONFIG_HOME`, so `config.Get()` had been returning the developer's **real**
`~/.config/gorilla-opencode/config.json` all along.

Invisible until a config value changed behaviour. `websearch.go` reads
`cfg.SearxNGURL`; the moment the installer wrote a real one, four tests that set
up `httptest` stub servers stopped talking to them and queried the live instance
instead. They failed with `want 2 hits, got 8`.

That number is luck. Had the live instance returned two results, the suite would
have stayed green while testing nothing at all.

`configtest` gains `IsolateWith(m, setup)`: the redirect happens first, the load
second — the only ordering that works, because `config.Load` resolves the config
path when it runs. The panic-guard stays in one place.

### A negative result, recorded

`internal/llm/provider/grounding_probe_test.go` establishes that **Antigravity
does not support Google Search grounding**:

| Model | Result |
|---|---|
| `gemini-3.6-flash-medium` | HTTP 200, confident answer, **no** `groundingMetadata` |
| `gemini-3.1-pro-high` | HTTP 400 `INVALID_ARGUMENT` |

The request shape is not the cause — gemini-cli places `tools` in exactly the
same position (`toVertexGenerateContentRequest`), and that is what the probe
sends.

Note the two different failure modes for one request. The pro model refuses
honestly; the flash model accepts the request, discards the tool, and answers
from training data anyway. So the probe asserts on the presence of
`groundingMetadata`, never on whether the answer reads plausibly — a fluent
ungrounded answer is indistinguishable from a searched one.

It is opt-in (`GORILLA_LIVE_GROUNDING=1`) and documented, so nobody spends quota
rediscovering it.

## Verification

**Verified:**

- The installer was run end to end on a real machine: 34 results on its own
  verification query, service `enabled` and `active`, `config.json` gained
  `searxngURL` with every other key byte-identical.
- `web_search` with `source: web` then returned **8 hits** through the normal
  code path, including a live degradation warning
  (`startpage (Suspended: CAPTCHA)`) surfaced rather than swallowed.
- The built `.deb` was extracted and the shipped script confirmed present,
  mode `755`, byte-identical to `packaging/setup-searxng.sh`.
- Whole `./internal/...` tree passes with `-count=1`.

**Not verified:**

- The installer has been run on exactly one machine (Debian 13, Python 3.13).
  Other distributions, Python versions and non-systemd sessions are untested.
- The `apt` path for `python3-venv` never fired here, because it was already
  installed. That branch is unexercised.
- Whether models reliably *offer* the setup rather than ignoring the
  instruction is unmeasured. Only the text is tested, not the behaviour it asks
  for.
- Nothing here has been driven through the TUI or a live agent loop.

## Upgrade notes

Nothing breaks. If you already set `searxngURL` by hand, the installer is not
required and nothing changes for you. If you never configure web search, the
only difference is that the assistant now offers instead of only explaining.
