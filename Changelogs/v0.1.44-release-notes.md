# Gorilla OpenCode v0.1.44 — The copyable mode is now something you can actually reach

**Date:** 2026-07-28
**Previous version:** v0.1.43

---
## Why This Release Exists
v0.1.44 exists because v0.1.43 got something wrong. We added a plain-text mode that finally lets you select and copy a whole session — and then made it reachable only by typing --plain on a command line. The desktop icon runs the program with no arguments, and clicking the icon is how most people start it. So the feature was there and most users did not have it. That is the second time this class of mistake has bitten this program: the agent's working folder used to default to your entire home directory for the same reason, because the icon passes nothing.

## What You'll Actually Notice

**Reaching plain mode from the desktop icon**
- BEFORE: Impossible. The icon runs the program with no arguments, so a flag-only mode was invisible.
- AFTER: Right-click the icon and choose "Plain mode (selectable and copyable)".
- Affects: everyone who starts the program from an icon

**Making the choice stick**
- BEFORE: You had to remember the flag every single time, from a shell.
- AFTER: /settings has "Which interface to start". Set it once and it applies however you launch, icon included.
- Affects: everyone

**Switching while you are already inside**
- BEFORE: No way to do it, and no hint the mode existed.
- AFTER: Type /plain. It saves the choice and tells you it applies next launch, rather than looking like it did nothing.
- Affects: everyone

## Decisions & Why

**Four ways in rather than one** — People start this program differently — some click an icon, some type a command, some are already inside it when they realise they need to copy something. One route only ever serves one of those groups. (benefits: everyone; tradeoff: More surface to keep consistent, so there is now a test that holds the two desktop-entry copies in step.)

**The normal interface stays the default** — Plain mode carries fewer commands — you cannot change model or edit settings there. Something with fewer capabilities should be chosen deliberately, not inherited from a default you never saw. (benefits: everyone; tradeoff: You have to opt in to the copyable mode.)

**Switching interface takes effect at the next launch, not immediately** — The screen is already drawn by the time you can type. Swapping the whole rendering approach mid-session would be a much larger change than this fix, and pretending otherwise would leave you staring at an unchanged screen wondering if it worked. (benefits: everyone; tradeoff: One restart. The message says so plainly.)

## Deliberately Not Done

- **Asking which interface you want at startup** — There are already two questions before you can type — the working folder, and what you want shown. A third would be noise, and this is a preference you set once rather than a decision per session.
- **Making the normal interface copyable** — Still the better end state, still a large rebuild: 21 pop-up sites across 15 dialogs and about 2,700 lines of layout code that assume they own the whole screen. Unchanged from v0.1.43.

## Privacy & Security
No changes. Nothing new is collected, sent or stored. The only new stored value is which interface you prefer, in your own config file.

## Risks, Backup & Recovery

- **Backup needed:** No.
- **Install time:** Under a minute.
- **Restart required:** Yes, as with any update. Quit any running copy first — it holds your old settings in memory and may write them back.
- **Rollback:** Install the v0.1.43 .deb. Nothing about your stored data changed, so nothing is lost either way. The interface preference is simply ignored by the older version.

## What's Still Broken

- **The normal interface still cannot be selected or copied** (anyone not using plain mode) — workaround: Use plain mode, or /export for a complete written record. — status: Open. It needs a large rebuild of the interface, planned separately.
- **Switching interface needs a restart** (everyone) — workaround: None needed — the message tells you. — status: By design; swapping renderers mid-session is a much larger change.
- **Right-click actions may not appear until your desktop rescans launchers** (some desktop environments) — workaround: Log out and back in, or run update-desktop-database. — status: Outside our control.

## Common Questions

**Q: Do I have to reinstall to get the right-click option?**
A: Yes, this version installs the updated launcher. If the entry does not appear immediately, your desktop is caching launchers — log out and back in once.

**Q: Which should I use?**
A: Stay on the normal interface unless you need to copy the session out or you prefer no panels at all. Plain mode has fewer commands: you cannot change model or edit settings there.

**Q: If I set it in /settings, does the icon respect it?**
A: Yes. That is the whole point of this release. The setting applies however you start the program.

**Q: Why does the switch not happen straight away?**
A: The screen is already drawn by the time you can type a command. Changing the whole way the program draws mid-session is a much bigger job than this fix, so we save the choice and tell you to restart rather than pretending.

**Q: Is anything different if I never use plain mode?**
A: No. Nothing about the normal interface changed in this version.

## Bottom Line
This is a correction, not a new capability. v0.1.43 solved the copy problem and then hid the solution behind a flag that most people would never type, because the desktop icon passes no arguments. There are now four ways to reach it — a right-click action on the icon, a saved setting, a command from inside, and the original flag — and the icon route was tested against the exact command the icon runs. The normal interface is unchanged and stays the default, since plain mode deliberately carries fewer commands. If you never use plain mode, this release changes nothing for you.

# v0.1.44 — plain mode reachable from the desktop entry, a saved setting, and /plain

## Architecture & Footprint

- **Toolchain:** go1.24.4 linux/amd64. No dependency changes. Built from the v0.1.44 tag with -ldflags "-X github.com/opencode-ai/opencode/internal/version.Version=v0.1.44".
- **Flags:** No flag changes. --plain is unchanged and still wins over the setting.
- **Resource deltas:** No measurable change expected; this adds a config field, a settings row, a slash command and desktop-entry metadata. No binary-size, RSS or startup measurement was taken, so none is quoted.

## Code Changes

| File | Change | Old behavior | New behavior |
|------|--------|--------------|--------------|
| `internal/config/config.go` | modified | No interface preference existed; plain mode was selectable only by --plain at invocation. | Config.Interface string, json "interface", omitempty. Absent means full. |
| `internal/config/extras.go` | added | n/a | InterfaceFull/InterfacePlain constants, InterfaceMode() and SetInterfaceMode(), plus a generated /settings row of KindEnum with Restart:true. Restart is set because the renderer is running by the time the dialog can be opened; a row that silently no-ops is worse than one that states its constraint. |
| `cmd/root.go` | modified | if plainMode { ... } — the flag was the only route into plain mode. | if plainMode || config.InterfaceMode() == config.InterfacePlain. Precedence: explicit flag, then saved setting, then TUI. |
| `internal/tui/tui.go` | added | No command referenced plain mode; it was undiscoverable from inside the program. | /plain (aliases /copy, /copyable) persists the preference and reports that it applies at next launch. It does NOT attempt to swap renderers mid-session. |
| `packaging/gorilla-opencode.desktop` | modified | Single Exec=gorilla-opencode launch, no Actions group. | Actions=plain; plus a [Desktop Action plain] group running `launch --plain`. launchCmd has DisableFlagParsing:true and execs the real binary with args verbatim, so the flag arrives intact. |
| `cmd/install.go` | modified | The desktopEntry string written by `gorilla-opencode install` had no Actions group, so per-user installs would have differed from the .deb. | Same Actions group, with a comment naming the other copy. Both pass desktop-file-validate. |
| `cmd/desktop_entry_test.go` | added | Nothing held the two desktop entries in step; they are hand-edited in separate files. | Asserts both declare Actions=plain;, define [Desktop Action plain], pass --plain to launch, keep the default click on the full interface, and name the action in terms of copying. |
| `internal/commands/registry.go` | modified | No /plain entry, so /help could not mention it. | Registered in GroupSession, explaining WHY Ctrl+A does not work in the TUI and that the change applies next launch. |
| `README.md, docs/SETTINGS.md` | modified | README documented --plain as the only route. | All four routes documented, ordered by how the reader is likely to start the program. SETTINGS.md regenerated from the registry (a test guards staleness). |

## Subsystem Changes

**STORAGE:** config.json gains `interface` (string, omitempty). Absent or any value other than "plain" resolves to full, so older configs and hand-edited typos fail safe toward the interface with more capability. No migration.

**OTHER:** Desktop entry metadata only; no change to the binary installed, the icons, or the docs the package ships beyond the release notes themselves.

**TELEMETRY:** No changes. None collected or transmitted.

## Test Coverage

- **Added:** cmd/desktop_entry_test.go — two tests over BOTH desktop-entry copies. Previously the cmd package had no coverage of the entries at all.
- **Removed:** None.
- **Notes:** 18 packages pass (cmd now has tests), go vet clean. The behavioural claim was verified end to end rather than only unit-tested: with interface:plain saved and NO flag, both `gorilla-opencode` and the icon's exact `gorilla-opencode launch` start plain mode; with interface:full the same command starts the TUI, evidenced by the sandbox's expected 'could not open a new TTY' from the TUI path. The first attempt at the launch test hit ensureEnvTemplate()'s first-run branch because the isolated HOME had no env file — that was harness setup, not a failure, and was corrected by seeding the file rather than by weakening the test.

## Security Posture
No changes. No CVEs, no dependency changes, no permission changes, no new attack surface. A Desktop Action executes the same binary already on PATH with one extra argument. Credentials were read from the developer's config for the live launch tests and every copy was shredded afterwards, with the scratchpad verified clean by pattern search.
