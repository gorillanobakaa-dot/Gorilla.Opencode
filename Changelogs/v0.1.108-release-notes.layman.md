# Your connection now has a setting, and answers can arrive in one piece instead of word by word — Plain Language

> Session record generated 2026-08-20

---

## What happened

This program is built for people whose internet is a satellite phone link or a weak mobile signal, where data is bought by the megabyte and often cannot be topped up with a card. All the machinery for surviving a bad connection already existed and had been measured against a deliberately broken link. None of it could be found. Every setting was an environment variable, which means the person on a 2 KB/s satellite link had to read the source code to survive on it.

This session bundles those settings into five named profiles you pick from a list, from Austere (1-9 KB/s, an Iridium satellite phone or a 2G signal) up to Unconstrained (Starlink, modern 4G and 5G). A profile changes how patiently the program waits before deciding your connection is dead, and how much data one message may spend. It never changes what the AI can do.

Along the way we measured what the connection actually costs, and one number changed the advice completely. Watching the AI type word by word costs 27 times more data than receiving the finished answer in one piece — 22,256 bytes against 834 for the identical reply. The word count you are billed for is exactly the same either way. So on the two slowest profiles the typing effect is switched off, and the picker explains why in plain language so you can overrule it if you prefer to watch it type.

## Honest state of play

Done and tested: the five profiles, the picker, the /connection command, the /settings row, the speed estimate, non-streaming on slow profiles, and the corrected too-big-message error. Thirty test packages pass, and both the Debian and Arch packages were opened and checked to confirm the binary inside is the one we built and carries the new code.

Not touched: the loadout, the tool list, the model. Deliberately, so that switching profile can never change what the AI is able to do.

Not verified in real use: the profiles have never run against a genuinely slow connection. They were built and tested on a fast one.

## Worst case if something is wrong

The likeliest harmful outcome is a profile that is too impatient for your real connection. If you pick Unconstrained on a satellite link, the program gives up after sixty seconds on answers that were still coming, and you would see repeated failures on a connection that actually works — the exact problem the feature exists to prevent, caused by the feature. The fix is to pick a slower profile.

A second, quieter one: with the typing effect off, a stuck connection looks identical to a slow answer. The dribble of words was itself proof something was alive. On the slow profiles the only thing now protecting you is the long wait limit, which is why those are set to eight and fifteen minutes instead of something brisk.

## What changed for you

**Finding the connection settings**
- Before: Environment variables only. You had to read the source to know they existed.
- After:  Five named profiles in a list, on first run, via /connection, or in /settings.
- Affects: everyone

**How long it waits for an answer**
- Before: Two minutes for everyone, whatever the link.
- After:  Fifteen minutes on Austere down to one minute on a fast line.
- Affects: everyone

**How the answer arrives**
- Before: Always word by word, on every connection.
- After:  Whole answer at once on the two slowest profiles: 27 times less data.
- Affects: some users

**When a message is too big to send**
- Before: Told the connection kept failing, when the connection was fine.
- After:  Told the conversation has grown too big for this profile, and what to do about it.
- Affects: some users

**Knowing your link speed**
- Before: No measurement at all.
- After:  Estimated from traffic already sent. Nothing is downloaded to test your line.
- Affects: everyone

## What you can do now

- Pick a connection profile from a list instead of setting environment variables.
- Type /connection at any time to change it, or find it in /settings under 'Network and pace'.
- See an estimate of your connection speed that cost nothing to produce - no test file is downloaded.
- Receive answers in one piece on the two slowest profiles, using 27 times less data for the same reply.
- Get told plainly when a message is too big for your profile, instead of being sent to debug a connection that is working.
- Have the program retry less on a slow link and more on a fast one - two attempts on Austere, five on a fast line.

## Should you be concerned?

Moderately, in two specific places, and not at all elsewhere.

First: none of this has run on a real slow connection. The numbers come from measurements taken on a fast line and from a deliberately broken link simulated in August. That is a reasonable basis, but it is not the same as a satellite phone in the field.

Second: turning off the typing effect removes the signal that told you something was still alive. We think that trade is worth 27 times less data, and the screen explains it so you can disagree, but it is a real loss and not a free win.

What should NOT worry you: the default profile deliberately behaves almost exactly like the old version, so upgrading changes little for anyone who never opens the picker. And a profile cannot change what the AI is able to do - only how long it waits and how much data it spends.

## Glossary

**Profile** — A named set of connection settings you pick from a list, like Austere or Broadband.

**Streaming** — Sending the answer one word at a time so you watch it appear, instead of all at once when finished.

**Token** — Roughly a word - the unit the AI company counts and bills you for.

**Upload budget** — A ceiling on how much data one message may spend, including any retries, so a failing connection cannot quietly drain your allowance.

**Round trip** — The time for a message to reach the far end and a reply to come back. On satellite this is one to two seconds even when everything works.
