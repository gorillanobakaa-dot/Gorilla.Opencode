# Gorilla OpenCode v0.2.0 — Breathing new life into an old fossil

*Track 1 of 2 — written for anyone. The developer track follows below.*

## Why This Release Exists

Every AI coding assistant carries a **system prompt**: a standing set of
instructions sent to the model before it ever sees your question. You do not
write it and, in most tools, you never see it. It is the difference between an
assistant that checks its work and one that cheerfully tells you a build
succeeded when it did not.

This program inherited its system prompt from upstream OpenCode, and that prompt
was written in 2023. Here is an actual line from it:

> IMPORTANT: Keep your responses short, since they will be displayed on a
> command line interface. You MUST answer concisely with fewer than 4 lines...

The string "IMPORTANT" occurs **seven times** in that file, two of them as "VERY
IMPORTANT"; "NEVER" occurs three times and "MUST" four. The brevity instruction is
given **three separate times**, twice in the identical "fewer than 4 lines" form —
as though the model would only believe it on the third attempt. The whole thing
reads like someone shouting at a machine. (Counted, not impressionistic:
`grep -o` against `system-prompts/historical/coder-anthropic-2023-upstream.md`.)

That is not a cheap shot at the original authors. It is the point of this
release, and it is worth being precise about: **being able to write excellent Go,
Rust or TypeScript does not mean you understand how a language model works.**
Those are different skills that happen to sit next to each other. The people who
built OpenCode built a genuinely good terminal program. The prompt inside it was
written the way almost everyone wrote prompts in 2023 — by intuition, in the
absence of research, on the reasonable-sounding but wrong assumption that
emphasis makes a model comply.

The research since then says the opposite, and consistently:

- Capitalising a word **splits it into more tokens** and dilutes attention rather
  than concentrating it.
- Threatening or emotionally loaded instructions measurably increase hedging and
  **false reports of success** — the exact failure this program exists to avoid.
- Piling on constraints makes instruction-following *worse*, not better. A 2026
  benchmark found real agent instructions average nearly twelve constraints, and
  that models follow them poorly.

We replaced that prompt once already. This release rebuilds it properly, using
guidance published by the team at Anthropic behind **Claude Fable 5** — who did
something unusual and generous: they wrote down what they learned about steering
an AI through long, unsupervised work, in plain copyable language, and published
it instead of keeping it as a competitive advantage. Their guide is the primary
source for this release and is credited in full in
[`system-prompts/RESEARCH-SOURCES.md`](../system-prompts/RESEARCH-SOURCES.md).

## What You'll Actually Notice

**It stops telling you things it has not checked.** The strongest single change:
before the AI reports progress, every claim it makes now has to point at
something that actually happened in the session — a command that ran, a file it
read. "I've fixed the build" is no longer something it can say on the strength of
having edited a file. In Anthropic's own testing this nearly eliminated invented
status reports. If you leave a Firefox or kernel build running overnight, this is
the change that matters to you.

**It stops doing things you did not ask for.** Asking a question is now
explicitly not an instruction to start changing code. If you describe a problem
or think out loud, you get an assessment — not a surprise commit, not a backup
branch you did not want, not a "helpful" refactor of code you were only asking
about.

**It stops trailing off.** A specific and infuriating failure: the AI ends its
turn with "I'll now run the build" — and then does not run the build. The rule is
now blunt: if the last thing you were about to say is a plan, carry out the plan
first.

**It stops giving up because the conversation got long.** Long sessions used to
produce unprompted offers to summarise and start fresh. It is now told plainly
that a long conversation is not a reason to stop working.

**Its final summary is written for someone who wasn't watching.** After hours of
unattended work, that summary is your first look at any of it. The AI is now told
to drop the shorthand it built up while working — no arrow chains, no invented
abbreviations, no jargon it coined three hours ago — and write the outcome first,
in ordinary sentences.

**It uses helpers properly.** It could always dispatch read-only helper agents to
search the codebase in parallel; the prompt simply never said when. It does now
— and it is told those helpers cannot build or run tests, so it stops trying to
hand them work they cannot do.

**Compaction stops erasing what already failed.** When a long conversation is
compressed to save space, the record of which fixes were already tried and did
not work now survives. Without that, a freshly compacted session will happily
retry the thing that failed an hour ago.

## What It Costs You

The prompt got bigger: roughly **1,058 tokens per turn, up from 464** — and it is
charged on every single request you make.

Being exact about that figure, since this release is about not overstating things:
the *sizes* are measured (1,855 → 4,233 bytes, from a probe run against the built
prompt, not a guess). The *token* numbers are an estimate — one token per four
bytes, the same approximation the `/context` menu uses to price everything. A real
tokenizer would give a slightly different answer. The direction and rough scale are
right; the last digit is not.

We think it is worth it, and you do not have to take our word for it: press
`/context` and you can switch off any individual section — with its token cost
and a plain-English line telling you what you lose. Two sections are marked
critical, because turning off the honesty rules makes the AI *more* likely to
claim success it never observed, and a menu that let you do that silently would
be dishonest.

For scale: the 2023 prompt this replaced was about **2,003 tokens**. The new one
is still roughly half of it.

## What We Deliberately Did Not Do

Anthropic's guide recommends adding a `send_to_user` tool, so an agent working
asynchronously can push a message to you without ending its turn. We evaluated it
and left it out. It solves a problem this program does not have — the AI's text
already streams straight into your terminal, and nothing summarises it on the
way. Adding it would have been copying the homework rather than doing it.

We also left the session-title prompt completely alone. We read it, none of the
guidance applies to a thing whose only job is to write fifty characters, and
changing it to look busy would have been worse than leaving it.

## What We Have Not Proved

We have not A/B tested this against the old prompt on real Firefox 154/155 or
kernel builds. The changes rest on published research and on Anthropic's reported
testing — not on our own measurements. That experiment is on the roadmap in
[`system-prompts/README.md`](../system-prompts/README.md) and that line stays
there until we have actually run it.

# Developer track

## Summary

All four shipped system prompts were reworked against Anthropic's Claude Fable 5
prompting guidance. Three new switchable sections; expanded honesty, verification,
output and conduct sections; the study copies in `system-prompts/` reorganised and
placed under a byte-identity test.

Primary source, credited in `system-prompts/RESEARCH-SOURCES.md`:
<https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-fable-5#create-a-send-to-user-tool>

## Changes

## The drift that prompted the new test

`system-prompts/README.md` described `current/coder-anthropic.md` as "used by the
Anthropic family **and by the `local` provider"`. That has been false since the
`baseAnthropicCoderPrompt` constant was deleted from `coder.go` — `BaseCoderPrompt`
returns only the modern prompt regardless of provider. Meanwhile the study copy of
the prompt that *is* shipped lived in `proposed/coder-modern.md` and was a flat-prose
draft that never matched the terse `coder-modern.txt` actually embedded.

So the directory whose entire purpose is "read what we actually send you" was
publishing two prompts we do not send and none of the ones we do.

`studycopy_test.go` byte-compares each `//go:embed` source against its published
copy and fails with the `cp` command to fix it. Verified non-vacuous: appending a
single byte to `system-prompts/current/task.md` fails the test; restoring it
passes.

## Measurements

Sizes measured with a probe test in-package, not estimated:

```
SUMMARIZER bytes=535   (was 351)
TITLE      bytes=267   (was 267 — unchanged)
BASECODER  bytes=4233  (was 1855)   ~1058 est. tokens, was ~464
TASK       fragidx=660 (was 228)
```

The `len/4` token figure is the same estimator `/context` uses to price sections;
it is an estimate and is labelled as one. **Not measured:** actual tokenizer
counts against any specific model, and any behavioural A/B against the previous
prompt.

## Test changes

`TestPromptOutputsAreByteIdentical` and `TestTaskPromptCompositionIsByteIdentical`
are byte-identity guards from the earlier storage refactor. Their constants were
updated deliberately, with the per-prompt breakdown recorded in the block comment
above the test — the file's own instructions require exactly that, in the same
commit, stated plainly.

`TestParseSectionsShapeOfTheShippedPrompt` asserts the section list in order;
updated to `{method, build discipline, verification, honesty, scope, delegation,
memory, tools, output, conduct}`. Verified non-vacuous by perturbing one entry
(`scope` → `scoop`) and confirming failure, then restoring.

Full suite: `go build ./... && go test ./...` clean.

## Citations added

`system-prompts/RESEARCH-SOURCES.md` gains the Anthropic credit and five papers.
Every arXiv ID in the whole file — the new entries and the pre-existing ones —
was fetched and its title compared against arXiv's metadata on 2026-07-29. All
resolved; none was fabricated. Five pre-existing entries carried a paper's short
or informal title and were corrected in place (2607.01641, 2601.20467, 2603.10047,
2601.02896, 2602.23971). The five Anthropic documentation URLs returned 200.

New, all within six months except where noted:

- arXiv:2605.01771 — *The Compliance Gap* (2026-05-03). Names the verbal-behavioural
  disconnect directly; its worked example is an agent that agrees to read files
  individually, batches the call, and reports success. This is the paper behind
  "audit before reporting".
- arXiv:2601.10343 — *OctoBench* (2026-01-15). Separates solving a task from
  following the scaffold's rules.
- arXiv:2603.25723 — *Natural-Language Agent Harnesses* (2026-03-26). The academic
  case for `/prompts` and `/context`.
- arXiv:2606.23664 — *MAS-PromptBench* (2026-06-22). Where multi-agent prompt
  optimization stops paying off.
- arXiv:2505.16944 — *AGENTIF* (2025). Outside the window, included because it is
  the measurement the others build on.

## Not verified in this release

- No behavioural A/B against the previous prompt on a real build. Tracked in
  `system-prompts/README.md`.
- No tokenizer-accurate token counts; all token figures are `len/4` estimates.
- The `/context` and `/prompts` dialogs were not driven interactively — an agent
  shell here cannot drive a Bubble Tea TUI (see `CLAUDE.md`). Section registration
  and assembly are asserted headlessly by `sections_test.go`. **The visual
  appearance of the three new `/context` rows is unconfirmed and needs a human
  look.**
