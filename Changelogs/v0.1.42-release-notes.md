# Gorilla OpenCode v0.1.42 — Three bugs the screenshots found that the tests did not

**Date:** 2026-07-28
**Previous version:** v0.1.41

---
## Why This Release Exists
This release exists because of a photograph. The plan was to take screenshots of v0.1.41 to publish alongside it — and reviewing them before upload turned up three bugs, two of which no automated check had noticed. The new command list was hiding whichever command your cursor sat on. The sign-in box, added one release earlier precisely to fix an un-clearable message, could not itself be dismissed with esc. And that same box drew black bars beside its text and cut the sign-in link off at the edge of the screen. All three were obvious the instant someone looked at a picture of the screen; none were obvious from the code or the test suite.

## What You'll Actually Notice

**The /help command list**
- BEFORE: Whichever command you had selected was missing from the list, while its explanation sat below — /clear absent with /clear's description, then /export, then /cd as you moved down.
- AFTER: The selected command shows as a highlighted bar with readable text. Nothing vanishes.
- Affects: everyone who opened /help

**Dismissing the sign-in box**
- BEFORE: esc did nothing. The box stayed until sign-in finished.
- AFTER: esc hides it, and signing in carries on regardless — dismissing it by accident costs you nothing.
- Affects: anyone signing in with Google

**How the sign-in link is displayed**
- BEFORE: One very long line, wider than the terminal, so the link ran off the edge of the screen and could not be read or copied. Every other line in the box was shorter, leaving black bars beside the text.
- AFTER: The link wraps inside the box, all of it visible, and the box is a clean rectangle.
- Affects: anyone whose browser did not open automatically

## Decisions & Why

**The sign-in link now wraps instead of staying on one line.** — I originally kept it unwrapped so it could be copied in one piece. The screenshot proved that wrong: the line was wider than the screen, so the link was cut off — unreadable and uncopyable. A wrapped link you can read beats an unbroken one you cannot see. (benefits: anyone reading the link off the screen; tradeoff: You can no longer select it as a single unbroken line. In practice the browser opens by itself and this is the fallback.)

**The quit key does not dismiss the sign-in box; only esc does.** — Every other panel can simply be reopened. The sign-in link cannot — losing it means starting /login again. (benefits: anyone who reaches for the quit key by habit; tradeoff: One more key to learn, stated on the box itself.)

**On a short terminal the sign-in box drops its explanation rather than shortening the link.** — Half a sign-in link is worthless; the surrounding sentence is merely helpful. (benefits: anyone on a small terminal window; tradeoff: Less explanation in a cramped window.)

**Six screenshots added to the documentation, each linking to full resolution.** — Terminal screenshots become unreadable the moment they are scaled down to fit a page. (benefits: anyone deciding whether this tool is for them; tradeoff: About a megabyte of images in the repository.)

## Deliberately Not Done

- **Reshooting the five screenshots that show v0.1.41 in the title bar.** — They show behaviour that has not changed. Only the two shots demonstrating the fixes needed to be current.
- **Copying the sign-in link to the clipboard automatically.** — This machine has no clipboard helper installed, and the alternative — writing a terminal escape sequence — is unreliable across terminals. Promising a copy that silently fails is worse than a link you can read.
- **Adding blank lines between the groups in /help.** — It reads slightly better but pushes the list past the height of a normal terminal, so you would have to scroll to see commands that currently all fit at once.

## Privacy & Security
No change to what is collected or sent; still only the AI providers you configure. One note carried forward rather than introduced: the sign-in screen shows a one-time sign-in link containing a short-lived token, so treat a screenshot of it the way you would any other in-progress login — the token expires within minutes and the identifier alongside it is public, embedded in every copy of the program.

## Risks, Backup & Recovery

- **Backup needed:** None. Settings files are untouched and unchanged from v0.1.41.
- **Install time:** Under a minute.
- **Restart required:** Yes, and it matters more than usual — see the FAQ. A running copy keeps using the version it started with, so the fixes only appear in a window you open after installing.
- **Rollback:** Install the previous .deb. Nothing in your settings changes between these two versions.

## What's Still Broken

- **Keystrokes in the interface still cannot be tested automatically here.** (Every dialog.) — workaround: None needed; report anything odd. — status: A limit of the development environment — a minimal test program cannot receive simulated key presses there either. All three bugs in this release were in exactly that blind spot, and two were found by eye instead.
- **A connection's key is still not checked when you save it.** (Anyone pasting a key with a typo or missing prefix.) — workaround: If a model returns an authorisation error, check the key is complete, including any prefix such as nvapi-. — status: Open, carried from v0.1.41. The cheap check proves nothing: some providers list their models without asking for a key at all.
- **Language servers switched off in /context only stop at the next launch.** (Anyone toggling them mid-session.) — workaround: Restart. — status: Known, deferred.

## Common Questions

**Q: I installed the fix but the bug is still there. Why?**
A: Almost certainly because the window was already open. A running program keeps using the copy of itself it started with, even after a new version is installed over it — the system marks the old file as deleted and the running process carries on with it. This happened during testing of this very release: the fix was installed, the bug appeared unchanged, and the title bar was still showing the older version. Close the window, open a new one. The version at the top tells you which one you are actually looking at, which is exactly why it is printed there.

**Q: How did three bugs get through if you test everything?**
A: Two of them were invisible to the kind of test that existed. The /help list was checked by asking whether each command's text appeared in the output — and it did. The text was there the whole time; it was drawn in a colour identical to its background, so a person saw a blank line and the test saw a match. Colour is now asserted, not just presence. The third — esc doing nothing — was in a code path that needs the whole application constructed to reach, so it had no test at all. It does now.

**Q: Why can't you test the keyboard directly?**
A: The development environment cannot deliver simulated key presses to this kind of terminal interface — verified by checking that even a minimal test program fails the same way, so it is the environment and not the code. That blind spot is exactly where all three of these bugs lived, which is why screenshots turned out to be worth more than another test run.

**Q: Do I need to change any settings?**
A: No. This release reads exactly the same files as v0.1.41 and changes none of them.

## Bottom Line
Three bugs, all in what you see rather than what the program computes, and two of them found by looking at pictures of the screen rather than by running tests. The most useful thing to take from this release is why the tests missed them: the /help list was verified by checking that each command's text was present in the output, and it always was — drawn in a colour identical to its background. The test saw a match; a person saw a blank line. Presence is not visibility, and the checks now assert colour. The other lesson is duller but cost real confusion during testing: a running copy of the program keeps using the version it started with, so a fix installed underneath an open window changes nothing until you open a new one. Nothing here changes your settings, and the whole release is repair plus six screenshots.

# v0.1.42 — TUI overlay correctness: esc routing, multi-line padding, and colour-asserted selection

## Architecture & Footprint

- **Toolchain:** go1.24.4 linux/amd64. No dependency changes, no new modules, no build-flag changes.
- **Flags:** unchanged.
- **Resource deltas:** Binary essentially flat against v0.1.41 (wrapping helpers and one extracted method). Repository grows ~920 KB from six 1600x900 PNGs committed under docs/screenshots/gallery/.

## Code Changes

| File | Change | Old behavior | New behavior |
|------|--------|--------------|--------------|
| `internal/tui/tui.go` | modified | The loginURL clear sat inside the `key.Matches(msg, keys.Quit)` branch, so esc never reached it and the overlay could not be dismissed. The overlay also rendered the URL on one unwrapped line: the box sized to the URL, exceeded the terminal and was clipped, while the remaining lines — padded only to the intended content width — left unpainted cells that render as black bars, since lipgloss does not pad the short lines of a multi-line render. | tryDismissLoginOverlay is called after every dialog's routing block, each of which returns early for a KeyMsg when open, so reaching it proves no dialog claimed the key; dialogs therefore keep first claim on esc and any dialog added later inherits precedence. The quit branch deliberately no longer clears it (unlike other overlays, the URL cannot be reopened). hardWrap breaks the URL mid-token — a word-wrapper would leave a single over-wide line — and renderEach pads each line individually; a height budget sheds prose before URL lines. |
| `internal/tui/components/dialog/commandhelp.go` | modified | The shared line() helper applied .Background(t.Background()) after the caller's style, overwriting the selected row's highlight and leaving foreground == background: the selected row rendered as an invisible blank line with no highlight bar. | line() only applies Width/MaxWidth; callers derive from a base style that already carries the panel background. The row-style decision is extracted as rowStyle(base, theme, selected) so the colour invariants can be asserted directly. |
| `internal/tui/login_overlay_test.go` | added | No test coverage for the overlay; the esc path needs a fully constructed appModel to reach through Update, which is why the bug shipped. | 8 tests: esc dismissal, consuming nothing but esc (the overlay is non-modal), uniform line width and terminal fit across six widths, whole-URL recoverability from the render, prose-not-URL shedding on short terminals, and hardWrap behaviour. |
| `internal/tui/components/dialog/commandhelp_test.go` | modified | TestEveryCommandIsReachable asserted strings.Contains(view, "/name"), which passes while a row is invisible — the text is present, only the colours hide it. | Adds TestSelectedRowIsVisible (foreground != background; selected background differs from unselected) and a render-level check that parses SGR background codes. |
| `docs/SCREENSHOTS.md, README.md, docs/screenshots/gallery/v0142-*.png` | added | No current screenshots; README did not surface /help. | Six 1600x900 unscaled screenshots with captions explaining each fix, every image linking to full resolution; README gains the /help section. |

## Subsystem Changes

**OTHER:** Establishes two TUI rules worth generalising. (1) A shared line/padding helper must not set colour — it silently overrides caller intent, which is exactly how the selected row became invisible. (2) Presence assertions are not visibility assertions: rendered output contains a row's text even when foreground equals background, so any test of a highlight must compare colours. Both are now recorded in CLAUDE.md.

**TELEMETRY:** No changes.

**STORAGE:** No changes. Config schema identical to v0.1.41.

## Test Coverage

- **Added:** internal/tui/login_overlay_test.go (8 cases) and two colour-asserting cases in commandhelp_test.go. First tests in package tui.
- **Removed:** none
- **Notes:** Non-vacuous throughout: restoring the unwrapped URL line yields 68 width-assertion failures; restoring the misplaced clear yields "esc was not handled while the overlay was up"; restoring the background clobber yields "the selected row's background (32;32;32) equals an unselected row's". The render-level colour test needed three attempts and each wrong version is documented in situ, because both failure modes are easy to reproduce: asserting the line carried SOME background escape passed against the bug (the buggy row inherits the panel background), and taking the FIRST background escape on the line failed against correct code (that is the box's leading padding, not the row). The correct invariant is the last background set before the command name. 16 packages passing, go vet clean. Interactive keystrokes remain untestable in this environment — verified environmental by confirming a minimal Bubble Tea program also receives no piped PTY input — and all three bugs in this release lived in that blind spot; two were found by inspecting screenshots.

The token is short-lived and spent, so this is documentation rather than a finding, but screenshots of in-progress auth flows should be reviewed before publication as a matter of course.
