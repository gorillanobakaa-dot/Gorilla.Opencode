# Gorilla OpenCode (Windows) 0.1.130 — The review tool comes back, patch porting arrives, and every turn gets cheaper to run

**Date:** 2026-09-03

---

## Why This Release Exists

This release began with a bug report that looked like the AI had broken. A user typed /review and the model answered 'I do not have access to a tool named review'. It was telling the truth. Months earlier, one press of the low-bandwidth button in /context had switched off seven tools at once, written that to disk, and nothing ever put them back. The connection recovered; the tools stayed off. Nothing anywhere said so. Fixing that properly meant fixing the button (it now has an undo), teaching every command to check its own tool is switched on before asking the AI to use it, and repairing a cost screen that had quietly started reporting the wrong number. Along the way the release grew: patch porting, eleven scientific databases, a politeness system that stops the program hammering free services, and an optional way to make every turn several thousand tokens cheaper.

## What You Will Notice

**the /review command**
- Before: The AI replied that it had no such tool, and nothing explained why.
- After:  It works. If it ever is switched off, the command says so and tells you which row in /context to turn on.
- Affects: everyone

**the low-bandwidth button in /context**
- Before: One press switched off seven tools permanently. There was no way back except resetting everything you had ever configured.
- After:  Press u to undo. It puts back exactly what the button took, and leaves alone anything you switched off yourself.
- Affects: everyone

**moving patches between versions of code**
- Before: You did it by hand, or asked the AI to read the diff and guess.
- After:  /port forward-ports, backports, rebases and refreshes patches, and tells you HOW each one landed - cleanly, by merge, or relocated by fuzz, which is the one that can be silently wrong.
- Affects: some users

**looking up scientific facts**
- Before: The AI could find papers about a protein but not the protein itself.
- After:  bio_lookup reads eleven databases directly - UniProt, Ensembl, PDB, AlphaFold, PubChem, ChEMBL, InterPro, ClinVar, openFDA, STRING, Reactome. Switched off by default; arm it in /context.
- Affects: some users

**how hard the program hits free services**
- Before: It fired requests as fast as it could and dealt with the refusals afterwards. On one recorded occasion a model, cornered by those refusals, invented a table of citations.
- After:  Every service gets a request budget and callers wait their turn. Published limits are used where a service states one.
- Affects: everyone

**what /context says a turn costs**
- Before: It added up every tool you had switched on, including ones the program no longer sends. The number could be several thousand tokens too high.
- After:  It reports what actually goes over the wire, shown as a range when tools are being held back.
- Affects: everyone

## Deliberately Not Done

- **Deferred tool loading is switched OFF when you install this.** — It saves about 2,900 tokens per session, which is real money on a metered connection. But on the small local model we tested it with, it silently cost the AI two of its four specialised tools - and when that happens the AI does not stop, it answers by hand and sounds confident. We want you to switch it on knowingly, not discover it failing quietly. Try it in /context and see how your own model copes.
- **One attempted improvement was removed after testing, instead of being shipped.** — We added a paragraph telling the AI to load a tool instead of doing the work by hand. It cost 63 tokens on every single turn and, measured across five runs, changed nothing at all. It came back out. A cost that buys nothing is a leak, and this program is used by people for whom that is not a rounding error.
- **Nothing here has been run on Linux.** — It compiles for Linux and passes the static checks, but it has never been executed there. This is the Windows build and it is labelled as such.
- **We did not upgrade to Anthropic's built-in version of deferred loading.** — It exists, but it needs a much newer library, and it only helps people on the newest paid models. Our version works on free-tier Gemini, free-tier ChatGPT, NVIDIA NIM and local models - which is where the people who need it actually are.

## Privacy & Security

No telemetry was added and none exists. The program still sends nothing anywhere except to the AI provider you configured. The eleven scientific databases are public and are queried without any API key - Gorilla sends none, and does not ask you for any. The new politeness system means the program now identifies itself when calling those public services, using a fixed contact string naming the project, which is what their fair-access policies ask for. Nothing about you is included. The code-review tools run entirely on your machine and nothing is uploaded.

**Before you start:**
- Windows 10 or 11
- About 60 MB of disk space
- Nothing else. The program carries its own tools inside it.

**Step 1:** Close Gorilla OpenCode if it is running.
✓ No Gorilla window open.

**Step 2:** Download gorilla-opencode.exe from the release page and put it somewhere you can find it, such as your Downloads folder.
✓ The file is on disk and is about 54 MB.

✓ It prints 'installed:' with a path, then 'Look for Gorilla OpenCode on your Desktop or in the Start menu.'


**To go back:** Run 'gorilla-opencode uninstall', then install your previous .exe the same way. Your conversations, settings and API keys are stored separately and are not touched by either step.

## If Something Goes Wrong

**The AI says it does not have a tool you know exists - review, web search, or research.**
Something switched it off. Usually the low-bandwidth preset in /context, which used to be one-way.
What to do: Open /context and look for the row. Press space to switch it on. If the low-bandwidth preset was what did it, press u to undo the whole thing at once.
Status: fixed in v0.1.130 - commands now refuse with an explanation instead of asking the AI to use a tool it has not got

**/review says the review did not run, and lists missing analysers.**
The review drives real analysis programs and they are not installed on this machine. This is deliberate: an empty result looks exactly like a clean report.
What to do: Read the list it prints. It names each missing tool and the command that installs it on Windows.
Status: working as intended

**You switched on deferred tool loading and the AI stopped using a specialised tool.**
With that setting on, the AI has to search for a tool before it can use one. Small models do not always realise they should.
What to do: Switch it back off in /context. Nothing else changes.
Status: known limitation, measured, documented - which is why it ships off

**A patch is reported as 'applied WITH FUZZ'.**
The patch did not fit where it said it would, so it was placed by searching for the surrounding lines. If those lines appear twice in the file, it can land in the wrong place and still look successful.
What to do: Read the diff before trusting it. The tool tells you exactly which parts were moved.
Status: working as intended - the warning is the feature

## Common Questions

**Q: Why did my review tool disappear in the first place?**
A: The low-bandwidth preset in /context switched it off along with six others, wrote that to disk, and had no undo. Your connection improved but the setting did not follow. That is fixed twice over: the preset is reversible now, and the /review command checks before it runs.

**Q: Should I turn on deferred tool loading?**
A: Try it, and watch what happens. It saves roughly 2,900 tokens a session, which matters if you are paying per token or living inside a free tier's daily limit. But on a small local model it cost us two of four specialised tools without saying so. If you use a larger model, it may well be worth it. It cannot cost you more than leaving it off - that is guaranteed and tested.

**Q: What does 'applied with fuzz' actually mean?**
A: The patch did not fit where it claimed to. The tool searched nearby for the surrounding lines and put it where they matched. Usually right; occasionally very wrong, if those lines appear more than once. That is why it is reported separately instead of being called success.

**Q: Is this the Linux version?**
A: No. This is Windows. It compiles for Linux and the tests pass in a static check, but it has never actually been run there and we will not claim otherwise.

**Q: Does the biology tool need an account or an API key?**
A: No. All eleven databases are public and Gorilla queries them without a key. Some offer higher limits if you register; Gorilla does not use that, and stays inside the free budget by pacing itself instead.

## Bottom Line

This release started as a bug fix and turned into the most heavily measured version of Gorilla so far. The immediate problem - a review tool that had silently vanished - is fixed at the root, and the mechanism that caused it can no longer do it again. On top of that you get patch porting, eleven scientific databases, and a program that is markedly more polite to the free services it depends on. The one genuinely new idea, deferred tool loading, ships switched off: it saves real money and it cost us two capabilities on a small model, and we are telling you that instead of letting you find out. Several things in here exist because a test contradicted what we expected, including one change that was written, measured, and removed for buying nothing. If you are on a metered connection or a free tier, the /context screen now tells you the truth about what a turn costs, which it had quietly stopped doing.
