# Gorilla OpenCode v0.1.133 — the Windows build catches up, and one part of it is an experiment

**Date:** 2026-09-03
**Previous Windows version:** v0.1.130
**Also released today:** v0.1.132, Linux only

---

## Why This Release Exists

Version 0.1.132 fixed several things you could see and touch, and then shipped
only for Linux. It carried a Debian package, an Arch package and a Linux
program, and no Windows program at all. Anyone on Windows arriving at the newest
release found three files they could not install.

So for most of a day the Windows version was three visible fixes behind, and
nothing on the page said so. This release is those fixes, compiled for Windows,
plus a change to the AI's instructions that is openly an experiment.

## What You Will Notice

**the command list, /help**
- Before: A narrow panel showing about a dozen of the thirty-one commands. If
  you did not already know the list scrolled, the bottom row looked like the end
  of what the program could do.
- After: Two columns across the whole window, with a count at the top. On an
  ordinary screen every command is visible at once.
- Affects: everyone, and especially anyone new

**the cost screen, /context**
- Before: Capped at a fixed size, so on a wide screen the column explaining what
  switching something off would cost you was cut off mid-sentence. That column is
  the one thing on that screen you need before deciding.
- After: It uses the whole window and finishes its sentences. The heading and
  footer stay put instead of scrolling away.
- Affects: everyone

**knowing you are in low-bandwidth mode**
- Before: Pressing `l` switched seven things off and said so once, in a message
  that faded. Six of the seven sat below the visible part of the list, so nothing
  on screen changed and it looked like a key that did nothing.
- After: A red line stays at the top for as long as the mode is on, saying how
  many things are off and which key puts them back.
- Affects: anyone on a slow or metered connection

**the AI is harder to catch lying to itself**
- Before: The AI was told to verify its work before reporting it done. It was not
  told *what to look at*, so it could run a build, read a success message that
  came from the wrong command, and report success honestly and wrongly.
- After: Two new rules. Check the actual file, not the status message. And if
  something expected is missing, say so rather than writing a placeholder so the
  task can continue.
- Affects: everyone. This program has printed "BUILD OK" over a failed build
  more than once.

**the AI keeps better notes about you**
- Before: Nothing stopped it recording its own guess as something you had said.
- After: Three rules. Open the file before claiming not to have the answer. Keep
  your words and its conclusions separate. One passing mention of something is
  not a preference.
- Affects: anyone who uses it across more than one session

**the AI stops folding under pressure**
- Before: If you said "that's wrong", it would often abandon a correct answer for
  a wrong one that sounded more agreeable.
- After: A rule to correct real errors and move on, without becoming steadily
  more apologetic each time it is pushed.
- Affects: everyone, and it costs you nothing

## The Experiment

**First, the unit everything below is priced in.** A **token** is roughly
three-quarters of a word. It is what AI services count and charge by, and what
your data allowance disappears in. Everything the AI has been told is re-sent
with every message you send, so a line added to its instructions is never a
one-off — it is a standing charge, on every message, for as long as it is
switched on. That is why each change here is priced rather than just listed.

There is a new switch in `/context` called **Scope restraint**. It is **on**,
and it costs **212 tokens on every message**.

It tells the AI to stay on the job you gave it:

- A file being nearby, already open, or mentioned by the one you asked about
  does not make it part of the task.
- "It would save time later" is not permission.
- Do not go reading through a whole folder tree nobody asked about.
- Move things to a clearly labelled holding place rather than deleting them.
- Assume the machine you actually have — its speed, screen and connection —
  rather than an imagined average one.

**Here is the honest part.** Nobody has tested whether any of that works. Not
once. We have no evidence that the AI reads around less with these lines than
without them — only a reasonable belief that it should.

They are on anyway, because a rule nobody ever runs can never be proven or
disproven, and leaving it switched off would have kept it a guess forever.

**If it goes wrong, it will go wrong by being too careful — not too reckless.**
Watch for the AI:

- asking permission for things it used to simply do,
- running commands one at a time that it used to send together, which makes it
  slower and costs you more,
- or saying it is stuck when it could have looked in the next folder along.

**Switching it off is one keypress.** Open `/context`, find *Scope restraint*,
press space. You get the 212 tokens back on every message from then on, and
nothing else changes.

## Deliberately Not Done

- **macOS** — Never built for, never run. Saying so is more useful than implying
  otherwise by silence.
- **Proving the new restraint rules actually work** — We have not done it. Not
  one test has shown that those five lines change how the AI behaves. They
  might make it tidier, they might make it timid, or they might do nothing at
  all while costing you 212 tokens on every message.

  They are switched on so that we can find out, on a version where that is
  printed on the box rather than discovered by you months later. If the AI
  starts asking permission for things it used to just get on with, that is
  these rules — open `/context`, find *Scope restraint*, press space.
- **A saving we found, tested, and could not make safe** — There is a switch
  called *Deferred tool loading*, and it is still off.

  What it is: the AI does not know its tools exist unless it is told, so a
  written description of every tool is sent with your message every single time
  you press enter. Those descriptions are most of what gets sent, and you pay
  for them whether the AI uses any of them or not. The switch holds the
  specialist ones back and sends a short index instead, so the AI can ask for
  the full description only when it wants one. That saves roughly **2,900
  tokens per conversation** — real money on a metered connection or a free
  daily limit.

  What went wrong: we ran it 26 times against a small AI on an ordinary laptop.
  Two of its four specialist tools were never reached, because the AI never
  thought to ask for them. Worse, it did not stop and say it was stuck. It
  answered from whatever it could read and sounded completely sure of itself.

  We know **why** — a small AI does not reliably work out that it should go
  looking for a tool before concluding it does not have one. We do **not** yet
  know how to make it reliably do that. A saving that sometimes removes an
  ability without telling you is not one we will switch on for everybody.

  If you use a larger AI it may work fine. Turn it on in `/context` and watch
  how yours copes. It cannot cost you more than leaving it off.

## Privacy & Security

No change. The program still contacts only the AI service you configure and the
specific sites you ask it to read. Nothing is collected, and there is no
telemetry of any kind.

## How to Install

**Before you start:**
- A 64-bit Windows machine
- About 55 MB of disk space
- No account and no card

**Step 1:** Close Gorilla OpenCode if it is open.
✓ No window titled Gorilla OpenCode is running.

**Step 2:** Download `gorilla-opencode.exe` from the release page.
✓ One file in your downloads folder.

**Step 3:** Check that what you downloaded is what was published.
```
certutil -hashfile gorilla-opencode.exe SHA256
```
✓ It prints `2513f4ccfd8c8143fc2523f3d35eddef067541291c65c5a0da0b0fac4d199eeb`.

**Step 4:** Install it. Open a terminal where you saved the file and run:
```
.\gorilla-opencode.exe install
```
✓ It reports where it copied itself and that it made Desktop and Start menu
shortcuts.

**Step 5:** Confirm the version.
```
gorilla-opencode --version
```
✓ v0.1.133

**To go back:** Run `gorilla-opencode uninstall`, then install your previous
`.exe` the same way. Your conversations, settings and keys are stored elsewhere
and neither step touches them.

## If Something Goes Wrong

**The AI keeps asking permission for things it used to do without asking.**
That is the new Scope restraint rules being too cautious, which is the failure
they were expected to have.
What to do: Open `/context`, find *Scope restraint*, press space.
Status: expected, and reversible in one keypress.

**The AI says it does not have a tool you know it has.**
Something switched it off, usually the low-bandwidth preset.
What to do: Open `/context` and press `u` to undo the preset.
Status: fixed in 0.1.130, and the red line added in this release makes it
visible when it happens.

**/review refuses to run and lists programs you do not have.**
Those analysers are separate programs. It refuses rather than returning an empty
result, because an empty result looks exactly like a clean report.
What to do: Read the list. It names each one and how to install it.
Status: working as intended.
