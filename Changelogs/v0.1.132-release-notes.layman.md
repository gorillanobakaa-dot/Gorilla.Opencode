# Gorilla OpenCode v0.1.132 — The Linux build, and the six things that only broke once somebody ran it

**Date:** 2026-09-03
**Previous version:** v0.1.130

---

## Why This Release Exists

Version 0.1.130 was the Windows build. It compiled for Linux and passed the automatic checks there, and that was the entire extent of the evidence, because nobody had ever run it. This release is that same work executed on Linux for the first time. The test suite failed in six places and not one of them was a fault in the program: every failure was a test assuming something that could only be true on Windows, and the program itself needed no changes at all. Three of those six were worse than an ordinary failure, because they had been passing for weeks while testing nothing at all. Then three more faults were found by photographing the running program, which no test had caught, and one of those was introduced during this very release while fixing something else.

## What You Will Notice

**the command list, /help**
- Before: A narrow panel in the middle of the screen showing about a dozen of the thirty-one commands, with nothing to say the rest existed. If you did not already know the list scrolled, the bottom row looked like the end of what the program could do.
- After:  It uses the whole window in two columns. On an ordinary screen every command is visible at once, and a line at the top counts them, so how much there is becomes something you read, not something you discover.
- Affects: everyone, and especially anyone new

**the cost screen, /context**
- Before: Capped at a fixed width, so on a wide screen it stopped short of the edge and the column explaining what switching a tool off would cost you was cut off mid-sentence. That column is the one thing on that screen you need before deciding.
- After:  Full width. The explanations finish their sentences.
- Affects: everyone

**knowing you are in low-bandwidth mode**
- Before: Pressing l switched seven things off and said so once, in a message that faded. Six of the seven sat below the visible part of the list, so nothing on screen changed and it looked exactly like a key that did nothing.
- After:  A red line stays at the top for as long as the mode is on, saying how many things are off and which key puts them back.
- Affects: anyone on a slow or metered connection

**copying the conversation, /copy**
- Before: It could not work on a fresh installation. Copying to the clipboard on Linux needs a small helper program, and the package never asked for one, so the command was dead on a newly set up machine.
- After:  The package asks for that helper, so /copy works after a normal install.
- Affects: everyone on Linux

**patch porting, /port**
- Before: Never run on Linux at all. It falls back to the system's own patch program in one case, and that program behaves differently on different systems, so this was the single genuine unknown in the whole port.
- After:  Tested against the Linux version and correct on all four of its behaviours. It still reports HOW each patch went on: cleanly, by merging, or by being relocated to fit.
- Affects: anyone maintaining patches

## Deliberately Not Done

- **macOS** — It has never been built for or run, and nothing here changes that. Saying so is more useful than implying otherwise by silence.
- **Making the token numbers exact** — They are estimates, about ten percent high, and the screen says so. They are good enough to choose what to switch off and not good enough to quote as a bill, and presenting a guess in the typography of a measurement would be the worse error.
- **Fixing deferred tool loading for small models** — One capability is still never reached by a very small model. It ships switched off. The cause is understood and the fix is not, and shipping a documented limitation beats shipping a guess.

## Privacy & Security

No change. The program still contacts only the AI service you configure and the specific sites you ask it to read. Nothing is collected, and there is no telemetry of any kind. This release adds a dependency on a small clipboard helper, which runs only when you use /copy and sends nothing anywhere.

## If Something Goes Wrong

**/copy says it could not reach the clipboard.**
Linux has no clipboard of its own for a terminal program; a small helper is needed. Before this release the package did not ask for one.
What to do: Install xclip, or wl-clipboard on a Wayland desktop with no XWayland. Installing this version with apt does it for you.
Status: fixed in 0.1.132

**The title at the top of /help or /context is missing.**
The panel was drawn as tall as the whole window, so the screen scrolled and what fell off the top was the heading.
What to do: None needed.
Status: fixed in 0.1.132

**A tool the AI needs seems to be missing.**
It is probably switched off in /context, possibly by the low-bandwidth button.
What to do: Open /context and look, or press u to undo the low-bandwidth preset. A red line now tells you when that preset is on.
Status: fixed in 0.1.130 and improved here

**The AI does not use the patch porting tool when asked about patches.**
With deferred tool loading switched on, a small model never searches for that particular tool.
What to do: Leave deferred tool loading off, which is how it ships.
Status: investigating

## Common Questions

**Q: Is this different software from the Windows 0.1.130 release?**
A: No. It is the same code, built for Linux and run there for the first time. The program needed no changes to work; what changed were tests that had assumed Windows, and three faults in how screens were drawn.

**Q: Six test failures sounds bad. Was the program broken?**
A: No, and that is the useful part. Every failure was a test making a Windows-only assumption. Three of them had been passing for weeks while testing nothing at all, which is worse than failing, because a test that cannot fail is not protecting anything.

**Q: Do I have to install anything else for /copy to work now?**
A: Not if you install with apt or pacman as described. Both will fetch the small clipboard helper for you. If you install by hand with dpkg it will not, which is why the instructions say apt.

**Q: Why is one of the fixes something you broke yourselves?**
A: Because it is true, and hiding it would make the release notes less useful. While widening one screen we made it exactly as tall as the terminal, which pushed its own heading off the top. It was found in a screenshot, not by a test, and there is now a test for it covering both screens.

## Bottom Line

This is the first time this code has actually run on Linux, and the honest headline is that the program was already correct: six test failures, no product defects. The value of running it was in what could not be learned any other way. Three of the failing tests had been passing while testing nothing, which is the kind of fault that hides indefinitely. Three more problems were found only by looking at photographs of the real screen, and one of those was introduced during this release while fixing something else. The screens people actually use are meaningfully better: the command list shows everything at once instead of a fifth of it, the cost screen finishes its sentences, low-bandwidth mode says it is on, and /copy works on a machine that was set up normally. Nothing here is verified on macOS, and the one known behavioural limitation, a small model never reaching one tool, ships switched off and is still open.
