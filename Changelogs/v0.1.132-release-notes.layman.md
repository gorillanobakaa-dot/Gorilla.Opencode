# Gorilla OpenCode 0.1.132 — the Linux build, and what running it for the first time found

**Date:** 2026-09-03

---

## Why This Release Exists

Version 0.1.130 was the Windows build. It compiled for Linux and passed the automatic checks there, and that was the whole of the evidence: nobody had ever actually run it. This release is that same work, executed on Linux for the first time, plus everything the first run turned up.

The test suite failed in six places. Not one of them was a fault in the program. Every single failure was a test making an assumption that could only be true on Windows, and the program itself needed no changes at all. That is a good outcome, but it is a thing you can only learn by running it, which is the entire point of doing so.

Three of those six were worse than an ordinary failure. They had been passing for weeks while testing nothing whatsoever.

## What You Will Notice

**The command list, /help**
- Before: A narrow panel in the middle of the screen showing about a dozen of the thirty-one commands, with nothing to indicate the rest existed. If you did not already know the list could be scrolled, the bottom row looked like the end of what the program could do.
- After: It uses the whole window in two columns. On an ordinary screen every command is visible at once with no scrolling, and a line at the top counts them, so how much there is becomes something you read rather than something you discover.
- Affects: everyone, and especially anyone new

**The cost screen, /context**
- Before: Capped at a fixed width, so on a wide screen it stopped well short of the edge and the column explaining what switching a tool off would actually cost you was cut short with a "...". That column is the one thing on that screen you need to read before deciding.
- After: Full width. The explanations finish their sentences.
- Affects: everyone

**Telling you when you are in low-bandwidth mode**
- Before: Pressing `l` in /context switched seven things off and said so once, in a message that then faded. Six of those seven were further down the list than the screen could show, so nothing you were looking at changed. It looked exactly like a key that did nothing.
- After: A red line stays at the top of the screen for as long as the mode is on, saying how many things are off and which key puts them back.
- Affects: anyone on a slow or metered connection

**Copying the conversation, /copy**
- Before: It could not work on a fresh installation. Copying to the clipboard on Linux needs a small helper program, and the package never said so, so the command failed on a machine that had just been set up. The program reported this correctly, but a correct error message is still a broken feature.
- After: The package now asks for that helper, so /copy works after a normal install.
- Affects: everyone on Linux

**Patch porting, /port**
- Before: Never run on Linux at all. It falls back to the system's own patch program in one case, and that program behaves differently on different systems, so this was the one genuine unknown in the whole port.
- After: Tested against the Linux version and correct on all four of its behaviours. It still tells you HOW each patch went on: cleanly, by merging, or by being relocated to fit. That last one can silently be wrong, so it is reported separately rather than called a success.
- Affects: anyone maintaining patches

## What Is Not Fixed

macOS has never been built for or run. Nothing here changes that.

The numbers shown on the /context screen are estimates. They are produced by measuring the size of a description and dividing by four, and against a real counter they run about ten percent high. They are accurate enough to choose what to switch off and not accurate enough to quote as a bill, and the screen says so itself rather than presenting a guess in the typography of a measurement.

The optional feature that withholds tool descriptions until the AI asks for them still fails for one specific capability when used with a very small model. That is unchanged, it ships switched off, and it remains the largest open question in this work.

## Honesty Notes

Two of the four pictures on the release page had to be taken three times, because the first attempts photographed screens that were still broken, and the second attempt is what found a fault nobody had noticed. The picture was the bug report.

One of the faults fixed here was introduced earlier in this same release, while fixing something else, and was found the same way.
