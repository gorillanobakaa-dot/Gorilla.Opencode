# Gorilla OpenCode (Windows) 0.1.130 — developer notes: deferred tool loading (opt-in, measured), patch porting, structured bio lookup, proactive rate limiting, and the loadout leak that silently disabled /review
**Date:** 2026-09-03

---

## Summary

Thirty-three commits over v0.1.120. The root cause that started it: ApplyLowBandwidthLoadout switched seven components off, persisted them, and had no inverse. A user's connection profile returned to unconstrained while tool.review, tool.websearch, tool.fetch, tool.research, tool.agent, tool.diagnostics and prompt.lsp stayed disabled indefinitely; the only symptom was the model reporting it had no such tool, which read as model failure. Three separate fixes: the preset now records what it actually changed and 'u' in /context restores exactly that (not ResetLoadout, which discards unrelated configuration); commands check their component is armed before dispatching, a guard /osint already had and /review and /port did not; and LoadoutTokenRange replaces LoadoutActiveTokens' single figure, because with deferred loading an enabled component is not necessarily a sent one. New surfaces: internal/politehttp (per-host request budgets as a RoundTripper above every provider), internal/llm/tools/toolsearch.go (client-side deferred loading), biodata.go (11 keyless scientific databases), patchport.go plus the vendored patch_port.py (forward-port, backport, rebase, refresh, port-series). Deferred loading ships OFF after 26 measured model trials.

## Known Alternatives Considered

Anthropic's server-side defer_loading was evaluated and rejected for now: it requires anthropic-sdk-go v1.69 against the v1.4.0 this repo pins, and it reaches only the newest paid models. From the commit message: 'the native paths exist precisely where the users who need this most are not: newest models, paid APIs. The client-side filter sits above every provider and is the only mechanism that reaches free-tier Gemini, free-tier ChatGPT, NIM and OpenRouter.' OpenAI has tool_search with defer_loading but gpt-5.4 and later only; Gemini has no equivalent and its own guidance is 'keep active set to 10-20 tools'; NVIDIA NIM has neither deferral nor prompt caching. For bioRxiv, its own API was rejected because it offers only date-range listing and DOI lookup with no keyword search: 'a search built on it would have to pull whole days of postings and filter them here, which is slow, unbounded, and silently incomplete'. Europe PMC's SRC:PPR index is used instead. For the low-bandwidth undo, ResetLoadout was rejected because 'that returns EVERY component to its shipped default, discarding whatever else the user had configured'. For the tool-name to loadout-row mapping, a naming rule was rejected and an explicit table used: web_fetch maps to tool.fetch and web_search to tool.websearch, so a rule 'would have silently failed on exactly those two and under-reported the saving'.

## Architecture Impact

Four invariants added, all test-enforced. (1) tool_search is never deferrable - deferring the mechanism that undefers everything leaves no way back, matching the Claude API's own 400 on that configuration. (2) Deferral can never cost more than not deferring: once the remaining withheld schema is worth less than the overhead (tool_search schema plus catalogue index), the mechanism switches itself off for that session and drops tool_search. Verified at every point along the discovery path, not only at the ends. (3) Discovered tools are appended, never inserted, and the Anthropic cache breakpoint moved from the last tool to the last STABLE tool - tool definitions sit in the cached prefix, so mid-array insertion would invalidate the cache on every discovery. (4) Everyday tools (bash, edit, view, write, find, patch) are never deferrable, so a model that never searches can still complete a task. Separately, //go:embed all:toolkit became //go:embed toolkit: the all: prefix also embedded __pycache__, and because Version() hashes everything embedded, the binary's identity depended on whether anyone had run the Python tests before building.

## Subsystem Changes

**NETWORK:** internal/politehttp wraps newSafeClient's transport, which covers web_fetch and every scholarly backend in web_search at once. SearXNG is deliberately excluded: it is the operator's own box and throttling it only slows them. NIM offers no prompt caching at all, so there is nothing there to invalidate.

**TUI:** /port added with argument parsing in portargs.go; /review help and /port help open the reference focused on that command via FocusCommand, which matches the command NAME instead of reusing the search filter - filtering on 'port' selected /sessions, whose detail mentions exporting. The /context cost line leads with the range so truncation cannot hide the ceiling.

**OTHER:** The vendored code-review toolkit was replaced with the owner's real one and extended: platform-aware install routes (winget/scoop/choco alongside apt/dnf/pacman/brew), a doctor reporting three states instead of two, uniformity warnings, and patch_port.py. package.py builds portable per-platform bundles - zip for Windows, tar.gz for Linux, because zip cannot carry the executable bit and a CRLF shell script fails with 'bad interpreter: /bin/sh^M'.

## Test Coverage

- **Added:** internal/politehttp (8 tests including parallel serialisation and Retry-After); toolsearch (discovery, per-session isolation, cache-prefix stability, the rescue path, and a structural check that three-way is attempted before fuzz); biodata (offline projection tests plus a GORILLA_LIVE_SEARCH-gated run over all 11 databases); deferred-cost tests that print the worst case and fail if the overhead ever exceeds a third of the saving; TestDeferralNeverCostsMoreThanNotDeferring, which walks the entire discovery path dearest-first; loadout undo tests covering the two ways an undo goes silently wrong (resurrecting a user's own choice, and a second no-op trim destroying a pending undo); portargs tests; a reachability test that every component renders in /context with a name, tradeoff and cost; test_patch_port.py, which builds real git repositories.
- **Removed:** None. Two tests were rewritten, not deleted: TestABareWordIsAPathEvenWhenItLooksLikeAFlagName became TestABareWordIsAPathWhenThatPathExists, keeping the original guarantee as one half; and TestAMissListsWhatCanBeLoaded now asserts what the message must achieve, not a literal string it happened to contain.
- **Notes:** Two guards were mutation-tested after being written - the earlier versions passed against deliberately broken code. TestLowBandwidthPresetSavingIsMeasured had to be repaired after LoadoutActiveTokens changed meaning: it was reading the up-front figure, which already excluded the components the preset then switches off, so the preset appeared to have collapsed from 43% to 19%. ## Security Posture

No CVEs addressed and no new attack surface. The SSRF guards in fetch.go are unchanged; politehttp decides only WHEN a request leaves, never where it goes, and the redirect test was updated to unwrap the new transport so it still asserts the redirect guard instead of accidentally testing the rate limiter. No new HTTP client was introduced, so the egress inventory in egress_inventory_test.go is unchanged. bio_lookup queries public endpoints with no credentials and Gorilla neither sends nor requests an API key. The politeness contact string identifies the project only and carries nothing about the user. Toolkit bundles are built with uid/gid normalised to root so a tarball does not leak the building machine's username.

## Known Issues

**[high]** The model reports that a tool does not exist - review, web_search, research.
- Cause: The component is disabled in loadout.json, most often by ApplyLowBandwidthLoadout, which was one-way before this release.
- Remedy: Press u in /context to undo the preset, or space on the individual row. From v0.1.130 the command refuses with an explanation instead of dispatching a prompt for a tool the agent has not got.

**[medium]** With deferred loading on, a specialised tool is never used and the model answers from file contents instead. (deferred to unresolved - the next attempt should be structural, and the 0/5 result may be a model-size finding, not a design one)
- Cause: The model never enters the search path. Measured on Gemma 4 E2B: patch_port 0/5 across two builds, with find and view used instead. Retrieval is not the cause - offline scoring returns patch_port as the top hit for every natural phrasing of the request.
- Remedy: Switch deferred loading off in /context, or use a larger model. Adding catalogue prose was tried, cost 63 tokens per turn, and measured 0/2 before and 0/3 after.

**[medium]** A patch reports applied-with-fuzz.
- Cause: git apply could not place the hunk (commonly no pre-image blob for a patch carried between unrelated repositories) so GNU patch located the context by searching.
- Remedy: Read the diff. Fuzz is the one outcome that can place a hunk in the wrong location and still exit 0; the offsets used are reported, not swallowed.

**[low]** TestListSubAgentsOrdered fails on Windows and passes on CI.
- Cause: Fixed in this release. sort.Slice was unstable and StartedAt.Before is false in both directions for same-tick registrations, so ordering fell out of Go's randomised map iteration. The Windows clock is coarse enough that same-tick registration is routine.
- Remedy: Already fixed - sort.SliceStable with the registration sequence as tiebreak.

**[low]** The smoke test hangs.
- Cause: Fixed. Its checks concern how the program fails, but with a local endpoint reachable, -p hi is a real inference request and was unbounded.
- Remedy: Already fixed - every invocation is time-bounded and the suite runs in about a second.
