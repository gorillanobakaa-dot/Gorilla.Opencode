# Gorilla OpenCode v0.1.134 — the AI could not read the file with the answer in it

**Date:** 2026-09-05
**Previous version:** v0.1.133

---

## Why This Release Exists

Yesterday's release added five rules telling the AI to stay on the job it was
given, and said openly on the release page that nobody had measured them.

Today they were measured. Two were broken.

## What You Will Notice

**fixing a build error**
- Before: You say "fix the error in parser.c". The compiler says a value is
  undefined. That value lives in a header file that parser.c uses. The new rule
  said that header was not part of your task, so the AI could not open the one
  file containing the answer. It would report the problem as unverified rather
  than just looking.
- After: Looking is allowed. Changing still needs permission. Reading along a
  chain of files to find the fault is treated as part of the job, because it is.
- Affects: anyone using it on real code, which is what it is for

**asking it to delete something**
- Before: One rule said do not delete, move it to a clearly labelled holding
  folder instead. An older and stronger rule said do not create files nobody
  asked for. So it could not delete, and could not do the approved alternative
  either. It stalled.
- After: The holding folder counts as part of the deletion you asked for.
- Affects: anyone asking it to clean anything up

## How This Was Found

Forty-four AI agents examined the rulebook from three directions at once, then ten
more tried to prove them wrong.

Three separate groups landed on the same rule without being told to look for it.
That agreement is why these two were fixed and the other three left alone.

## Deliberately Not Done

- **Fixing the other three restraint rules.** They are unmeasured and still
  switched on. One drew twenty-six findings in the audit, barely any checked. One
  keypress removes all five: `/context`, find *Scope restraint*, press space.
- **A Linux build.** The last one is 0.1.132 and does not have this fix.
- **macOS.** Never built for, never run.

## The Honest Part

The worry that started this was that the rulebook had become lopsided, roughly
fifteen stop rules against six go rules. **That count was wrong.** Done properly it
is twenty against eighteen. Balanced. The real problem was two sentences, not a
ratio.

Every one of the ten agents asked to demolish a finding succeeded. They were told
to assume findings are wrong unless proven, so that is partly built into the
method, and only about a tenth of the serious findings were checked before the
budget ran out.

Eight of thirteen test scenarios changed behaviour with no harm at all.

And no agent ran a real task. These are predictions with reasoning attached, not
measurements.

## How to Install

**Step 1:** Close Gorilla OpenCode if it is open.
✓ No window titled Gorilla OpenCode is running.

**Step 2:** Download `gorilla-opencode.exe` from the release page.

**Step 3:** Check that what you downloaded is what was published.
```
certutil -hashfile gorilla-opencode.exe SHA256
```
✓ It prints 9c3bd04f8ea8c06c8de1ec781be2e7d70bca94939bfd1ed970e0045dac3b4840

**Step 4:** Install it. In a terminal where you saved the file:
```
.\gorilla-opencode.exe install
```
✓ It reports where it copied itself and the shortcuts it made.

**Step 5:** Confirm the version.
```
gorilla-opencode --version
```
✓ v0.1.134

**To go back:** run `gorilla-opencode uninstall`, then install your previous file
the same way. Your conversations, settings and keys are stored separately and
neither step touches them.

## If Something Goes Wrong

**The AI keeps asking permission for things it used to just do.**
That is the three remaining restraint rules being too cautious.
What to do: `/context`, find *Scope restraint*, press space.
Status: expected, and reversible in one keypress.

**The AI says a tool does not exist.**
Something switched it off, usually the low-bandwidth preset.
What to do: `/context`, press `u` to undo the preset.
Status: fixed in 0.1.130.
