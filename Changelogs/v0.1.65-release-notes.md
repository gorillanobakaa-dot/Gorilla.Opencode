# Gorilla OpenCode v0.1.65 — Claude, GPT-OSS and Gemini for free, through your own Google account

*Track 1 of 2 — written for anyone. The developer track follows below.*

## Why This Release Exists

Two things happened, days apart, and this release answers both.

**First, the free tier stopped working.** If you signed in with Google to use the
free Gemini models, you started getting an "Internal error" and nothing came back.
Nothing in this program broke. Google quietly changed the rules on their side: the
free "Code Assist" tier is no longer offered to ordinary programs — only to Google's
own new app, called **Antigravity**. When this program asked for the free tier,
Google's answer was, in plain terms, *"that door is closed; use Antigravity now."*

**Second — and this is the good part — that same Antigravity door is one every
Gmail account already has a key to.** Google gives every personal Google account a
generous free allowance in Antigravity that includes not just Gemini, but
**Anthropic's Claude (Sonnet and Opus 4.6) and OpenAI's GPT-OSS** as well. It is
your allowance. Google grants it to you for free the moment you have a Gmail address.
Until now the only way to spend it was Google's own Antigravity command-line tool.

This release does two things about that. It gets the **free Gemini tier working
again** by having the program introduce itself the way Google now expects. And it
adds a brand-new way to sign in — **"Antigravity free tier"** — that unlocks
**Claude, GPT-OSS and Gemini, at no cost, using the allowance already attached to
your own Google account.**

## What You'll Actually Notice

**A provider menu every time you start the program.** When you open Gorilla OpenCode
— by typing it, or by clicking its icon — you now see a list of every way to connect,
with the cursor already sitting on the one you used last:

```
Choose a provider for this session
Enter continues with the highlighted one.

> Antigravity free tier - Claude + GPT-OSS + Gemini (Gmail sign-in)   (current)
  Google - Code Assist free tier (Gemini only, Gmail sign-in, no key)
  NVIDIA NIM (free API key)                                           (ready)
  Local Ollama (no key)
  Anthropic (Claude) - API key
  ...
```

If you are not changing anything, press **Enter** and you carry on exactly as before
— one keystroke. If you fancy a different model today, pick another row. Some days
you want Claude; some days a local model with no internet; some days a fast free
one. You no longer have to edit any settings files to switch. **Esc** keeps your
current setup and continues; **Ctrl+C** quits.

**A new top choice: "Antigravity free tier".** Pick it, a browser window opens, you
approve with your Google account, and that is the whole setup. Afterwards, open the
model list (`/model`) and you will see **Claude Sonnet 4.6**, **Claude Opus 4.6
(Thinking)**, **GPT-OSS 120B** and **Gemini** — all free, all drawing on your own
Google allowance.

**A running total of what you have left.** Type **`/usage`** at any time and a line
appears showing how much of your weekly free allowance remains:

```
Antigravity weekly quota — Gemini Models: 29% (resets in 6d) · Claude and GPT models: 87%
```

The same line also appears **on its own when you start a session**, so you always
know where you stand before you begin. (It stays quiet for anyone not using
Antigravity — you will never see it unless it applies to you.)

## The One Thing You Should Understand Before Relying On It

The Antigravity sign-in is **unofficial**. It works by having Gorilla OpenCode speak
to Google using the same identity Google's own Antigravity tool uses — which is
allowed to reach *your* free allowance. The allowance is genuinely yours. But because
Google does not publish this as a public service, **Google could change something on
their side and break it at any time, without warning.** If that happens, the button
will simply stop working until the program is updated to match.

Everything else in this release does not depend on that: the free **Gemini** tier fix
uses Google's officially-supported login and is not at that risk.

## Decisions & Why

**The provider menu appears on every launch, not just the first time.** People change
their minds daily about which model they want, and the people who start this program
by clicking its icon have no other way to switch — they cannot type a hidden command.
Making the choice a one-keystroke question on every launch is the only route that
reaches everyone. The cost — one press of Enter for people not changing anything — is
deliberately tiny.

**When you pick Antigravity, your day-to-day model becomes Claude, but the little
background jobs use Gemini.** The program quietly names files and summarises history
for you as you work. Those small jobs are set to run on Gemini, which has a
*separate* weekly allowance from Claude and GPT. That way the housekeeping never eats
into the Claude/GPT allowance you actually care about.

**Your Antigravity sign-in is kept completely separate from your Gemini sign-in.**
They live in two different files. Signing into one never disturbs the other, so you
can keep both and switch between them freely.

**API keys are never shown on screen.** When you paste a key into the menu, it appears
as dots with a length count (`•••••••• (42 chars)`), never as text — a key printed on
screen would sit in your terminal's history where anyone could scroll back to it.

## Also In This Release (from an earlier work session)

A **DeepSeek** provider was added in a prior development session and is included here.
It lets you connect DeepSeek's models with a DeepSeek API key. It was not written as
part of this release's work, so it is noted here for completeness rather than
documented in depth.

## Deliberately Not Done

- **No official blessing for the Antigravity route.** This is interoperability with
  your own account, not a partnership. It is documented plainly as unofficial so no
  one relies on it as if it were guaranteed.
- **No `/usage` history or graphs.** The quota is shown as one honest line, not a
  dashboard. A single number you can trust beats a chart you have to interpret.
- **The full Antigravity model catalogue is trimmed to five.** Google's tool lists
  many effort-level variants; this ships the ones most people want (Claude Sonnet,
  Claude Opus Thinking, GPT-OSS, and two Geminis) rather than a wall of near-
  duplicates.

## Privacy & Security

Your Google sign-in happens in your own browser, directly with Google — this program
never sees your password. The resulting token is stored on your own machine, readable
only by you (file permissions `0600`), exactly like the existing Gemini login.
No telemetry, no new third parties: the only new network calls go to Google's own
servers, the same ones Google's Antigravity tool talks to. Your prompts on the free
tier are subject to Google's free-tier data terms, shown to you on the consent screen
— read them if that matters to you.

## Risks, Backup & Recovery

The risky part is isolated: only the Antigravity provider depends on the unofficial
route, and if Google changes something, only that provider stops — everything else
keeps working. Your sessions, settings and other keys are untouched by this upgrade.
If you want to step back, the previous package (v0.1.64) stays on the releases page
and installs over this one with `sudo dpkg -i`.

## How To Install

```sh
sha256sum -c checksums.txt
sudo dpkg -i gorilla-opencode_0.1.65_amd64.deb
gorilla-opencode --version && dpkg -l gorilla-opencode | tail -1
```

Both must say `0.1.65`. Quit any running copy first.

## Common Questions

**Is using my Antigravity allowance this way against the rules?** The allowance is
granted to your Google account for free; you are spending your own. What is unofficial
is *reaching it from a program other than Google's*. We can't promise Google won't
object or change it — that is the honest risk above.

**Will this cost me money?** No. Both free routes (Antigravity and the Gemini-only
Code Assist tier) cost nothing. The paid providers (Anthropic key, OpenAI key, etc.)
are still there if you want them, clearly labelled.

**What happens when I run out of weekly quota?** The model politely refuses until the
weekly reset (the `/usage` line tells you when that is). Claude/GPT and Gemini have
separate allowances, so running one dry does not touch the other. Switch models from
the menu or `/model` in the meantime.

**Do I have to use the menu every time?** You have to press one key — Enter — to
continue with what you had. That is the whole cost of always having the choice in
front of you.

## Bottom Line

The free Gemini tier works again, and a new sign-in unlocks Claude, GPT-OSS and
Gemini for free through the allowance your Google account already has. Pick your
provider on every launch with one keystroke, and check what you have left with
`/usage`. The Claude/GPT route is unofficial and could be changed by Google — that is
stated plainly and kept isolated so nothing else depends on it.

# v0.1.65 — Antigravity provider, every-launch provider portal, and the free-tier User-Agent fix

*Track 2 of 2 — for developers.*

## Architecture & Footprint

Four bodies of work, all measured before they were claimed:

1. **Free-tier restoration** — a two-line User-Agent change, root-caused live.
2. **Every-launch provider portal** — a new Bubble Tea startup screen plus its
   config-aware apply layer.
3. **Antigravity provider** — a new OAuth identity and a new transport, ~90% shared
   with the existing Code Assist client.
4. **`/usage`** — a quota fetch surfaced on demand and at session start.

New files: `internal/auth/antigravity_oauth.go`, `internal/llm/provider/antigravity.go`,
`internal/llm/models/antigravity.go`, `internal/tui/startup/provider.go`,
`cmd/provider_portal.go`, and four test files. Modified: `cmd/root.go`,
`cmd/launch.go`, `internal/auth/gemini_oauth.go`,
`internal/llm/provider/code_assist.go`, `internal/llm/provider/provider.go`,
`internal/config/config.go`, `internal/tui/components/dialog/models.go`,
`internal/tui/tui.go`. Full suite passes; `go vet` and `gofmt` clean.

(A pre-existing DeepSeek provider — `internal/llm/models/deepseek.go` plus edits to
`openrouter.go`/`models.go`, added in a prior session — rides along in this tag by
the maintainer's decision. It is not part of this release's work and is not analysed
here.)

## 1. The free-tier User-Agent fix — how it was root-caused

Symptom: after a successful Google login, `generateContent` returned HTTP 500 and
the onboarding reported a **blank project** at `standard-tier`. The instinct was to
blame the generation call. Measurement said otherwise.

A raw `loadCodeAssist` against the live `cloudcode-pa` endpoint, with a real token,
returned this:

```json
"ineligibleTiers": [{
  "reasonCode": "UNSUPPORTED_CLIENT",
  "reasonMessage": "This client is no longer supported ... migrate to the Antigravity suite",
  "tierId": "free-tier"
}]
```

Only `standard-tier` (which requires a user-supplied GCP project) was allowed — hence
the blank project and the 500. Google had discontinued the free tier for non-
Antigravity clients. Re-issuing the *same* call with a `User-Agent` whose product
token is `antigravity` flipped `allowedTiers` back to `["free-tier", "standard-tier"]`
with `ineligibleTiers: []`, and `onboardUser` then provisioned a managed project.

The gate was isolated by bisection: the User-Agent header alone controls it (the
`x-goog-api-client` `gd/` token an earlier draft proposed does nothing), and it must
be sent on **onboarding only** — `generateContent` is *rejected* with 403 under the
Antigravity UA and serves normally under the default one once a project exists. So
`auth.CodeAssistUserAgent` is set on `callCodeAssist` (loadCodeAssist/onboardUser) in
`gemini_oauth.go` and deliberately **not** on the generation path in `code_assist.go`.
Both call sites carry a `GORILLA OVERRIDE` explaining the asymmetry, because it is
exactly the kind of thing a future reader would "clean up" into a bug.

## 2. The every-launch provider portal

`internal/tui/startup/provider.go` is a dependency-light Bubble Tea model in the same
mould as the workspace and extras screens (it cannot import `config`; `cmd` builds the
rows, it renders, `cmd` applies). It honours the frame-width invariant: every line
goes through the package's `wrapTo`/`clip`, only the selected row's description is
drawn (so the frame never grows taller than a small terminal), and secret input is
rendered as bullets with a length counter — a pasted key never reaches the screen.
`internal/tui/startup/provider_test.go` asserts, headlessly, that no rendered line
exceeds the terminal at 24/40/80/120 columns *with every row selected*, that a secret
is never echoed, and the Enter/Esc/`r` semantics.

`cmd/provider_portal.go` is the config-aware half: it builds rows from the loaded
config (which providers already have credentials), applies a choice to real setters
(`UpsertProviderKey`, `UpsertLocalEndpoint`, `UpdateAgentModel`), and loops on failure
so a bad key returns to the menu instead of aborting the launch. `cmd/root.go` invokes
it after `config.Load` and before the existing "no provider" fatal check — so choosing
a provider there is what satisfies that check. `cmd/launch.go`'s old first-run "edit
the env file and relaunch" dead-end is replaced by the portal. A guard test,
`TestEveryPortalRowIsHandled`, fails if a row is ever presented that `applyPortalChoice`
does not handle.

## 3. The Antigravity provider

**Reconnaissance.** The protocol was captured, not guessed, from the installed
Antigravity CLI (`agy` 1.1.10) via a local mitmproxy (Go honours `HTTPS_PROXY` +
`SSL_CERT_FILE`; the client does not pin certificates). A forced token refresh
yielded the installed-app OAuth `client_id`/`client_secret` and the exact scope set;
a driven generation yielded the endpoint, headers and envelope.

**OAuth** (`internal/auth/antigravity_oauth.go`) mirrors the proven Gemini loopback
flow, reusing its shared helpers, against Antigravity's client id and scopes
(`cloud-platform`, `userinfo.*`, `experimentsandconfigs`, `cclog`, `openid`).
Credentials live in a separate `antigravity-oauth.json` (0600). `SetupProject`
discovers the managed free-tier project via `loadCodeAssist`; `Ensure` refreshes.

**Transport** (`internal/llm/provider/antigravity.go`) targets
`daily-cloudcode-pa.googleapis.com/v1internal` and reuses the Code Assist client's
conversion, tool-conversion, part-collection and streamed-response parsing verbatim
(`convertMessages` was extracted to a free function `caConvertMessages` for this).
It differs only where the capture proved it must: the generation call **does** carry
the Antigravity User-Agent (opposite of the Gemini path); the envelope adds three
top-level fields (`requestId`, `userAgent:"antigravity"`, `requestType:"agent"`) added
to `caEnvelope` as `omitempty` so the Gemini path is unaffected; and the model is a
plain per-request name (`claude-sonnet-4-6`) — model selection is **not** the stateful
`setUserSettings` dance the client's UI narrates into the prompt, which was the key
finding that kept this a clean transport rather than a session-state machine.

**Registration** (`internal/llm/models/antigravity.go`) exposes five models under
`ProviderAntigravity` at cost 0. The provider is enabled in `config.go` when its
credential file exists (same pattern as the Gemini-OAuth provider), and
`providerDisplayName` labels it in the picker.

## 4. `/usage`

`AntigravityCreds.RetrieveQuota`/`QuotaSummaryLine` call `retrieveUserQuotaSummary`
and format a single status line. A pure `formatQuotaLine(*QuotaSummary, now)` is split
out and tested against the *captured* wire body, so a Google-side shape change fails a
test rather than silently blanking the view. The `/usage` command and the
session-start `Init()` hook both call the one shared function; the startup hook returns
a nil message when not signed in to Antigravity, so it is invisible to everyone else
and never blocks startup (it runs in the Cmd goroutine).

## Test Coverage & What Was Actually Exercised

- **Free-tier fix:** proven end-to-end against the live endpoint — `loadCodeAssist`
  eligibility flip, `onboardUser` project provisioning, and the free-tier-with-project
  onboard shape that the client sends.
- **Antigravity transport:** proven end-to-end through gorilla's own code, not curl —
  a guarded `TestAntigravityLive` (`AG_LIVE=1`) drove `buildEnvelope → post → SSE
  parse` against the live backend and Claude replied `PONG` (`modelVersion:
  claude-sonnet-4-6`). `TestAntigravityEnvelopeShape` asserts the serialized envelope
  carries the required fields and that the Gemini path does not gain them.
- **`/usage`:** the wire shape and formatting are unit-tested against the captured
  body; the live endpoint was confirmed returning current numbers.
- **Portal:** headless width/secret/semantics tests as above.

**Not exercised — stated plainly:** the *interactive browser consent* step of the
Antigravity login. An agent shell cannot drive a browser. The flow is a line-for-line
mirror of the working Gemini login using the same helpers, and every non-interactive
link around it (token refresh, project discovery, generation, quota) is proven, but
the consent round-trip itself must be confirmed by a human clicking through it once.

## Security Posture

One new installed-app OAuth `client_id`/`client_secret` pair is embedded in the
binary — the same category of value the repository already embeds for the Gemini CLI
client, and itself extractable from the freely-distributed `agy` binary with
`strings`. Tokens are user-scoped, stored `0600`, refreshed via Google's standard
endpoint. Diagnostic output masks credentials throughout. The new network egress is
to Google's `daily-cloudcode-pa` and `oauth2.googleapis.com` only.

## The Honest Risk

The Antigravity route depends on undocumented, server-controlled behaviour: the
client-identity gate, the request envelope, cert non-pinning, and token refresh. Any
of these can change on Google's side and break the provider silently. This is the same
class of fragility the existing "login with Google" feature already accepts, confined
here to one provider. It is documented in every new file and in the project's memory
so a future session re-derives it in minutes rather than hours.

## Deployment & Verification

Same protocol: tag at `main`, build stamped with
`-ldflags -X .../version.Version=v0.1.65`, package, then extract the `.deb` and confirm
the **inner binary** hash matches the source build and that this release's notes are
present in the package. Publish, confirm `isDraft` is false, download the artifacts
back, verify checksums, and install from the downloaded package with `dpkg -i`.
