# v0.1.111 - the quota meter restored and locked, a decompression bomb closed, and a Python audit

> Session record generated 2026-08-20

---

## Problem Being Solved

Three unrelated defects, two of them introduced by earlier "helpful" passes rather than by new work.

1. Commit `5e4cd97` (2026-08-19) was an ASCII sweep across 81 files, 657 insertions, matching on "looks like a box character". It replaced `U+2588`/`U+2591` in `internal/tui/quota_panel.go` with `#`/`.`, destroying the quota meter's body while leaving the per-cell gradient maths intact and therefore invisible. The originating request had concerned misaligned lines in the coder prompt. The sweep also rewrote arrows inside code comments, which no terminal renders.

2. `internal/llm/tools/pfind.py` `_read_lines()` under `--search-zip` decompressed archive members into a list with no limit. The existing `--max-filesize` guard checks `os.lstat(fp).st_size` - the *compressed* size - so it does not apply.

3. Commit `e4e744f` (v0.1.90) deleted six `v0190-osint-*.png` from the gallery while adding eight unrelated captures in the same commit. `docs/SCREENSHOTS.md` still referenced four of the six.

## Approach Taken

**Meter.** Restored the glyphs only; `quotaHexColor` and `barCellColor` were never modified and still map `1.0 -> #00FF00`, `0.5 -> #FFFF00`, `0.0 -> #FF0000` per cell. Verified against `v0.1.80:internal/tui/quota_panel.go`: `quotaBar` at HEAD is behaviourally identical to the pre-sweep version.

The `styles/ascii.go` rule exists because ambiguous-width characters make lipgloss mis-measure and **wrap** a frame, surfacing as unexplained height elsewhere. That hazard is real for chrome that wraps content. This panel prints to scrollback via `tea.Println`, never into the one-row inline frame, and accounts for its own chrome width. Worst case on a CJK terminal is one wrapped line that scrolls away. Separately measured: `U+2591` is East Asian **Neutral** and carried no width risk at any point.

**Bomb.** A shared byte budget across the whole archive, charged on bytes actually read:

```python
MAX_DECOMPRESSED_BYTES = 256 * 1024 * 1024
class _Budget:
    def offer(self, n):   # how much MAY be read - does not charge
    def spend(self, n):   # charge for bytes that actually arrived
```

`_read_capped` bills raw bytes; `_text_lines_capped` bills `len(block.encode("utf-8", "ignore"))`, so both paths remain byte budgets rather than one being a character budget. `PFIND_MAX_DECOMPRESSED_MB` overrides; `0` disables.

**Locks.** `internal/tui/quota_locked_test.go` - the codebase equivalent of `chattr +i`.

## Before

`quotaBar` rendered `#` and `.`. `_read_lines` had no cap. Four Python files used the open-and-immediately-consume idiom. Six gallery PNGs absent from the working tree. `__pycache__/` and `*.pyc` unignored.

## After

`quotaBar` renders `█`/`░`. `pfind.py` carries a shared decompression budget with a loud, accurate truncation notice. All handles use `with`. All six PNGs restored. `.gitignore` covers compiled bytecode.

## Known Alternatives

**Per-member cap instead of shared:** rejected. It stops one huge member and does nothing about ten thousand small ones - the 2000-member tar is the counterexample.

**Silent truncation:** rejected. It would make "no matches" and "I stopped reading" indistinguishable.

**Blanket `timeout=` on all six remaining `subprocess.run` calls:** rejected, and this is the same failure class as the ASCII sweep - right-looking, applied by pattern, wrong where it matters. Decided per call instead:

| Call | Decision |
|---|---|
| `release_pipeline.py:751` runs a just-built binary | 60s - a broken build waiting on stdin would hang the release forever |
| `release_pipeline.py:745` `dpkg-deb -x` | 180s, local extraction |
| `release_pipeline.py:607` version probe | 60s, local |
| `test_dual_track_roundtrip.py:37` | 300s, local, no network |
| `release_pipeline.py:212` `run_cmd()` | **optional parameter, default none** - it runs `git push` and `gh release upload` of a 20 MB asset, which on a single-digit-KB/s link legitimately takes many minutes |
| `setup-lsps.py:112` package manager under sudo | **none** - sudo may block on a password prompt (a human, not a hang), and killing apt or dpkg mid-transaction breaks the package database |

## Reachability, stated so this is not mistaken for an emergency

`search_zip` defaults to `False` and `internal/llm/tools/find.go` never exposes it. The model cannot reach the decompression path. Only a human invoking `pfind.py` directly with `--search-zip` could. Fixed regardless, because the standalone copy in `Scripts.For.Work` is precisely that human's tool and had the identical hole. All three `pfind.py` copies re-synced and hash-verified identical (`87950741cf46d247`): repo, standalone, and the installed `/usr/share` copy.

## Two bugs in the fix, both caught by testing rather than reading

- The budget charged on **offer** rather than **spend**, so a 1 MB read attempt against a 100 KB tar member burned 1 MB of budget for 100 KB of data. A 64 MB budget truncated a legitimate archive after 3 MB.
- The truncation warning printed `MAX_DECOMPRESSED_BYTES` (the module default) while a smaller `PFIND_MAX_DECOMPRESSED_MB` override was in force, naming a limit the run never used.

## What the Python audit cleared

Twenty files. `pfind.py` - the only Python that ships, embedded in the binary and in the `.deb` - has zero unclosed handles and zero un-timed subprocess calls; its seven whole-file reads are all inside `with` blocks. No infinite loops, no unbounded recursion, no missing socket closes anywhere in the tree.

## Process failure worth recording

A test harness importing `pfind.py` created `internal/llm/tools/__pycache__`, and a `git add -A` swept a 168 KB compiled `.pyc` into a commit. Caught and reset before pushing. The release pipeline itself runs `git add -A`, which is precisely how such a thing gets published by accident. Now ignored.

Separately: the six deleted screenshots were found by the owner noticing they were gone, not by any test. A guard that fails when a `docs/` image reference does not resolve would have caught it the day it happened. Noted in `TO.DO.TO.FIX/Ideas.And.Experiments`.

## Verification

30 test packages pass. Both the Debian and Arch packages built and opened. Both locks were verified by breaking them deliberately - flattening the bar and rewording a banana rung each produce a named failure explaining what was lost. The first draft of that check was a no-op: it searched for the literal glyph while the source stores the escape `█`, which is exactly how a guard ends up looking like it works.
