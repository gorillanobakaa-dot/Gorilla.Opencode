# Gorilla OpenCode v0.1.155: the Windows release. The AI knows the machine and its own tools, has a files tool and a read-only Windows tool, and stopping a command stops everything it started

**Date:** 2026-10-27
**Previous version:** v0.1.154

---

## Why this release exists

The owner tried Gorilla OpenCode on Windows with AIs that run on the laptop itself. They did not know the program's own tools. They did not know that Windows' copy program, robocopy, can copy on up to 128 threads at once, how to look at a file's attributes (read-only, hidden), or which PowerShell they were typing into. The reason was simple: all the AI was told about the computer was "Platform: windows".

Other things went wrong on Windows every day. A file saved by PowerShell was refused as "binary". A robocopy copy that worked was reported as failed. Looking at a folder asked for permission every time. Stopping a command left the programs it had started running, unseen, using memory. A command that asked a question ("are you sure? y/n") hung until the time ran out.

This release fixes those things. Then it was checked the way a person uses it: 35 everyday requests (copy, mirror, move, rename, list, attributes, delete, "what tools do you have", "build this with MSVC", "which files came from the internet") were typed into the real program, and each result was checked on the disk, never by trusting what the AI said.

The check started on an AI running on the laptop (Qwen3.6-35B-A3B in LM Studio). Its first three requests were right, but each took 4 to 7 minutes, and the laptop's memory was 88% full. The owner stopped it and ordered the rest run on ChatGPT (GPT-6-Luna, the lightest model of the ChatGPT sign-in), in a window he could watch. The first pass was right on 27 of 35. Seven of the eight misses had a cause in the program or in the test; all seven were fixed. The final result: **33 of 35 right**. The two misses were the AI's own:

- "Prefix every file here with 01_, 02_, 03_": the AI gave every file the prefix 01_, then said it had numbered them 01, 02 and 03. The tool's own result showed 01_ three times. The program told the truth; the AI misreported it. The same request was right in the first pass.
- "What tools do you have?": the AI listed its tools correctly, but did not say "robocopy", which the check required.

## What you will notice on Windows

**The AI knows this computer**
- Before: the AI was told "Platform: windows" and nothing else.
- After: when the program starts, it looks at the computer once, without going on the internet and without starting any program, and tells the AI in a few lines: which Windows and edition, whether you are an administrator, which PowerShell it is typing into and its version, how many processor threads there are and that robocopy takes up to 128, whether long paths and Developer Mode are on, whether git, Visual Studio's C++ compiler (MSVC) and Windows Terminal are installed, whether PowerToys is installed, Sysinternals tools if they are there, and which helper programs are built into this copy.
- Asked to build with MSVC, the AI is told exactly how to start the compiler from PowerShell. Before, it got the quoting wrong twice.
- Asked "is PowerToys installed?", it is told the answer. Before, it said it could not tell.
- Cost: the instructions sent to the AI are about 520 tokens longer on every turn. On a small AI on your own computer that is real. You can switch it off with the "Environment info" row in `/context` (that also removes the folder listing).
- Affects: everyone on Windows. On Linux and macOS the same lines without the Windows facts.

**The AI knows its own tools**
- Before: only the technical definitions of the tools; small AIs often did not connect them to a request.
- After: a table called "YOUR TOOLS", one line per tool, made from the real list of tools, so it cannot be out of date. Asked "what tools do you have", the AI is told to answer from it.
- Longer how-to notes (robocopy's switches and what its exit numbers mean, PowerShell file commands, attributes and permissions, services and event logs, each built-in helper) are not sent every time. The AI reads one when it needs it.
- Affects: everyone.

**One tool for everyday file work: `files`**
- Copy, mirror and move whole folders with robocopy, on up to 128 threads (by default one per processor thread). "Mirror C:\a to D:\b with 64 threads" works as you would say it.
- Mirror, purge and move delete files for good. That is what those robocopy switches do, and the owner decided they should be real. So before any of them runs you see a dry run listing what will be copied AND what will be deleted, and you are asked. Auto mode does not answer for you here, and a run without anyone watching (`-p`) refuses them.
- If the dry run shows any error (a drive that is not there, a folder it cannot read), nothing runs.
- Mirroring onto a whole drive or onto your user folder, or between two folders where one is inside the other, is refused outright.
- Make a file read-only, hidden, or normal again, for one file or a whole folder. Compressing and encrypting are refused, with a pointer to Windows' own commands.
- Rename many files at once: replace text in the names, change upper and lower case, number them 01_, 02_ and so on. The new names are shown first, and a rename that would give two files the same name is refused before any file moves. If one rename fails, every name is put back.
- Show a file's details: size, dates, attributes, owner, who may open it, and whether it was downloaded from the internet.
- List a folder, hidden and system items included and marked as such.
- Delete: to the Recycle Bin, unless you say "permanent". If you asked for the Recycle Bin earlier in the conversation, "permanent" is refused.
- Tested in temporary folders: 2,000 files copied with 128 threads, names with accented letters, paths longer than Windows' old 260-character limit, read-only files, a folder link that points back at itself, and one real trip to the Recycle Bin.
- Affects: everyone, most of all on Windows.

**A read-only tool for Windows itself: `windows`**
- Before: to answer "is the print spooler running?", the AI wrote a PowerShell command, waited for you to allow it, and read text made for a person.
- After: one tool reads five things and answers in a fixed form the AI reads reliably: one registry value or key; services (state, how they start, which program they are); the event log (errors of the last day by default); scheduled tasks (state, last and next run, what they run); and a short fixed list of system facts (Windows version, processor, disks, memory, graphics, network addresses, running programs, installed updates, drivers and a few more). At most 20 items unless the AI asks for all.
- It cannot change anything. It does not ask before reading, because it only reads: that was the owner's decision.
- What it reads goes to your AI's provider, like everything else the AI reads. So it never reads the computer's serial number, the network cards' hardware addresses, or the full command lines of running programs (they can contain passwords). If you do not want the AI to see your event log or registry at all, switch the tool off in `/context` (row "Windows: registry, services, event log, tasks, CIM").
- The Security event log needs administrator rights; the tool says so.
- Ask: "what errors were in the System log today?", "when did the backup task last run?", "how much space is left on each drive?", "which updates were installed this month?".

**Stopping a command stops everything it started**
- Before: a command can start programs, which can start more. Stopping the command, closing a language server, or the program crashing left some of them running, unseen, holding memory and files.
- After: every program Gorilla OpenCode starts goes into a Windows "Job Object", a container that Windows ends all at once. Stop a command (Esc, or a timeout) and everything it started ends. If Gorilla OpenCode itself crashes or is killed, Windows ends them all. The same holds for language servers, MCP servers and hooks.
- Your PowerShell session stays: its variables, activated virtual environment and folder are kept, and the answer says "The shell session was kept". Before, stopping a long PowerShell command ended the whole shell.
- Change to know about: something you asked the AI to start in the background (a development server, a file watcher) now stops when its session ends: when you stop a later command, change folder with `/cd`, or quit. If a program must outlive Gorilla OpenCode, start it yourself, outside it.

**Commands that ask a question**
- Before: `Read-Host`, a "y/n" prompt, or a program that needs a real console window hung until the time ran out.
- After: the AI can run such a command in "console mode" and type the answers in advance. Ask "run the setup script, and answer yes when it asks". Console mode runs as a separate program in the same folder, so it does not see variables set earlier in the session. One command at a time; a full interactive program (an editor, a game) is not supported.

**PowerShell and the files it writes**
- A file saved by PowerShell (`>` in PowerShell 5.1, `.reg` exports) or an old Western European text file was refused as "binary". Now it is shown, with one line saying which encoding it was read in.
- robocopy's exit code 1 means "files were copied". It was reported as a failure; now the result says "robocopy: success - files were copied". Codes 8 and above are still failures, with their meaning.
- Looking at files (`Get-ChildItem`, `Get-Item`, `Get-Content`, `Test-Path`, `Get-FileHash`, `Get-Acl` and similar) no longer asks permission, as long as nothing in the line changes anything. `Get-ChildItem | Rename-Item ...` still asks. A credential file still asks however it is spelled.
- Scripts such as `npm`, `npx` or a Python virtual environment's `Activate.ps1` could refuse to run. They run now: the program's own PowerShell bypasses the script policy. The computer's setting is never changed.
- Accented letters printed by git or Python came out garbled. Text is UTF-8 throughout now.
- A program waiting for keyboard input could swallow the next commands. Now it gets "nothing" instead.
- Editing a file with Windows line endings no longer mixes in Unix line endings.
- The AI is no longer told never to use `&&` when your PowerShell is version 7, which accepts it. The warning stays for Windows PowerShell 5.1.

**Stronger warnings for dangerous Windows commands**
- Deleting registry keys or restore points, wiping free space, changing the script policy, taking ownership of system files, changing system permissions, deleting or stopping core services, scheduled tasks, start-up (Run) keys and robocopy `/MIR` used to get the same plain question as `dir`. Now they get the strong warning, saying in one sentence what cannot be undone, and they ask even when everything else is allowed.

**A folder deleted under the program**
- Before: a command run in a folder that had been deleted reported "no output (exit code 0)", as if it had worked.
- After: you are told the folder no longer exists, the command is NOT run, and the session moves to the nearest folder that still exists. Run the command again if you still want it.

**Reading text in pictures**
- Before: only with the tesseract program installed.
- After: with the text recognition built into Windows, offline, when tesseract is not there. The answer starts "TEXT READ OUT OF THE IMAGE ... using OCR (Windows OCR)".

**Your sign-ins are encrypted**
- Before: the sign-in files were plain files any program running as you, or any administrator, could read.
- After: they are encrypted for your Windows account on this computer (DPAPI, Windows' own encryption). Old sign-ins keep working and are encrypted the next time they are saved. A file the program cannot read is kept and reported, never deleted.
- If you start an older version after this one has saved your sign-in, the older one cannot read it and asks you to sign in again. Nothing is deleted. (This downgrade was not tested; it is what the design does.)

**Built-in helper programs (toolbox builds)**
- A Windows build made with the "toolbox" option carries seven helper programs inside its one .exe: pfind (file search), ast-grep (structural code search), difftastic (a diff that understands code), sd (find and replace), hyperfine (timing), ninja (a build runner) and uutils coreutils (the usual Unix commands). The AI's shell can call them by name. Your own terminals are not changed.
- The first time one is needed it is unpacked into your own private cache folder, and its fingerprint is checked before every single run. A copy that does not match is replaced; a helper whose fingerprint is wrong is refused, and the AI is told the command was not run. Nothing is downloaded.
- File search no longer needs Python in a toolbox build: it uses the new pfind.exe, a Rust program built on ripgrep's own search parts. It gives the same answers as the Python pfind, checked with 84 tests run on both. It was 2.2 to 5.6 times faster on everyday searches, and 15.5 times faster at counting lines of code, measured on this project's own folder.
- Size: a toolbox build is about 85 MB; a plain build about 58 MB and carries no helpers. Which one this release's `gorilla-opencode.exe` is: see the file table on the release page.

**Web search without installing anything**
- Before: on Windows, "web search is not configured" and an instruction to install lynx.
- After: the same message names three ways to turn web search on. One needs no install: the built-in reader. The program fetches the results pages of Brave, Ecosia, Mojeek and Marginalia itself and reads them as text.
- It is **off until you turn it on**, because your search words go to those four search engines. To turn it on, add `"webSearchBuiltin": true` to the program's config.json, or set `GORILLA_OPENCODE_WEB_READER=builtin`, and restart. Whether it should be on by default is an open decision of the owner.
- `gorilla-opencode doctor` lists, under "Tool capabilities", which web search route and which picture-reading engine this computer has, and what is missing.

**Other Windows changes**
- The code-review tool's installer uses Scoop on Windows and never offers Linux's apt there.
- The sparse checker stays Linux-only, and on Windows says why and what to use instead.

## What you will notice on every system (Windows, Linux, Mac)

**Typing while the program opens**
- Before: if the "Initialize project?" question was on screen, letters typed at an ordinary pace could vanish. A test typed "What is in the folder Folder?" and the AI received "t is in the folder Folder?".
- After: every key you type reaches the chat box. Only y, n, q, Enter and Esc answer the question.

**A tool server that crashes**
- Before: if an add-on tool server (an MCP server) crashed during a call, the chat waited forever.
- After: the call ends at once and says the server stopped. On a Mac this needed its own fix; it was built and checked for errors, but not run on a Mac.

**ChatGPT over a weak connection**
- Before: one failed connection (for example "TLS handshake timeout" on a phone hotspot) ended the turn.
- After: a request that never reached the server is sent again, twice (after 2 and after 4 seconds). A request that did reach the server is never sent twice.

**Folder listings say what they left out**
- Before: "what is in this folder" could leave out a subfolder whose files were all deeper down, without saying so.
- After: a listing names every folder it did not open.

## What changes for Linux and Mac users

Beyond the four fixes just above and the web reader (the same on every system, off until you turn it on), little changes:

- The `files` tool exists for you too. It uses a built-in copier instead of robocopy. Attributes: only read-only can be changed. Deleting to the trash uses `gio trash` or `trash-put` on Linux and the Finder on a Mac; if none is there, the delete is refused, never done for good in silence. These paths were tested on GitHub's Linux machines, not by hand; the trash route was never run, and nothing was run on a Mac.
- The AI gets the "YOUR TOOLS" table and the short description of the computer, without the Windows facts.
- Job Objects, console mode, the `windows` tool, Windows text recognition, sign-in encryption and the toolbox helpers are Windows only. Linux and Mac builds carry no helpers.

## Deliberately not done

- Pipes stay the normal way commands run; console mode is chosen per command, because its output is a drawing of a screen, not a clean log.
- The how-to notes are not sent on every turn (about 3,000 tokens each turn for knowledge most turns do not need). The AI reads them when needed.
- The `windows` tool reads; it never starts a service or edits the registry. Those stay PowerShell commands that ask first.
- Code-signing: the release script can sign the program once there is a certificate. There is none, so this release is not signed.
- No local-AI run beyond the first three requests (the owner's decision, for memory).

## Privacy and security

Nothing new is sent anywhere by itself. The look at the computer reads only this computer, once per run. The `windows` tool reads only this computer and leaves out serial numbers, hardware addresses and full command lines. Windows text recognition runs offline. The web reader is off until you turn it on, and then sends your search words to four search engines. Signing runs only with a certificate the owner does not have yet. The helper programs are inside the .exe, checked by fingerprint before every run, and never downloaded. Some code was copied (not downloaded at run time) from Microsoft's hcsshim project under its MIT license; none of its logging or telemetry was taken. Sign-ins are now encrypted on Windows.

## How to install

**Windows:** download `gorilla-opencode.exe`, then in a terminal in that folder: `.\gorilla-opencode.exe install`.
**Debian, Ubuntu, Mint:** `sudo apt install ./gorilla-opencode_0.1.155_amd64.deb`. **Fedora, openSUSE, Rocky:** the `.rpm`. **Any other Linux:** `gorilla-opencode-v0.1.155-linux-amd64` (make it executable) or the `.tar.gz`.
**Mac (macOS 10.13 or later, Intel):** the `...-mac-10.13-x86_64.zip`; right-click `Install Gorilla OpenCode.command`, choose **Open**.

Check a download against `SHA256SUMS-v0.1.155.txt`.

## If something goes wrong

- **A program you started through the AI stopped when you pressed Esc or quit:** that is the new rule: everything a session started ends with it. Start long-running programs yourself, outside Gorilla OpenCode.
- **The answer says the shell session is gone ("variables and an activated venv set up earlier are gone"):** the stop could not keep the session this time. Set up again (activate the venv) and carry on.
- **You are asked to sign in again after going back to an older version:** this version encrypted your sign-in and the older one cannot read it. Sign in again; nothing was deleted.
- **"web search is not configured":** the built-in reader is off. Turn it on as above, or install lynx, or use your own SearXNG.
- **A helper command was "NOT run":** the copy of that helper inside the program did not match its fingerprint list, so it was never run. A copy in the cache that does not match is replaced by itself; this refusal is about the copy inside the .exe. Nothing else stops working.
- **"The command was NOT run" with a deleted folder:** the folder the session was in was deleted. The session moved to the nearest folder that exists; run the command again there or `/cd` where you want.
- **A mirror, purge or move asks even in auto mode:** it deletes files for good. Read the preview, then answer.
- **A text file shows the wrong letters:** a file in another old code page (Cyrillic, Greek) is shown as Western European letters. The line above it says which encoding was used.

## Bottom line

On Windows the AI is told what the computer is and what tools it has, uses one files tool with a preview before any permanent delete, reads Windows facts without asking and without changing anything, and stopping a command stops everything it started. On Linux and the Mac: fixes for lost keys, a crashed tool server, weak ChatGPT connections and incomplete listings, and a web reader you can turn on.
