# Gorilla OpenCode v0.1.47 — Your conversation now lives in your terminal, where you can scroll it, select it and copy it

*Track 1 of 2 — written for anyone. The developer track follows below.*

## Why This Release Exists

You could not scroll back through a conversation. You could not select it with the
mouse. `Ctrl+A` selected nothing and `Ctrl+Shift+C` copied nothing. Five hours of
work was, in the most literal sense, not there.

The reason turned out to be one line of setup, and it had been there since the
program was first written. A terminal has two screens: the normal one, whose
history your terminal keeps and lets you scroll, and an **alternate screen** — a
scratch surface with no history at all. Full-screen programs use the alternate
screen because it lets them paint anywhere and leaves your shell untouched when
they exit. The cost, which nobody had priced, is that nothing drawn there can be
scrolled back to, selected or copied. The terminal keeps no record of it.

Every workaround that was on the table — drawing our own scrollbar, shipping a
clipboard helper, using a special escape sequence to set the clipboard directly —
was compensating for that one decision. This release removes the decision instead.

## What You'll Actually Notice

**Your scroll wheel works.** So does `Ctrl+A`, so does `Ctrl+Shift+C`, and so does
your terminal's own search. None of that is code we wrote. Finished messages are
now *printed* into your terminal rather than painted over it, so your terminal owns
the text and does what it has always done with text.

**The prompt sits at the bottom and stays there.** It used to drift downward as
replies arrived, settling only once enough output had accumulated to fill the
window.

**The grey blocks are gone.** Messages were being drawn inside filled rectangles,
which looked deliberate on a screen the program owned and looked like floating
widgets on your own terminal background. Your words are now bold with a `>` in
front; the model's are plain prose. That difference survives being pasted into a
text file, which a background colour does not.

**Typing a long prompt shows the whole thing.** The input box grows as you type, up
to 20 rows — measured at about 320 words — and when there is more above than fits it
says so: `▲ 4 more lines`. Before, it stayed one row tall, so everything above the
line you were on scrolled silently out of sight and a long prompt looked as though
it were losing words.

**Long replies no longer slow the interface down.** This one was our own fault and
it was measured, not guessed:

| Length of the reply being written | Before | Now |
|---|---|---|
| 50 words | 0.96 ms per frame | 0.05 ms |
| 800 words | 6.5 ms per frame | 0.14 ms |
| 3,200 words | **21 ms per frame, 3.4 MB of waste** | **0.15 ms, 65 KB** |

The preview of the reply-in-progress was re-formatting the *entire* answer, every
frame, in order to show its last six lines. The longer the answer, the slower
everything got. It is now flat: the same cost whether the reply is 50 words or
40,000.

**The session's numbers moved below the prompt** — model, folder, context used, cost,
tokens in and out, language servers, files changed — because there is no side panel
in this mode.

**The startup folder question no longer smears** when you resize the window
mid-question. That was a separate, older bug (from v0.1.41), visible in a screencast
as a trail of half-drawn copies.

## Decisions & Why

**The alternate screen is still available**, as a setting, off by default. Turn it
on and you get the old full-screen interface exactly as it was: panels that never
scroll away, no flicker while streaming — and no history, no selection, no copy.
`/settings` says so in those words. Google made the same call in Gemini CLI, whose
equivalent setting also defaults to off.

**We did not change your terminal's background colour**, although we checked and we
could. There is an escape sequence for it and your terminal honours it — measured:
asked it, got black; set it to `#282a36`; asked again and got `#282a36`. It was
rejected because it changes a setting you own and would *not* change back if the
program were killed. Painting nothing at all was the better answer.

**We did not build a scrollbar or ship a clipboard helper.** Both became pointless
the moment the text was really in the terminal. Roughly a day of planned work was
deleted rather than written.

**Mouse reporting stays off** unless you are using the alternate screen. Asking the
terminal for mouse events takes drag-to-select away from it; with the conversation
in your scrollback there is nothing left to gain.

## Deliberately Not Done

- **The 400 Bad Request** seen on a question that used the web-fetch tool is not
  fixed. It is understood well enough to say it is not the reasoning setting (that
  was off), and the likely cause is the two fetches never returning, leaving tool
  calls with no results — which the API rejects. Not chased yet.
- **Numbered lists in replies still collapse onto one line.** That is standard
  Markdown, where single line breaks are not paragraph breaks. It predates all of
  this and changing it changes how every reply is formatted, so it is being left for
  a decision rather than done by surprise.
- **A rewrite in Rust or TypeScript** was raised and rejected on evidence. The 21 ms
  frame was one bad function call, not the framework; Codex's Rust interface is
  1.23 million lines across 97 crates; and the architecture we now have is the one
  Gemini CLI uses.

## Privacy & Security

No change. No telemetry, no accounts, no network calls this release did not already
make. The one new capability considered — writing to your clipboard — was not built.

## Risks, Backup & Recovery

The interface now behaves differently by default, and that is the risk worth
naming. If you prefer the old one:

```sh
gorilla-opencode        # then: /settings → Draw on a separate screen → on → restart
```

Everything else is unchanged. Your sessions, configuration and keys are untouched.
Downgrading is `sudo dpkg -i` on the previous `.deb`, which remains on the releases
page.

## How To Install

```sh
sha256sum -c checksums.txt
sudo dpkg -i gorilla-opencode_0.1.47_amd64.deb
gorilla-opencode --version && dpkg -l gorilla-opencode | tail -1
```

Both must say `0.1.47`. Quit any running copy first.

## What's Still Broken

- The **400 Bad Request** above.
- Markdown collapsing single line breaks.
- The alternate-screen interface has had far less exercise than before, since it is
  no longer the default path.
- The size sweep covers 8 of about 15 dialog surfaces.
- Tool descriptions are still roughly 3,680 tokens against the system prompt's 464.
  There is no duplication left to remove and no evaluation suite to prove a cut is
  safe, so nothing was cut.

## Common Questions

**Did this make it slower?** The opposite, measurably. See the table above.

**Why is there a screenful of blank space above my first message?** That is the
program scrolling once at startup so the prompt begins on the bottom row. It is the
price of a fixed prompt without a scroll region — and a scroll region would have
been worse, because lines scrolled out of one are discarded instead of joining your
scrollback.

**Can I still get the old look?** Yes — one setting, above.

**Does my old configuration still work?** Yes. Nothing was renamed or removed.

## Bottom Line

The conversation is text in your terminal now. Scroll it, select it, copy it, search
it. Eleven commits, 3,483 lines added across 55 files, and the largest single item
was deleting a day of planned work that turned out to be unnecessary.

## Where This Came From

This release exists because of a question — "is Gemini CLI written in Go?" It is
not; it is TypeScript. But its source was on the machine, and reading it showed that
Google had independently made both of the choices being argued about: history pushed
into the terminal's own output, and the alternate screen off by default. That
settled an architecture debate with evidence instead of taste.

# v0.1.47 — leave the alternate screen, print the transcript, and stop re-rendering it every frame

*Track 2 of 2 — for developers.*

## Architecture & Footprint

11 commits, 55 files, +3,483 / −140. 22 packages of tests, `go vet` clean.

The central change is one option and its consequences. `tea.WithAltScreen()` is no
longer passed unconditionally; it comes from `config.AlternateScreenEnabled()`,
default false. Everything else follows from what that makes true.

The premise was measured before any of it was built
(`internal/tui/inline/scrollback_test.go`):

- Outside the alternate screen, `tea.Println` puts a line into the terminal's real
  output **exactly once**.
- Inside it, the same call is **discarded** — 0 of 3 lines reach the output.

Both directions are asserted, and forcing `WithAltScreen` back into the inline test
makes it fail, so neither is vacuous. A third test records the constraint that
follows: bubbletea's inline renderer erases its previous frame by walking the cursor
up by the number of **logical** lines it last drew, so a frame taller than the
window puts every later erase in the wrong place. Keeping the footer short is a
correctness requirement, not a preference.

## Code Changes

**`internal/tui/components/chat/printer.go`** (new) — emits each settled message via
`tea.Println` exactly once. Printing is irreversible, which drives every rule:
messages are only printed once `ScrollbackReady` (user messages on arrival,
assistant messages when finished, tool messages never — they render inside the
assistant message that called them); printing **stops** at the first unsettled
message rather than skipping it, because a later message emitted first is
permanently out of order; nothing prints before the width is known.

**`internal/tui/components/chat/scrollback.go`** (new) — `RenderForScrollback`
deliberately reuses `renderUserMessage`/`renderAssistantMessage`, with a test
asserting the output is identical to the pane's, so the two cannot drift.

**`internal/tui/overlay_state.go`** (new) — `anyOverlayOpen` discovers the ~18
`show*` flags by reflection rather than listing them. A hand-written list rots on
the nineteenth dialog, and the failure mode is that dialog drawing into a short
inline footer and corrupting the terminal. `bufferCmd` is the single place that
enters and leaves the alternate screen, called from a wrapper around `Update` — the
per-call-site version is the one that gets some paths right.

**`internal/tui/pin_bottom.go`** (new) — scrolls the window once so the cursor starts
on the last row, and again by the delta when the window grows. Explicitly **not** a
DECSTBM scroll region: lines scrolled out of a region are discarded rather than
added to scrollback, which would pin the prompt perfectly and destroy the history
the release exists for.

**`internal/tui/styles/styles.go`, `background.go`** — `PanelBackground()` and
`ApplyPanelBackground()` are the two decision points for every fill. 70 method-call
fills and 12 `ForceReplaceBackgroundWithLipgloss` calls routed through them; 29
semantic backgrounds (error, warning, primary, info, success) deliberately left
alone.

**`internal/tui/components/chat/message.go`** — `renderMessageFlat` for the inline
case: no fill, no border, user text prefixed and bold, assistant text plain Markdown.
Hard-wrapped with `ansi.Hardwrap` because dropping the panel also dropped the
lipgloss `Width` that bounded every line.

**`internal/tui/components/chat/editor.go`** — the field sizes itself rather than
waiting for a layout round trip. `maxEditorHeight` 12 → 20; `textarea.MaxHeight`
99 → 300; an overflow notice naming the hidden row count.

**`internal/tui/components/chat/footerinfo.go`** (new) — the sidebar's second,
horizontal rendering, two rows, truncating rather than wrapping.

## Subsystem Changes

**Performance.** `livePreview` called the full Markdown pipeline over the entire
growing reply, every frame, to show six lines: 0.96 ms/348 KB at 50 words rising to
21 ms/3.4 MB at 3,200. Now bounds the input *before* wrapping, so allocations stop
growing entirely — 88 per call at any length, down from 52,368. 137× faster at
3,200 words.

**Startup pickers** moved *into* the alternate screen — the opposite move for the
opposite reason. They ran inline so the chosen folder stayed visible; with no
repaint on resize, each resize step left a stale half-drawn frame. They now ask in
the alternate screen and print the answer as one durable line.

**Mouse.** `RequestMouseEvents()` is distinct from `MouseWheelEnabled()`: the
preference is honoured only where it can buy anything.

## Test Coverage

New: `inline/scrollback_test.go`, `printer_test.go`, `scrollback_test.go`,
`footerinfo_test.go`, `overlay_state_test.go`, `scrollback_footer_test.go`,
`pin_bottom_test.go`, `page/footer_shed_test.go`, `styles/panel_background_test.go`,
`cmd/altscreen_wiring_test.go`, `chat/flat_render_test.go`,
`chat/editor_growth_test.go`. `screentest.BackgroundBreak` reports the first column
whose background differs from its row's — the defect a width assertion cannot see,
because the rows were the right length.

Every invariant was checked by breaking the code: 6 mutations on the printer, 8 on
the footer and buffer switching, 7 on the pinning, 5 on the editor, 3 on the wiring.

Six of those sweeps initially reported a gap, and **all six were faults in the
tests**, recorded in comments where they happened:

1. The ordering test passed falsely — the shared `userMsg` helper hardcodes ID
   `"m1"`, so two user messages collided and were deduped instead of ordered.
2. The budget test drove a stub page that honoured its own budget, so ignoring the
   real budget was invisible.
3. `shedToFit`'s test supplied its own ordering, so the actual priority was untested
   until it was given a name.
4. An alternate-screen assertion looked for "a background escape somewhere", which
   the timestamp line supplies regardless of how the body rendered.
5. The preview cost test compared a 50-word reply against a 4,000-word one, which
   measures nothing — the short one does not fill six rows.
6. Then it asserted on output *size*, which cannot see the expensive version at all,
   since both cap at six rows. Allocation count is what distinguishes them.

## Security Posture

No new network paths, no new dependencies, no new file writes. OSC 52 was measured
as unsupported by VTE 0.80.1 (sentinel survived), and OSC 11 as supported, but
neither is used.

## Deployment & Verification

Tag, build, extract the `.deb` and confirm the **inner binary** reports the same
version as the control file, publish (checking `isDraft`), download the artifacts
back, verify checksums, then purge and install from the downloaded package. The
artifact-inspection step is not ceremony: it caught a v0.1.46 package whose control
file said `0.1.46` around a binary reporting `v0.1.45`.
