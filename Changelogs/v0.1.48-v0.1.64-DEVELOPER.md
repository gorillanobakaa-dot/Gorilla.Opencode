# Transcript unblocking, byte-bounded tool results, and the inline-renderer width invariant

**Version:** v0.1.64
**Date:** 2026-07-31

---

## Summary

Sixteen builds between 2026-07-28 and 2026-07-31, 30 commits, 66 files changed with 4,110 insertions and 4,225 deletions. Four defects dominate. First, ScrollbackReady returned false for tool messages to prevent double-printing, but printPending breaks on the first message that is not ready, so the first tool result halted the transcript permanently — every later message, including the model's completed answer, was generated, persisted and never rendered. Second, the grep tool capped matches at 100 while the resource being consumed was bytes, returning 2,438,026 bytes from files where a whole source file is one escaped JSON string; that single result moved a conversation from 15.9K to 675K tokens in one turn, and because tool results are replayed on every subsequent turn it was a recurring cost. Third, bubbletea's inline renderer erases its previous frame by moving the cursor up by the number of logical lines it drew, so any line wider than the terminal occupies two physical rows while counting as one and the erase under-reaches by one row per wrapped line per render. Fourth, the context percentage was inflated by roughly two orders of magnitude, displaying 387%.

## Design Rationale

Each fix was placed at a choke point rather than at the call sites, because the failures were all caused by per-site policy drifting apart. Tool-result bounding lives in NewTextResponse at 400 KB rather than in twelve individual tools, because twelve tools each measuring whatever was natural to them — files, lines, matches, seconds — is precisely how the byte overflow was missed. Frame width is enforced by clampToWidth in tui.go rather than in the four footer components, because they all use lipgloss Width() and fixing them individually leaves the invariant one careless Render() from breaking again. For the transcript stall the goal was right and the lever was wrong: duplicate suppression belongs in RenderForScrollback returning an empty string for that role, not in withholding readiness. ScrollbackReady means 'will not change again', not 'has something to show'. Truncation is always announced, because a model handed a silent fragment reasons about the fragment as though it were complete.

## Architecture Impact

Three invariants are now explicit and enforced centrally. (1) No line in a rendered frame may exceed the terminal width — this is a hard invariant of the bubbletea inline renderer, not a style preference. (2) A limit must be expressed in the unit of the resource it protects; item counts are a proxy and proxies fail exactly when items are unusual, which is when the limit was needed. (3) Readiness and displayability are distinct properties and must not share a predicate. A fourth change is behavioural rather than structural: all four shipped system prompts were rewritten, and the coder prompt is now parsed into switchable sections at runtime, so the instruction set is user-modifiable configuration rather than a compiled constant.

## Subsystem Changes

**TUI:** Scrollback printing, footer height and width invariants, reasoning rendering, message history. internal/tui/inline/ drives a real bubbletea program headlessly and replays its bytes through a terminal emulator that models scrolling (terminal_test.go); the width bug was found there, not on screen.

**OTHER:** Tool result bounding at NewTextResponse; grep bounded by size rather than match count.

**OTHER:** System prompt subsystem: runtime section parsing, per-section loadout gating, and a byte-comparison guard holding the published study copies identical to the embedded originals.

## Test Coverage

- **Added:** internal/tui/inline/scroll_boundary_test.go reproduces the over-wide-line footer drift and asserts against a reconstructed screen. A permanent test asserts the info block's height is constant rather than merely bounded. A test asserts a footer alternating 3<->4 rows and collapsing 20->1 both render correctly, which is what disproved the frame-height hypothesis. studycopy_test.go byte-compares system-prompts/current/ against the embedded prompts so the published copy cannot drift from the shipped one.
- **Removed:** Superseded agent planning documents were removed; no test coverage was removed.
- **Notes:** v0.1.59 was shipped with a failing test because a shell chain did not gate on the exit code and printed 'all green' while a test was red. A pipe returns the last command's status, not the test's. Capture $? on its own line. Non-vacuity was verified for the guards in this range by restoring the defect and confirming the test fails.

## Security Posture

No changes. No telemetry, no new network endpoints, no permission model changes, no dependency additions in this range. Indirect exposure reduction only: bounding tool results at 400 KB reduces the volume replayed to the provider on every subsequent turn, since tool results are re-sent each turn.

## Known Issues

**[high]** Transcript stops after the first tool result; UI holds on 'Waiting for response…' indefinitely while the session database continues to accumulate messages.
- Cause: Running a build older than v0.1.63. printPending breaks on the first not-ready message and ScrollbackReady returned false for tool messages.
- Remedy: Upgrade to this release.

**[high]** Token usage jumps by hundreds of thousands after a single search, and stays elevated on every subsequent turn.
- Cause: Running a build older than v0.1.62. grep bounded match count rather than bytes and matched inside files where one line is an entire escaped source file.
- Remedy: Upgrade. Results are bounded at 400 KB at NewTextResponse and truncation is announced.

**[medium]** Footer drifts down the screen and jumps back, leaving orphaned fragments mid-transcript.
- Cause: A frame line wider than the terminal. The inline renderer erases by logical line count, so a wrapped line under-erases by one physical row per render.
- Remedy: Upgrade to v0.1.57 or later, which clamps every frame line centrally.

**[medium]** Footer still observed to jump after v0.1.63.
- Cause: Unknown. Frame-height oscillation and the 20-row editor collapse are both disproved and have permanent tests. Diagnose by capturing the byte stream with script(1) and replaying it through internal/tui/inline/terminal_test.go — not from a screenshot.
- Remedy: No fix available. Report window width and a byte capture.

**[low]** No reasoning output despite reasoning display being enabled.
- Cause: extras-reasoning-generate false while extras-reasoning-show true yields no thinking from any model that does not reason by default.
- Remedy: Enable 'Ask the model to think out loud' in /context. From v0.1.60 the program states this on screen rather than showing nothing.

**[low]** Higher per-turn token cost after upgrading.
- Cause: The rewritten coder prompt is ~1,058 tokens per turn versus ~464 previously, and prompt tokens are re-sent every turn.
- Remedy: Disable individual sections in /context; each shows its token cost. Note that two sections are marked critical because disabling them increases unverified success claims.
