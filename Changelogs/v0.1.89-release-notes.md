# Gorilla Opencode v0.1.89 — no window draws outside the window

Released 17 August 2026, one commit after v0.1.88. A display-correctness
release: three dialogs were drawing frames wider than the terminal, and one was
drawing taller. Nothing else changed.

## Plain-language track

### Why This Release Exists

A menu that is wider than your terminal does not simply look untidy. The
program draws its screen by rubbing out the previous one, and it counts how
much to rub out in **lines it wrote**, not in rows your terminal used. A line
too wide to fit takes two rows on screen but still counts as one — so every
redraw leaves one row behind, and those leftovers pile up in your scrollback as
debris that nothing can clear.

Three screens had exactly that fault. `/context` asked for 106 columns whatever
size your terminal actually was, and both `/osint` screens had the same defect
at 80 and 70 columns. The `/osint` warning screen also asked for 37 rows on a
24-row terminal, which pushes the top of the box off the screen entirely.

If your terminal is wide — a maximised window on a normal monitor — you would
never have noticed. It bites on narrow windows, split panes, and phone or
tablet sessions.

### What You Will Notice

**menus on a narrow terminal**
- Before: `/context` and the two `/osint` screens drew past the right-hand edge, and leftover rows collected in the scrollback.
- After:  Every screen fits inside the terminal it is drawn into. Where a line is too long for the space, it is cut with an "…" rather than spilling out.
- Affects: anyone whose terminal is narrower than about 106 columns

**the `/osint` warning screen on a short terminal**
- Before: It rendered every line unconditionally — 37 rows on a 24-row screen, so the top scrolled away.
- After:  It gives up its explanatory prose in stages until it fits. What it never gives up is the decision: the warning, what the run costs, the helper and mode controls, and the keys.
- Affects: anyone using `/osint` on a short terminal

**the `/context` menu on any terminal**
- Before: Headings and hints were handed to the layout raw, so a narrow window silently turned each into two or three rows.
- After:  They are cut to the width available, which gives a row back on the smallest terminals.
- Affects: everyone, most visibly on small screens

### Deliberately Not Done

- **The stranded-lines report from an Arch tester is still open.** The bug fixed
  here is the same *class* — a frame wider than the terminal — and his own
  screenshots include the `/context` screen, so this may well be his cause. It
  is a plausible mechanism, not a confirmed diagnosis, and it is not being
  reported to him as a fix. The questions still outstanding are his terminal,
  his font, `$TERM`, and whether a menu was open at the time.
- **`/context` still needs more rows than a 10-row terminal has.** It needs 18
  now instead of 19, which is progress rather than a cure. Terminals that small
  are tracked by a ratchet in the test suite rather than pretended about.

## Developer track

### Summary

One commit. `loadoutDialogCmp.width()` floored the content width UP to
`loadoutMinWidth` (100) and the render then added 6 columns of border and
padding, so the frame was 106 columns wide at any terminal size. The same
shape appeared in both `/osint` screens as `min(110, max(80, width-8))` and
`min(104, max(70, width-6))`. A new `dialogWidth(termWidth, preferred, chrome)`
subtracts chrome from the terminal, treats the preferred width as a cap rather
than a floor, and keeps a 20-column absolute minimum. `OsintDialogCmp.View()`
gains the progressive-shedding pattern already used by `/help` and `/context`:
four leanness tiers measured with `lipgloss.Height` until one fits, dropping
prose while keeping the warning headline, the cost lines, the helper and mode
controls and the key hints. Every headline, subtitle and hint in the loadout
dialog now passes through `fitLine`, because a `.Width(w)` style wraps rather
than overflowing and each wrap cost a row on exactly the terminals with none to
spare. Both `/osint` screens are registered in `sizedDialogs` so the existing
screen-invariant suite covers them from here.

### Architecture Impact

No interface, provider or agent change. The invariant restated in code: chrome
is SUBTRACTED from the terminal, never added to a content size. The
`knownSmallOverflow` ratchet gains `/osint 60x10: 20`, `/osint 40x8: 26` and
`/osint-page 40x8: 11`, and `/context` drops from 19 to 18 at both small sizes.

### Why The Existing Suite Missed It

`TestNoDialogOverflowsTheWidth` renders through `screentest.Render`, whose grid
CLIPS over-wide lines exactly as a real terminal does — a property that package
asserts about itself deliberately. Clipping destroys the evidence before the
assertion runs: `WidestRow()` cannot exceed the terminal width, so the test
could not fail for this defect. The new `frame_fits_test.go` measures
`lipgloss.Width` on the string *before* it reaches any grid. This is the
vacuous-test failure mode the project's own standards warn about, found in a
test that had been passing quietly.

### Known Issues

**[medium]** Stranded frame lines on an Arch/CachyOS tester's terminal. (reported on v0.1.87, still open)
- Cause: Unknown. This release fixes a bug of the same class — over-wide dialog frames — and his screenshots include the `/context` screen, so it is now the leading hypothesis ahead of the earlier font/glyph-width theory.
- Remedy: Needs his terminal emulator, font, `$TERM`, terminal width, and whether a dialog was open. If v0.1.89 still strands lines for him, the cause is elsewhere.

**[low]** `/context` overflows terminals shorter than about 18 rows.
- Cause: Two dials, three section headings, four extras rows and a help line are structural; the fitter can only shrink the feature list.
- Remedy: Tracked by `knownSmallOverflow`, which fails if it gets worse OR better, so the figure cannot rot.

**[medium]** Old conversations are missing from the history list. (deferred to unscheduled)
- Cause: Unchanged from v0.1.85: the session store moved and the previous files were not migrated.
- Remedy: The old files remain in the old location. No migration exists.

**[low]** `TestExactLongPromptWrapsAtTerminalWidth` passes against a reverted fix. (deferred to unscheduled)
- Cause: Unchanged from v0.1.86: the test is vacuous with respect to `measuredRows()`.
- Remedy: Write a screen-driven regression test. Note that this release found a second vacuous test by the same reasoning; the class is worth a sweep.
