# A message that told people their connection was broken when it was fine — Plain Language

> Session record generated 2026-08-20

---

## What happened

The previous release made answers arrive all at once on the two slowest connection settings, because sending a reply word by word costs 27 times more data. That part works and the saving is real. What it broke was a warning message.

The program watches for a worrying silence. If nothing has come back after twelve seconds it says so, because on a shared or free AI service that usually means the service is cold and warming up. That warning made sense when answers always arrived word by word: the first word turning up was proof something was alive.

With the answer now arriving in one piece, nothing turns up until it is finished. So the program saw silence, decided the connection was in trouble, and said so on every single message - on a fast connection, with a healthy service. It was seen firing twice within one answer. The words it used were the damaging part: it told people their endpoint was warming up, which is a diagnosis, and it was the wrong one. Somebody would go looking for a broken connection that was never broken.

## Honest state of play

Done and tested: the two different messages, the short footer note, /context working while the AI is busy, and the corrected busy message. Thirty test packages pass and both the Debian and Arch packages were opened and checked.

Deliberately NOT changed: you still cannot switch model while the AI is working. Opening the model list is harmless, but choosing from it replaces the connection the running request is using. Press escape first, then switch - which is the safer order anyway.

Not fixed, and not caused by this work: one test about the sidebar fails when tests are run in a random order. It fails the same way on the previous release.

## Worst case if something is wrong

The wrong message was the harm, and it is now corrected. If the new one is also wrong in some situation nobody has hit yet, the cost is the same shape: somebody reads a confident sentence about their connection and acts on it. That is why both messages now say what they are actually based on, and why the slow-connection one names the setting responsible and how to change it.

## What changed for you

**The warning during a long wait**
- Before: Always said the service was probably warming up.
- After:  On the slow settings it says the quiet is expected and the whole answer is coming at once.
- Affects: some users

**What the footer shows**
- Before: Only a phase name and a counter.
- After:  Adds a short note on those settings so you can see the answer arrives in one piece.
- Affects: some users

**Changing tools while the AI is working**
- Before: Refused until it finished.
- After:  /context works while it is working; the change lands when the current answer ends.
- Affects: everyone

**Knowing how to stop it**
- Before: Nothing said that escape cancels.
- After:  The busy message now says escape cancels, and which commands still work.
- Affects: everyone

## What you can do now

- See an accurate explanation when the screen goes quiet, instead of being told your connection is struggling.
- Trim the tool list with /context while the AI is still working, so a model stuck in a loop can be reined in.
- Read in the busy message that escape cancels the current answer - it always did, but nothing said so.

## What is still missing

- **You cannot change model while the AI is working** — A model stuck in a loop has to be stopped with escape first, then swapped.
- **No screenshot of the new message yet** — You cannot see the corrected wording without running it on a slow-connection setting.
- **A sidebar test fails when tests run in random order** — Nothing for users; it makes the test suite less trustworthy for developers.

## Should you be concerned?

Not about this fix, which removes a false alarm and adds nothing risky.

Worth knowing: the previous release shipped that false alarm, so anyone who installed v0.1.108 and chose a slow connection setting was told every single message that their connection might be in trouble. Nothing was actually wrong with their connection, and nothing was damaged - but it was misleading, and misleading is the failure this project cares most about avoiding.

## Glossary

**Cold start** — A shared AI service that has been idle and takes longer than usual to answer the first question.

**Footer** — The single line at the bottom of the screen showing what the program is doing.

**Loadout** — Which tools and instructions are switched on, changed with /context.

**Escape** — The key that cancels the answer the AI is currently producing.
