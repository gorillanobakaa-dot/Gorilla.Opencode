# Gorilla Opencode v0.1.117: a window of nothing but a zero is not a window

One fix. The usage panel was drawing a full green bar for an allowance that does
not exist.

Found the way the last three were found: the owner looked at his own screen,
compared it with another program, and asked a plain question. *"What's the
secondary limit all about? In Codex you do not get a secondary limit, only a
MONTHLY limit."*

---

## Plain-language track

### The bar that was measuring nothing

Sign in with a ChatGPT account, type `/usage`, and you got two bars: a monthly
limit reading 16% left, and underneath it a **"Secondary usage limit" at 100%,
three bananas, full green**.

There is no secondary limit on a free plan. That bar was measuring nothing.

### Where it came from

OpenAI's server does send a "secondary" figure on every reply. On a free account
it sends a bare **zero**, with no window length and no reset time attached. That
is the server's way of saying *not applicable here*.

Here is the reading taken off the owner's own account, exactly as stored:

```
primary  : used 84%,  window 30 days,  resets 15 September   <- a real limit
secondary: used 0%,   no window,       no reset time         <- nothing at all
```

Our code took that zero at face value. Zero used means a hundred left, so it drew
a hundred left: a full bar, in green, with the cheerful message.

**OpenAI's own program throws that reading away.** It only counts a limit as real
if at least one of the three things says something. A zero with nothing attached
fails all three, so Codex never shows it. That is why the owner's two screens
disagreed.

### Why this is worse than showing nothing

A blank would have been honest. A confident full green bar is not.

This project has a rule written into the file that reads balances: **unknown and
plenty-left must never look alike.** A full bar for an allowance that does not
exist is the bad half of exactly that pair. Somebody could look at that screen
and believe they had a second pot of credit in reserve.

### Fixed, using their guard rather than one of ours

The rule is now the same as OpenAI's own client: a limit is real if it has been
used at all, **or** declares how long its window is, **or** says when it resets.
A bare zero is discarded.

Both directions are tested, because getting it wrong the other way is just as
bad. A limit reading zero used that **does** carry a window or a reset time is a
genuine untouched allowance, and it still shows.

### A note on the two numbers disagreeing

Our panel said 16% and Codex said 18% at the same moment. That one is not a
fault. Both read the same monthly pot, but each updates from **its own** replies,
and the owner had spent about 2% through this program since Codex last looked.
Ours was the fresher figure.

## Developer track

### `internal/auth/chatgpt_quota.go`

`parseWindow` returned a `*ChatGPTWindow` whenever the `-used-percent` header was
present, regardless of the other two. On a free plan the backend sends:

```
x-codex-secondary-used-percent: 0
(no x-codex-secondary-window-minutes)
(no x-codex-secondary-reset-at)
```

`Remaining()` then computed `(100-0)/100 = 1.0`, `Label(true)` fell through
`durationWord(0) == ""` to the `secondary usage` fallback, and the panel rendered
a full-scale bar titled "Secondary usage limit Remaining".

The guard is ported verbatim in intent from
`codex-rs/codex-api/src/rate_limits.rs`, `parse_rate_limit_window`:

```rust
let has_data = used_percent != 0.0
    || window_minutes.is_some_and(|minutes| minutes != 0)
    || resets_at.is_some();
has_data.then_some(RateLimitWindow { ... })
```

Go equivalent, after reading all three headers:

```go
if used == 0 && minutes == 0 && reset == 0 {
    return nil
}
```

Ported rather than invented, on the same principle as `Label()` and
`durationWord()` before it: this backend is undocumented, and OpenAI's own client
is the only authority on what its headers mean.

### Tests

| Test | Asserts |
|---|---|
| `TestAWindowOfNothingButZeroIsNotAWindow` | a bare-zero secondary is dropped, with the real monthly primary kept |
| `TestAnUntouchedButRealWindowSurvives` | zero used WITH a window, or WITH a reset, still renders |
| `TestOnlyAnEmptySecondaryMeansNoReading` | a response carrying only the empty secondary parses to nil, so "no meter" stays distinct from "meter reads full" |

Checked non-vacuously: removing the guard reproduces v0.1.116 and fails two of
the three, quoting the phantom window.

### Also

The stale reading cached at `~/.config/gorilla-opencode/chatgpt-quota.json` on
the development machine had the phantom secondary in it, so it was cleared by
hand. Any user with the same stale file sees the bar disappear on their next
request, when the file is rewritten from fresh headers. No migration ships,
because the file is a cache with a one-request lifetime.
