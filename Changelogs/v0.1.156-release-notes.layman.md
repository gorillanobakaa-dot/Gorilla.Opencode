# Gorilla OpenCode v0.1.156: the toolbox really inside the Windows program, files listed with owner, date and permissions, and a proper archive action

**Date:** 2026-10-27

---

## Why this release exists

Three things went wrong with version 0.1.155, and this version fixes all three.

1. **The Windows program was missing its toolbox.** 0.1.155 was supposed to
   carry seven helper programs inside the one Windows file, so the AI can use
   them even on a computer that has none of them installed. The file that was
   published did not contain them. The reason was in the tool that builds the
   releases, not in the program: it never passed the switch that puts the
   helpers in, and the clean copy of the source it builds from does not hold
   the helpers at all (they are kept out of the source repository on purpose,
   because they are 162 MB). Nobody noticed, because the program works without
   them; it just has fewer tools.
2. **"List all your files and their attributes"** got only half an answer. The
   AI listed read-only and hidden flags and nothing else. Owner, creation date
   and permissions needed a separate question per file, and the AI never asked
   them.
3. **"Archive all the files in the working folder"** went badly. The AI wrote
   its own small program to make a zip, saved the zip inside the folder it was
   packing (so the archive sits among the files it contains), and asked you
   nothing about format, compression or where to put it.

## What you will notice on Windows

### The toolbox is there

The Windows program now contains the seven helpers: GNU-style commands
(coreutils: `ls`, `sort`, `wc` and about a hundred more), `ast-grep` (search
code by its structure), `difft` (compare files by meaning), `hyperfine` (time
commands), `ninja` (a build tool), `sd` (find and replace) and `pfind` (fast
file search). Each one is checked against a fingerprint written into the program
before it is ever run; a changed helper is refused. They are unpacked the first
time they are needed, into a private folder of your account.

The build tool now refuses to make a Windows release if any helper is missing
or is not the exact file expected, and it reads back from the finished program
that the toolbox switch is really in it. The same check ran on the file you
download.

7-Zip is not one of the seven. It never was; the 0.1.155 notes listed it as not
built yet. For archives this release uses something Windows already has (see
below).

### Listing files with all their details

Ask *"list all the files here and their attributes"* and the AI now gets, for
every file and folder, in one step:

- the attributes (read-only, hidden, system, archive and the rest),
- the owner (the Windows account the file belongs to),
- when it was created,
- the permissions: who may read, change or fully control it, and whether that
  comes from the folder above,
- any hidden extra data attached to the file, and the **Mark of the Web**:
  Windows' note that a file came from the internet, with the address it came
  from when Windows recorded one.

The AI is told to say once what is the same for every file (usually the
permissions) instead of repeating it a hundred times.

### Making an archive

Ask *"archive all the files in this folder"* and the AI now uses one action
made for it:

- **Formats:** zip (the default), 7z or tar.xz.
- **Compression level:** 0 (no compression, fastest) to 9 (smallest, slowest);
  the default is 6, what 7-Zip calls "normal".
- **Password:** for zip, encrypted with AES-256. 7z and tar.xz cannot take a
  password here; the AI is told so and offers zip instead.
- **Where it goes:** next to the folder, never inside it. A folder called
  `work` becomes `work-20261027-213000.zip` beside it. You can name another
  place, but not one inside the folder being packed, and an existing file is
  never overwritten.

Before anything is written, you see what will be packed (how many files, how
big) and where it will go, and you are asked. Afterwards the AI tells you which
defaults it used and what else you could have chosen.

The zip without a password is made by the program itself. 7z, tar.xz and the
password zip are made by `tar.exe`, which is part of Windows 10 (since 2018)
and Windows 11, from the Windows folder itself, never a program of the same name
found elsewhere. Nothing is downloaded.

## What changes for Linux and Mac users

The list with details shows owner, group and permissions (the `rwx` letters).
Linux does not record when a file was created in a way this program reads, so
that line is missing there.

Archiving as zip works everywhere. 7z, tar.xz and password zip need `bsdtar`:
on Debian and Ubuntu, `sudo apt install libarchive-tools`. tar.xz also works
with the ordinary `tar` most Linux systems already have.

## How it was checked

The owner's own two sentences were typed into this version, unattended, with
ChatGPT's GPT-6-Luna, in a test folder with real files (hidden ones, read-only
ones, and two marked as downloaded from the internet), and the result was
judged from the disk and the answer:

- *"list all your files and their attributes in the working folder"*: one step,
  with details. The answer named the attributes, the owner, the creation time,
  the permissions and the two downloaded files. Right in both runs.
- *"archive all the files in the working folder"*: one step, a zip next to the
  folder and nothing inside it; the answer named the defaults (zip, level 6, no
  password) and the other choices (7z, tar.xz, another level, a password,
  another place). Right in both runs.

The first try of each was not fully right: the answers left out the creation
date and the other choices, although the program had given them to the AI. The
program now ends those two results with a short line telling the AI what to
pass on; after that change both runs of both requests were right.

## Deliberately not done

- No 7-Zip inside the program. Windows' own `tar.exe` already makes 7z files;
  it cannot put a password on them, which is the one thing 7-Zip would add.
- No way to change permissions or owners from the files tool yet; it shows them.
- No unpacking action; the existing archive tool lists what is inside an
  archive and can pull single files out.

## Privacy and security

Nothing new talks to the internet. The password for a zip is handed to Windows'
`tar.exe` on its command line, the only way that program takes one without a
person typing it: while the archive is being written, another program running
under your own account could read it. The password is never shown in the
question you are asked or in the answer.

The permissions list shows account names and, where Windows has no name for an
account, its long number (a SID). That is information about your computer; it
stays in your conversation like everything else the AI reads.

## How to install

Download the file for your system from this page, check it against
`SHA256SUMS-v0.1.156.txt`, and replace the old one. On Windows the new
`gorilla-opencode.exe` replaces the old file; your settings and sign-ins stay.

## If something goes wrong

- *"tar.exe is missing"*: your Windows is older than Windows 10 version 1803.
  Zip without a password still works.
- *"refused: ... is inside ..."*: you asked for the archive inside the folder
  it packs. Leave the place out, and it goes next to the folder.
- *"refused: ... already exists"*: pick another name; nothing was overwritten.
- If the toolbox seems missing, run `gorilla-opencode.exe --version`; it should
  print `v0.1.156`. The checksum file on this page tells you whether your
  download is the published one.

## Bottom line

The Windows program now really has its toolbox. Ask for all the details of the
files in a folder and you get them in one go. Ask for an archive and you get a
zip next to the folder, with a question first and a word on what else you could
have chosen.
