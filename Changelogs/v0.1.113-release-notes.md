# Gorilla Opencode v0.1.113 — the menu explains itself

Released 21 August 2026. Replaces v0.1.112, which shipped earlier the same day.

Two tracks below, both complete. Neither is a summary of the other.

---

## Plain-language track

Small release, entirely about the first screen anybody sees.

### The provider menu had a rule nobody could see

The list of providers was ordered — free sign-ins first, then your own machine,
then the ones needing a key. A real rule. But Google's three routes sat at
positions 1, 3 and 9 with unrelated providers in between, so from the outside it
looked like no order at all. The owner, reading his own screen: *"if there is a
logic in the way they are displayed I can't see it."*

An order nobody can work out is not an order.

Now the easiest ways in come first, and companies stay together:

1. **Google Antigravity** — Gmail sign-in, no key, no card
2. **Google Code Assist** — Gmail sign-in, no key, no card
3. **Google Gemini** — a free API key
4. **ChatGPT sign-in** — works on the free plan, no key
5. **NVIDIA NIM** — free key, about a hundred models
6. then Ollama, Cloudflare, Groq, Cerebras — everything else that costs nothing
7. then OpenRouter, Anthropic, OpenAI, xAI, DeepSeek — the ones needing a card

The three Google rows now say "Google" in their names. Grouping by position only
helps somebody who already knows Antigravity is a Google product, and most
people do not.

### The Gemini key row now tells you how to get one

It used to name the key and assume you already had one — which is backwards,
because a person without a key is exactly who that row is for.

It now says: **free, no card needed, make one at aistudio.google.com/apikey with
any Google account, and leave billing switched off.**

The warning under it was rewritten too. It used to say free keys are "heavily
rate-limited" and push you towards the sign-in rows, which reads as *do not
bother*. What actually happens is that one busy turn uses up a per-minute
allowance, and the failure arrives as `HTTP 429` or a bare "unknown error" — so
it looks like a broken key, and people give up on a key that is fine.

The row now names that, and says the sign-in rows spend a **separate**
allowance. That turns one dead end into two pools you can alternate between.

### `/update` says what it threw away

When the program asks a company for its model list, it removes the entries that
are not chat models — speech, image, embedding and safety models. Picking one of
those returns an error that looks like a broken key.

That filter is a list of words, so it can be too greedy, and until now that was
invisible: `OpenAI 5 usable` reads as a small catalogue, not as seventy-three
models thrown away by mistake. The report now shows both numbers:

```
OpenAI 5 usable, 73 skipped
```

Nothing is printed when nothing was skipped.

This exists because nobody here has a paid key for Anthropic, OpenAI or
DeepSeek, so those three could not be tested against the real thing. The honest
answer to "I cannot check this" is to make the failure obvious to whoever can,
instead of claiming it works.

### Housekeeping

The agent instruction file, the roadmap and the internal bug notes are no longer
published to GitHub. They are working notes for whoever is at the keyboard, not
documentation, and links that pointed at them are plain text now so nothing
leads to a missing page. The Arch package's checksum was regenerated for the
v0.1.112 source archive.

## Developer track

### Picker ordering (`cmd/provider_portal.go`)

The order was an accident of how the slice literal happened to be written. It
encoded a real rule and communicated none of it. Rewritten into five commented
groups — Google, ChatGPT, NVIDIA, other-free, paid — with the reasoning above
them.

Pinned by `TestPortalRowOrder`: the Google block must be contiguous and start at
index 0, `chatgpt` and `nvidia-nim` must follow it in that order, and **no paid
provider may sort above a free one**. `TestGoogleRowsSayGoogle` asserts the three
Google rows carry "Google" in their names.

An ordering that lives only in the order of a literal is one careless insert
from being scrambled with nothing failing — which is what happened here.

Row names: `Antigravity free tier` → `Google Antigravity`, and `Google - Code
Assist free tier` → `Google Code Assist`.

### `catalogueNote` (`internal/tui/tui.go`)

The per-provider line of the `/update` report was built inline inside a network
callback, so it could not be tested. Extracted to `catalogueNote(res)` and
covered by three tests: the skipped count appears when non-zero, nothing is
added when it is zero, and retired ids are still named.

`CatalogueResult.Skipped` was already being counted by the fetch and simply not
reported.

### Gemini row copy

`What`, `Warning` and `InputPrompt` rewritten. Verified against the owner's own
AI Studio console the same day: **Billing Tier reads "Free tier"**, billing never
set up, one key created 13 July 2026.

### Not in this release, but established while working on it

Two findings, both measured, both recorded in the brain:

- **Google has blocked the Gemini CLI's OAuth client for Code Assist for
  individuals.** A live probe of `cloudcode-pa.googleapis.com/v1internal:loadCodeAssist`
  with the stored credential returns HTTP 200 with `ineligibleTiers[0].reasonCode
  = "UNSUPPORTED_CLIENT"`. The owner's standalone `gemini-cli` 0.52.0 fails at
  sign-in with that message.
- **This program is not affected**, because of a fix made on 2026-08-03: it sends
  a `User-Agent` whose product token is `antigravity` on the onboarding calls
  only, and Google then allows the free tier and provisions a managed project.
  Measured both ways with the same token on 2026-08-21: default agent → free tier
  refused; the app's agent → free tier eligible, project present.

The second is why nothing in this release touches the Code Assist row. An earlier
draft of this work proposed removing it, on the strength of a probe that used the
wrong `User-Agent` and therefore measured a different client.
