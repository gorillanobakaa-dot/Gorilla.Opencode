# Gorilla Opencode v0.1.112 — the model lists stop being a lie

Released 21 August 2026. Replaces v0.1.111.

Two tracks below, both complete. Neither is a summary of the other.

---

## Plain-language track

### The thing that started this

Somebody picked DeepSeek R1 from the model list and got this back:

```
POST "https://api.groq.com/openai/v1/chat/completions": 400 Bad Request
{"message":"The model `deepseek-r1-distill-llama-70b` has been decommissioned
and is no longer supported."}
```

They picked another one. Same thing. `qwen-qwq-32b`, also decommissioned.

Two models, two failures, three minutes apart. Both had been sitting in the
menu looking perfectly selectable.

### Why they were there

The program carried a hand-typed list of every model each company offers,
written into the program itself. Companies retire models constantly. Nothing in
the program ever checked. So the list quietly stopped being true, and nothing
announced it — a retired model does not warn you, it sits in the menu and fails
the moment you choose it.

Checked against the companies on 21 August 2026, **sixteen of those entries were
dead**:

| Company | Dead entries | The most recent |
|---|---|---|
| Groq | **all five** | `llama-3.3-70b-versatile`, shut down 16 August — five days before this was written |
| Anthropic | **all seven** | the last of them retired 15 June |
| xAI | **all four** | the whole grok-3 line, superseded by grok-4 |

Worse than the menu: those same dead names were the **defaults**. A new user
who pasted a Groq key had every part of the program pointed at a model Groq had
already switched off.

### What changed

**The program now asks.** The moment you paste a key, it asks that company what
it actually serves today, and remembers the answer. It asks again when you run
`/update`, and it tells you what disappeared:

```
Groq 41 usable (+3, -5) — retired: llama-3.3-70b-versatile, qwen-qwq-32b, …
```

A model that has been switched off now leaves the menu instead of waiting there
to fail. Six companies work this way now: Anthropic, OpenAI, Groq, Cerebras,
xAI and DeepSeek.

The defaults changed with it. Nothing in the program names a specific model any
more — it asks the list. A default can now only ever be something the company
really serves.

### Four companies removed entirely

Microsoft Azure, GitHub Copilot, Amazon Bedrock and Google Cloud are gone from
the menu, along with the code that spoke to them.

Every one of them needs a company account, a paid subscription or a cloud
project with billing switched on. This program is built for people on old
laptops, metered connections and no credit card. Thirty entries nobody in that
position could ever reach were taking up a menu whose whole problem is that it
is too long to read.

Nothing was thrown away — the files are kept in the quarantine folder, exactly
as the house rule requires.

### The list you actually see

Menu entries built into the download: **369 before, 45 after.**

The big cut is OpenRouter. It shipped with 279 models compiled in, of which
**18 cost nothing and 261 charge money** — 94% of the largest block in the menu
unreachable without a card. The download now carries the free ones. Anyone with
an OpenRouter key runs `/update` and gets the full list from the network, so
nothing is lost; it just stops being in everybody's download.

### One row per model

The same model is often reachable through several companies. GPT-OSS 120B is
served by NVIDIA, Groq, Cerebras and OpenRouter — four rows that look identical
and are not, because they spend different allowances.

Searching now shows **one row**, on the route with the most usable free
allowance, naming the others: *"also on groq, openrouter"*.

The order comes from a measurement, not a preference. OpenRouter's free tier is
**50 requests a day** without a card. NVIDIA's limit is roughly **40 a minute**.
A per-minute limit slows you down; a per-day limit sends you away until
tomorrow. That difference is the entire ranking.

### `/purge` stops overstating

`/purge` clears downloaded model lists. It used to report "purged 284 models"
when 279 of those shipped inside the program and came back the moment you
restarted. The number was true for one session and nothing said so.

It now says: *"cleared 284 models … 279 of them ship with the app and come back
when you restart."*

### Is the download smaller?

A little. **50.72 MB → 49.35 MB**, about 1.4 MB. On the 8 KB/s connections this
is built for, roughly three minutes off every download.

Almost none of that is the model lists — those are tiny. It is the four removed
companies taking their supporting code with them.

## Developer track

### What was actually wrong

Six providers shipped `map[ModelID]Model` catalogues compiled into the binary.
Presence in the picker was decided by a Go file, so upstream retirements were
invisible until a user hit `400 model_decommissioned` at request time. Verified
against the providers on 2026-08-21: Groq 5/5 dead, Anthropic 7/7 dead (all
`-latest` aliases resolve to retired models and 404), xAI 4/4 dead.

The defaults were the sharper edge. `config.setDefaultModelForAgent`,
`setProviderDefaults` and `cmd/provider_portal.go` each named constants —
`Llama3_3_70BVersatile`, `Claude37Sonnet`, `GPT41`, `XAIGrok3Beta` — so a first
run auto-assigned agents to retired models.

`internal/llm/models/openrouter.go` had recorded the general form of this in
August 2026 for one provider: *"that is what a hand-maintained mirror of someone
else's catalogue does: it does not fail loudly when upstream moves, it just
quietly stops being true."* The other ten providers kept the shape.

### The change

**`internal/llm/models/catalogue_fetch.go`** (new). `LiveCatalogues` maps
provider → `{URL, auth style, curated Prefer order, Skip patterns, FreeTier}`.
`FetchProviderCatalogue` **replaces** — never merges — that provider's registry
entries from the provider's own listing, caches to
`CacheBase()/<provider>-models.json`, and reports `Added`/`Removed`.

Merging would keep a retired model, which is the failure the file exists to end;
the replace is asserted by a test that fails if it is weakened.

Three wiring points:

| When | Where | Note |
|---|---|---|
| On connect | `cmd/provider_portal.go` | The moment a key first exists. A failed listing returns an error that says the key was kept, so `/update` can retry. |
| On `/update` | `internal/tui/tui.go` | Retired ids are **named** in the report. |
| At startup | `internal/config/config.go` | `LoadCachedCatalogues` — disk only, never network, and ordered **before** the default-model ladder, which now queries the registry. |

Auth differs by provider and is load-bearing: Anthropic takes `x-api-key` plus
`anthropic-version`, everything else a bearer token. Anthropic's listing also
publishes `max_input_tokens`/`max_tokens`, so its context windows are the
provider's own figures rather than curated ones. Everything else falls back to
bundled metadata, then a conservative 32K floor — too low costs an early
compaction, too high sends a request the provider rejects and the user cannot
tell that from a broken key.

Non-chat ids are filtered at the source (`Skip` per provider plus the shared
`cannotChat` list): OpenAI's listing is mostly whisper/tts/dall-e/embeddings,
and a safety classifier answers a chat request with a bare 400 that reads as a
broken key.

`PreferredCatalogueModel` supplies defaults from a curated `Prefer` order, never
list position — NVIDIA returns its catalogue in id order, which once made
`01-ai/yi-large` the default purely for starting with a digit.

### Removed

`internal/llm/models/{azure,copilot,vertexai}.go`,
`internal/llm/provider/{azure,bedrock,copilot,vertexai}.go`, the Bedrock entry
in `models.go`, `hasAWSCredentials`, `hasVertexAICredentials`,
`hasCopilotCredentials`, `LoadGitHubToken`, and the `gcp-custom` portal row.
Quarantined to
`/home/gorilla/Agents.Work.Trash/gorilla-opencode-provider-cull-26-08-21-11-58/`.

`go mod tidy` then dropped 8 modules — the whole Azure SDK chain (`azidentity`,
`azcore`, `internal`, `microsoft-authentication-library-for-go`, `golang-jwt`).

### Other fixes in this release

- **Footer notices reach the transcript.** `util.InfoMsg.Echo` was opt-in and
  almost nothing opted in, so oversized notices existed only as a truncation.
  `statusCmp.InfoBudget()` now exposes the status bar's own truncation budget
  (extracted from `View()`, one definition), and `appModel.shouldEchoNotice`
  echoes anything wider than it. Echoed lines are coloured by severity.
- **`/purge` was blind to local endpoints.** It filtered by provider on
  `{OpenRouter, Antigravity}`, so ~100 NVIDIA NIM models survived every purge.
  Now purges `ProviderLocal` and the fetched catalogues too, with a keep-set so
  the model an agent is currently on cannot be blanked.
- **`/purge` counted honestly.** `RemovedCompiled` separates entries that ship
  in the binary and return on the next launch.
- **Duplicate collapse.** `internal/tui/components/dialog/duplicates.go`:
  fingerprint by api id with vendor prefix and `:free`/`:nitro` suffix stripped;
  `providerQuotaRank` decides the survivor. The ranking is deliberately coarse —
  `internal/config/ratelimit.go` settled in this estate that free-tier limits are
  "undocumented, variable, and load/time-of-day dependent", so a table of exact
  numbers would be wrong within weeks and wrong silently.
- **`verify.go`'s endpoint table is derived** from `LiveCatalogues` rather than
  being a second copy, with a test that fails on drift.
- **A latent panic**: `statusCmp.chrome()`/`model()` dereferenced
  `config.Get()` unconditionally and crashed if the bar rendered before
  `config.Load`.

### Verification

- Live probe through the real code path, no key: all six endpoints returned
  `refused the key (HTTP 401/403)`, confirming URLs, auth headers and the error
  path against reality.
- 11 new tests in `catalogue_fetch_test.go` against `httptest` stubs; 5 in
  `duplicates_test.go`; new purge and echo tests.
- **Non-vacuity proven**: reverting `registerCatalogue` to merge makes
  `TestFetchDropsModelsTheProviderNoLongerServes` fail on both assertions, then
  pass again when restored.
- `go build ./...`, `go vet ./...`, `go test ./...` clean.
