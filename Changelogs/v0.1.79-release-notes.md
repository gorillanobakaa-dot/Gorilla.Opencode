# gorilla-opencode v0.1.79 — release notes

Released 2026-08-09. One fix, shipped immediately after v0.1.78.

## Plain-language version

**lynx is now a hard requirement rather than a suggestion.**

v0.1.78 said the package *recommends* lynx — the small text browser that makes
web search work with no setup. That sounded polite and was wrong.

`apt` honours a recommendation. **gdebi does not** — the graphical installer you
get by right-clicking a `.deb`, which is how most people who do not live in a
terminal install software. Its source never mentions the field. `dpkg -i`
resolves nothing at all.

So the two friendliest ways to install would have skipped the package that makes
the headline feature work, and web search would have looked broken to exactly
the people it was built for. A promise that only holds when you install the
expert way is not a promise.

It is 641 KB, and it now arrives on every install path:

```sh
sudo apt install ./Compiled.Builds/gorilla-opencode_0.1.79_amd64.deb
# or right-click the .deb → Open With → GDebi
```

`dpkg -i` will now refuse until lynx is present, which is the correct behaviour:
loud, rather than quietly shipping something that cannot do what it says.

## Technical

`Recommends: lynx` → `Depends: lynx` in the package control block. Verified by
reading gdebi's own source: no occurrence of "Recommends" anywhere in it.

`apt-config` confirms apt's default is `APT::Install-Recommends "true"`, which is
why the difference was invisible when tested with apt alone — the one tool that
honours the weaker field.

## Verification

- `dpkg-deb -f` on the built package reports `Depends: lynx` and no `Recommends`.
- Installed over v0.1.78 with `apt`; binary and dpkg agree at 0.1.79.

**Not verified:** the gdebi path itself was not exercised — the conclusion comes
from reading its source rather than watching it install. lynx was already present
on this machine, so a clean-machine gdebi install remains untested.
