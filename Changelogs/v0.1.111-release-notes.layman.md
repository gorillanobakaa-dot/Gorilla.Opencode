# The meter got its colours back, and a 204 KB file that could eat 420 MB of memory — Plain Language

> Session record generated 2026-08-20

---

## What happened

Two days ago a tidy-up pass swept through 81 files replacing anything that "looked like a box character" with plain keyboard symbols. The request behind it had been narrow: fix some misaligned lines in the instructions given to the AI. The sweep went far past that, and one of the things it flattened was the quota meter - the coloured bar that shows how much of your free allowance is left. The solid block became a row of `#`, and a meter that reads as an object became a line that reads as text. Two days of deliberate design, undone by a pattern match.

It is back, and this time it is nailed down.

Then, because that raised a fair question about what else a well-meaning pass might have left behind, every Python file in the project was audited. That found something worse than a cosmetic loss: a compression bomb. A 204 KB archive could be made to expand into 200 MB of data and 420 MB of memory. On the old, weak laptops this program is built for, that is a swap storm or an out-of-memory kill.

And six screenshots deleted three days ago had been showing as broken images on the public gallery page ever since. Restored.

## Honest state of play

Fixed and measured: the compression bomb (420.7 MB down to 148.9 MB peak memory, measured on a real bomb file), four files left open without being closed, six restored screenshots, and the meter.

Worth being plain about: **the AI cannot reach the compression bomb.** The archive-searching option is off by default and the program never offers it to the model. Only a person running the search tool by hand with `--search-zip` could hit it. It was fixed anyway, because the standalone copy of that tool on this machine is exactly that person's tool and had the identical hole.

Two bugs in the fix itself were caught by testing it rather than reading it. The budget charged for data it was offered instead of data it actually read, which cut a perfectly normal archive off after 3 MB. And the warning message printed the wrong limit - naming a number the run never used. A message that lies about its own cause is worse than no message.

Not fixed, deliberately: one script that installs system packages still has no time limit on it. It runs under `sudo`, which may simply be waiting for you to type a password - that is a human thinking, not a hang - and killing a package installation halfway through leaves the system's package database broken. An unlimited wait you can interrupt yourself is the right answer there.

## Worst case if something is wrong

The new memory limit could stop reading a genuinely large archive before the end. If it does, **it says so out loud** - it names the file and the limit that stopped it, and tells you the environment variable that raises or removes the cap. Truncating quietly would make "found nothing" and "I stopped looking" look identical, which is the failure this project cares most about avoiding.

## What changed for you

**The quota meter**
- Before: `[####......]` - flat, reads as text.
- Now: `[████░░░░░░]` - a solid body carrying the red-to-green gradient, one colour per cell.
- The colour maths was never damaged. Only two characters had been swapped, and that was enough to destroy the object.

**Searching inside archives (by hand)**
- Before: no limit. A small archive could fill your memory.
- Now: 256 MB by default, shared across the whole archive rather than per file inside it - because ten thousand small files add up the same as one huge one.
- `PFIND_MAX_DECOMPRESSED_MB` changes it. Set it to `0` to turn the cap off if you mean it.

**The gallery page**
- Before: four broken images since 17 August.
- Now: all six restored, recovered exactly from history.

**Files**
- Four places opened a file and trusted the language to close it. One of those was a *write*, which can exit with data still sitting in a buffer - and a half-written catalogue looks exactly like a complete one.

## The part that is a rule, not a fix

The meter is now protected by three tests that fail loudly if anyone flattens it again: one for the solid block, one that checks the gradient still runs red to green *and* that the cells are actually different colours, and one that holds all nine banana rungs word for word.

A future change can still alter any of it - it just has to delete the lock on purpose and say why. An accident cannot. Only a decision can.
