# Gorilla OpenCode v0.1.69 — the provider menu finds your setup whatever you named it

*Track 1 of 2 — written for anyone. The developer track follows below.*

## Why This Release Exists

The startup menu asked for an NVIDIA NIM API key that was **already saved**. The
NVIDIA row showed as not set up, while Groq, Cerebras and xAI all showed
`(ready)`. Retyping the key would have appeared to fix it — and then it would
have asked again on the next launch, forever.

The key was never lost. The menu simply could not see it.

**The cause: the app looked for your NVIDIA setup by NAME.** It searched for an
entry called exactly `NVIDIA NIM`. If you had named yours anything else — this
user's is `Gorilla.FREE.NVIDIA.NIM` — the menu found nothing and concluded you
had never set it up.

That is the wrong question to ask. A connection is identified by **where it
points**, not by what you called it. Both are now matched by address.

## The same mistake had a second, quieter symptom

Because choosing NVIDIA from the menu also wrote back the app's own fixed name,
picking it created a **second** entry beside yours, both aimed at the same
address. Two connections to one address fight over which one serves the models,
and the loser's model list is emptied — which is how a config ended up with two
NVIDIA entries and **zero** usable models between them.

Re-picking a provider now updates your existing entry instead of adding a twin,
and carries your saved key across, so pressing Enter on the row can never wipe a
working credential.

## What You'll Actually Notice

- Your NVIDIA connection shows `(ready)` again, under whatever name you gave it.
- The menu stops asking for a key you already provided.
- Choosing NVIDIA or Ollama edits your existing entry rather than duplicating it.

## Decisions & Why

**Matched by address, not name, on purpose.** People rename things; that is
normal and should not break recognition. The app's own name is now only a
*default* used when you have no entry for that address at all.

**A keyed entry beats a keyless one.** If two entries somehow point at the same
address, the one holding an actual key wins, so a leftover blank duplicate cannot
mask a working key.

**If this was already broken for you, it repairs itself.** No action needed —
the menu will simply recognise your existing connection on the next launch.

## Risks, Backup & Recovery

Small, contained change to the startup menu's NVIDIA and Ollama rows. API-key
providers (Anthropic, OpenAI, Gemini, Groq, Cerebras, OpenRouter, xAI) and both
Google sign-in options are untouched. No settings are rewritten on startup; the
previous package remains on the releases page.

## How To Install

```sh
sha256sum -c checksums.txt
sudo dpkg -i gorilla-opencode_0.1.69_amd64.deb
gorilla-opencode --version && dpkg -l gorilla-opencode | tail -1
```

Both must say `0.1.69`. Quit any running copy first.

## Common Questions

**Did I lose my API key?** No. It was in your settings the whole time; only the
menu's recognition was broken.

**Do I need to rename my connection to match?** No — that is precisely what this
release removes the need for.

**I have two NVIDIA entries. Will this merge them?** It will stop *creating* more
and will always work with the keyed one. Removing a leftover duplicate is still a
manual edit.

## Bottom Line

The startup menu recognises your providers by where they point instead of what
you named them, so it stops asking for keys you already gave it.

# v0.1.69 — resolve local endpoints by baseURL, not by name

*Track 2 of 2 — for developers.*

## Architecture & Footprint

One file, `cmd/provider_portal.go`, plus `cmd/provider_portal_endpoint_name_test.go`
(four tests). `gofmt` and `go vet` clean; full suite green.

## The defect

`providerPortalRows()` resolved the NIM endpoint with

```go
endpoint := func(name string) (config.LocalEndpoint, bool) {
    for _, e := range cfg.LocalEndpoints {
        if e.Name == name && !e.Disabled { return e, true }
    }
    ...
}
```

called as `endpoint(nimEndpointName)` where `nimEndpointName == "NVIDIA NIM"`. A
keyed endpoint at `https://integrate.api.nvidia.com/v1` named anything else was
invisible: `Configured: false`, `NeedsInput: true`, so the portal demanded the
key on every launch. `Active` had the same flaw, comparing
`models.LocalEndpointFor(curModel)` against the constant.

**Note the asymmetry that hid this.** Model *registration*
(`registerLocalEndpoints`, `config.go`) already de-duplicates and registers **by
baseURL**, name-agnostic — so the endpoint worked perfectly for inference while
the portal reported it missing. The two halves of the system disagreed about what
identifies an endpoint.

`applyLocalEndpoint(name, baseURL, key)` had the mirror-image bug: it looked up
the stored key by `e.Name == name` and passed the fixed name to
`UpsertLocalEndpoint`, which matches by Name — so selecting NIM beside a
user-named entry **created a second endpoint on the same baseURL**. That is the
documented "last one wins" route-stealing trap, and it is how a live config ended
up holding `Gorilla.FREE.NVIDIA.NIM` and `NVIDIA NIM` with zero registered models
each.

## The fix

`endpointFor(baseURL)` scans by `e.BaseURL`, preferring an entry with a non-empty
`APIKey` so a blank duplicate cannot mask a working one. `nimName` / `ollamaName`
resolve to the user's actual name (falling back to the constant when no entry
exists) and are used for the `Active` comparison.

`applyLocalEndpoint` adopts the existing entry's `Name` for that baseURL before
upserting, and inherits its `APIKey` when none was supplied — so an Enter on the
row is idempotent rather than destructive. The name constants are now documented
as defaults for the no-entry case only.

## Verification

Non-vacuous: restoring the name-based lookup produces

```
--- FAIL: TestAUserNamedNimEndpointCountsAsConfigured
    a keyed NIM endpoint under the user's own name is not recognised
--- FAIL: TestApplyingReusesTheUsersEndpointInsteadOfCreatingATwin
    registered under "NVIDIA NIM" instead of the user's "Gorilla.FREE.NVIDIA.NIM"
    the stored key was not carried over (got "")
    expected exactly one endpoint at https://integrate.api.nvidia.com/v1
      named "Gorilla.FREE.NVIDIA.NIM", found [Gorilla.FREE.NVIDIA.NIM NVIDIA NIM]
```

— the duplicate reproducing on demand. Two further tests cover the negative case
(no endpoint at that URL ⇒ not configured) and a keyless entry ⇒ not configured,
so the positive assertions cannot pass vacuously. Assertions read the config back
from disk rather than trusting in-memory state, and `TestMain` runs under
`configtest.Isolate`.

## Security Posture

Unchanged. No new credentials, endpoints or dependencies; keys are still masked
in all diagnostic output.

## Deployment & Verification

Tag at `main`, build with the version ldflag, package, extract the `.deb` and
confirm the inner binary version and this release's notes. Publish non-draft,
download the assets back, verify checksums, install from the downloaded package,
and confirm `main` is at the tag.
