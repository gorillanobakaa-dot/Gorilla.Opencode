# gorilla-opencode v0.1.78 — release notes

Released 2026-08-09.

Twenty commits. Web search that needs no setup, a model list that tells you the
truth about what things cost and what they are good for, and a personal
shortlist so you never scroll a catalogue of hundreds again.

---

## Plain-language version

### You can search the web without setting anything up

Last release the assistant could search the web only if you ran your own search
engine. Now it uses **lynx** — a text-only browser from 1992, 641 KB, already in
Debian — and it works out of the box.

An honest note: lynx is **not** bundled in the download. It comes from Debian's
own repository like everything else on your system, so Debian ships its security
updates rather than us. The whole feature costs about **13 KB** of download.

Install with `sudo apt install ./Compiled.Builds/gorilla-opencode_0.1.78_amd64.deb`,
**not** `dpkg -i` — dpkg does not fetch what a package recommends, so it would
silently skip lynx.

### The model list now tells you what things cost

Every model says its price before anything else:

```
FREE — NVIDIA Nemotron 3 Ultra …
$0.04/$0.14 per 1M — Amazon Nova Micro …
$2.5/$12.5 per 1M — Amazon Nova Premier …
```

Free models were marked before and paid ones simply were not, so telling them
apart meant knowing that silence means paid — and 260 of 274 entries were silent.

### And what they are actually good for

Model names are meaningless to most people, and finding out what
`inclusionai/ling-3.0-tiny` is means a web search and a heavy vendor page. On a
slow connection that is not inconvenient, it is impossible. So every model now
carries a plain verdict:

```
shit tier for code — vendor calls it roleplay (vendor: "roleplay")
CAN CODE (vendor: "agentic coding")
UNTESTED for coding work — use at your own risk
```

Where the label comes from the vendor's own description, **the word that
triggered it is quoted**, so you can check the claim instead of trusting us.
Where we have used a model ourselves and it caused damage, we say so and cite
where that was recorded. Where nobody knows anything, it says exactly that
rather than guessing.

### A personal shortlist

Press **space** on any model to bookmark it, **b** to jump to your list. It works
across every provider, so the models you actually use sit in one place instead of
being hunted for among hundreds. Press space again to remove one — a list you can
only add to becomes another wall.

### Smaller things

- The model list has **ends**. It used to wrap around forever, so at 128 models
  you could scroll past the top without noticing and lose your place entirely.
- OpenRouter **works again**. Nine of its twenty-two models had been retired by
  the provider, including the two used as defaults — so setting it up produced
  something that could not answer at all.
- `gorilla-opencode models refresh` downloads the current model list yourself,
  without waiting for a release.

## Technical detail

### Web search: lynx

`source: web` resolves SearXNG (if configured) → lynx (if present) → refuse.
`Recommends: lynx`, 641 KB against a 19 MB package.

**Why lynx rather than an HTTP client.** Measured against `html.duckduckgo.com`:
curl gets HTTP 202, 14,241 bytes and 47 `anomaly` markers — a block page — while
lynx gets 3,247 bytes of real results. The block was never DuckDuckGo refusing
automation in general; it was that client.

**Why the user agent is left honest.** Claiming to be Chrome raises the hit rate
and makes failure quieter: blocked with the honest UA gives 157 bytes and
`exit 1`; blocked while claiming to be Chrome gives 1,122 bytes, `exit 0`, and a
CAPTCHA reading *"Select all squares containing a duck"*. A model handed the
second summarises the CAPTCHA.

**Success is measured in extracted results.** Both cheaper checks fail: that
CAPTCHA is exit 0, and a rate-limited DuckDuckGo returns 12,075 bytes at exit 0
with zero results.

**Engines are measured, not assumed.** External result URLs through lynx:
marginalia 43, brave 28, ecosia 27, mojeek 19, bing 7, yahoo 7, dogpile 4;
duckduckgo 0, google 0 (it refuses text browsers outright), startpage 0. Brave →
Ecosia → Mojeek → Marginalia, mainstream first. DuckDuckGo and Google are
permanently excluded.

Two parser bugs were found by running it, both producing plausible output: every
result titled "More on reddit.com", and — worse — a real title attached to the
**wrong URL**, because lynx wrapped a link label across two lines and the parser
searched forward into the next result. Fixed structurally: a marker with text
carries its own label and looking elsewhere is never allowed.

### The model catalogue

OpenRouter's list is generated by `cmd/openrouter-models` from the public
catalogue, and refreshable at runtime with `models refresh`. From 400 published
models: 67 dropped for being unable to call tools, 59 dropped as asynchronous
batch endpoints, leaving **274**.

Descriptions are built in four layers, each traceable:

1. **Earned** (`metadata/verdicts.json`) — we used it; here is what happened,
   with a citation. A test fails the build if a verdict has no evidence.
2. **Curated** (`metadata/nim.json`) — a judgement already written for the same
   underlying model reached through a different provider (23 of the 274).
3. **Vendor's claim** — classified, with the trigger word quoted.
4. **Nothing known** — said plainly.

Distribution: 87 untested, 65 research/admin, 44 mention coding, 35 shit tier,
22 CAN CODE.

The cache carries a **schema version** describing the rules that built it. A
cache built under older rules is discarded rather than trusted — added after a
stale cache silently reverted two fixes that were verified in the source and
invisible on screen.

### Bugs fixed that users are hitting today

- **OpenRouter was broken.** Nine of its 22 hand-written models no longer existed
  and a tenth could not call tools; two of the dead ones were the defaults for
  every agent. Nothing failed loudly — a stale list does not crash, it stops
  being true.
- **The model list wrapped forever.** Both ends are hard now.
- **Groq shipped Go identifiers as model names** — "Llama4Scout",
  "DeepseekR1DistillLlama70b" — with no descriptions.
- **The system prompt described tools that were switched off.** Prompt lines now
  carry `[[needs tool.x]]` and vanish with the tool. The worst case told the
  model "never say you cannot reach a page" while `tool.fetch` was disabled — an
  instruction to fabricate.
- **The env block showed no source code.** ASCII sort put 13
  `GITHUB-RELEASE-NOTES-*` files first and the 25-entry budget was gone before
  reaching `cmd/` or `internal/`. Directories now lead and version families
  collapse to one line. It also removed an accidental prompt injection: a model
  sent the single word "oi" continued the version sequence and ran
  `git tag -a v0.1.78`.

### Conventions

Built packages go in **`Compiled.Builds/`**, never the repo root. One .deb per
release looked harmless until the root held 47 of them and ate the system
prompt's directory listing.

`CLAUDE.md` and the machine-wide directives now state who this is for: people
with old hardware on single-digit-KB/s connections, often with no credit card.
Written as constraints, because a value that cannot decide an argument does not.

## Verification

**Verified:**

- Whole `./...` tree passes with `-count=1`.
- lynx backend driven against live engines: 8 hits with correct titles matched to
  correct URLs; both parser bugs pinned by regression tests from verbatim
  captures.
- `models refresh` run against the live endpoint: 400 fetched, 274 usable, 14
  free, 67 + 59 skipped with reasons stated separately.
- Bookmarks: add, remove, insertion order, mid-list removal, persistence to disk,
  retired bookmarks surviving with an explanation, and an empty list taking no
  column.
- The name guard was checked non-vacuously — its first regex missed
  "Llama4Scout" because the capital follows a digit, so it passed against the
  exact name it was written to catch.

**Not verified:**

- Search-engine reliability over time. These are the same upstreams SearXNG
  queries and they rate-limit; expect intermittent failures, reported as
  failures.
- The lynx parser is tested against Brave and Mojeek layouts; Ecosia and
  Marginalia only through the live path.
- The `sudo -n` fallback has not been exercised on a machine that actually
  prompts for a password.
- 251 of 274 OpenRouter models have never been run here. Their labels come from
  the vendor's own words, which is why the trigger is quoted.
- No live agent-loop testing of the prompt changes; only their assembly is tested.

## Upgrade notes

Nothing breaks. Install with `apt` rather than `dpkg -i` so lynx is pulled in. If
you had tried OpenRouter before and concluded it did not work — it genuinely did
not, and it does now.
