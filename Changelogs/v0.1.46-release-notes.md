# Gorilla OpenCode v0.1.46 — The interface is quick again, your mouse selects text again, and the clock was never lying about the model — only about itself

**Date:** 2026-07-28
**Previous version:** v0.1.45

---
## Why This Release Exists
You said three things felt wrong: the interface seemed sluggish, the models seemed slower, and highlighting text produced garbage in the input box. All three turned out to be real problems, but only one of them was what it looked like. The interface genuinely had slowed — by code I added in the previous release. The models were never slower; the previous release had simply stopped under-reporting how long they took by a factor of a thousand. And the highlighting problem was the program quietly taking the mouse away from your terminal.

## What You'll Actually Notice

**Redrawing the switches menu**
- BEFORE: 6.65 milliseconds, paid on every keypress and every streamed word
- AFTER: 2.05 milliseconds — quicker than before the slowdown was introduced
- Affects: everyone

**Redrawing the help list**
- BEFORE: 2.70 milliseconds
- AFTER: 1.35 milliseconds
- Affects: everyone

**Selecting text with the mouse**
- BEFORE: produced characters like [<32;71;41M in the input box, and display corruption
- AFTER: selects text as it does in any other program
- Affects: everyone

**Scrolling the conversation**
- BEFORE: mouse wheel
- AFTER: PageUp and PageDown; the wheel can be switched back on in settings
- Affects: everyone

**How long a reply took**
- BEFORE: an 84-second reply displayed as 84 milliseconds
- AFTER: 84 seconds, which is what it always was
- Affects: everyone

## Decisions & Why

**Mouse reporting is off unless you ask for it** — Asking the terminal for mouse events takes drag-to-select away from you, and the only modes available report one event per character cell crossed — a single drag fires hundreds, which is what stalled the program and spilled raw codes into your typing. (benefits: anyone who selects text, which is everyone; tradeoff: The wheel no longer scrolls unless you switch it back on. PageUp and PageDown were already there.)

**The menu remembers the size that last fitted, then checks it still fits** — Recalculating from scratch on every redraw is what made it three times more expensive. Checking rather than trusting means content that changed shape between frames still cannot spill off the screen. (benefits: everyone; tradeoff: None found. It is both faster and no less correct.)

**One prompt rule relaxed; six kept** — Anthropic published guidance saying newer models need fewer rules, and the rule they use as their example is one we also had — a blanket ban on comments. The six we kept are about verification and honesty, not style: never claim success you have not seen, do not invent file paths. Those are not the model's taste, they are its accountability. (benefits: anyone reading code the agent writes; tradeoff: You may see slightly more comments where the surrounding code has them.)

**The release tooling now refuses to commit deleted files** — It ran a blanket 'stage everything' before committing. Nine files of published research were sitting deleted in the working tree at the time and would have been written permanently into a release. (benefits: everyone, invisibly; tradeoff: A deliberate deletion now needs an explicit flag.)

## Deliberately Not Done

- **Shrinking the tool descriptions, which are eight times the size of the system prompt** — That is genuinely where the tokens are. But tool descriptions steer how the agent behaves, and this project has no way to measure whether answers got worse. Anthropic could cut theirs safely because they run coding tests against every change. Cutting ours blind risks an agent that quietly gets worse at editing files with nobody knowing why. The prerequisite is a way to measure quality, not a smaller file.
- **Making the main interface selectable and copyable** — Unchanged for three releases: it is a large rebuild of roughly 2,700 lines of layout code. The plain interface remains the way to copy a session.
- **Fixing menus for windows shorter than 24 rows** — 24 rows is the classic minimum and the line we hold. The shorter cases are recorded so they cannot quietly get worse.

## Privacy & Security
No changes to what is collected, stored or sent — nothing is. One change reduces what the program asks of your terminal: it no longer requests mouse event reporting unless you turn it on.

## Common Questions

**Q: Did you make the interface slow and then fix it?**
A: Yes. The measuring code added in the previous release re-ran on every redraw. It is now roughly a third of the cost it was, and slightly quicker than before that release.

**Q: So the models were never getting slower?**
A: Correct. The previous release fixed a bug where every duration was divided by a thousand, so an 84-second reply had been displaying as 84 milliseconds. It always took that long. If you also turned on thinking out loud, that part genuinely does add time.

**Q: Why can't I use the wheel to scroll any more?**
A: Because asking your terminal to report the wheel also takes away click-and-drag text selection, and floods the program with events. PageUp and PageDown scroll the conversation. If you would rather have the wheel, settings has a switch that explains the trade.

**Q: Should I be worried that a release nearly deleted files?**
A: It did not, and the files were never lost — they were recoverable the whole time. But the tooling would have made the deletion permanent, and now it refuses and lists what is missing instead.

## Bottom Line
This release undoes a slowdown I introduced, gives you your mouse back, and corrects one number that was still a guess. The most useful thing in it may be the explanation rather than the code: your models were never getting slower, the clock had been under-reporting them by a factor of a thousand for as long as the feature existed. The interface slowdown was real and is now slightly better than before it started. Text selection works again, at the cost of the wheel unless you ask for it back. And the honest gap: the display corruption you reported was never reproduced, so if it survives this update the diagnosis was wrong.

# v0.1.46 — undo the FitHeight render regression, make mouse reporting opt-in, calibrate the last estimate

## Architecture & Footprint

- **Toolchain:** go1.24.4 linux/amd64. No dependency changes. Built from the tag with -ldflags "-X github.com/opencode-ai/opencode/internal/version.Version=v0.1.46".
- **Flags:** No CLI flag changes. New persisted setting `mouseWheel` (default false).
- **Resource deltas:** Dialog View() cost, measured at 100x30 with the colour profile forced identically in both trees: /context 6.65ms -> 2.05ms, /help 2.70 -> 1.35, /connect 1.43 -> 1.46, /settings 1.18 -> 1.48. No binary-size, RSS or startup measurement taken, so none claimed.

## Known Issues & Deferred Work

- [medium] The display corruption reported alongside the mouse leak was never reproduced headlessly — message rendering, the reasoning block, a 4000-char unbreakable paste and the split layout all produce uniform widths, and the layout clamp passes. Attribution to the mouse flood is reasoning, not proof.
- [medium] The screen-invariant sweep covers 8 of ~15 dialog surfaces. Model picker, sessions, permissions, tasks, filepicker, theme and arguments are not included and may overflow undetected.
- [low] Dialogs still overflow terminals below 24 rows, held by a ratchet keyed by name and size.
- [low] Tool descriptions are ~3,680 tokens against the system prompt's ~464 and are the real cost centre, but there is no eval suite, so trimming them risks silent quality loss. There is ZERO duplication between prompt and descriptions and no prescriptive language in the descriptions, so the safe levers are already spent.
- [low] layout.Fitter's key is caller-supplied. A caller that omits something affecting rendered height reintroduces the stale-cache class of bug; nothing enforces key completeness.
- [medium] The TUI still renders in the alternate screen and cannot be selected or copied.
