## The interface is quick again, and your mouse selects text again

Three complaints, three real causes — but only one was what it looked like.

**In plain terms:** the interface genuinely *had* got slower, by code I added in
v0.1.45; it's now slightly quicker than before that release. The **models were never
slower** — v0.1.45 stopped under-reporting their time by a factor of a thousand, so an
84-second reply that used to read `84ms` now reads what it always was. And dragging to
select text typed garbage into the input box because the program had quietly taken the
mouse away from your terminal.

📄 **Full notes, both tracks:**
[v0.1.46-release-notes.md](https://github.com/gorillanobakaa-dot/Gorilla.Opencode/blob/v0.1.46/Changelogs/v0.1.46-release-notes.md)

### Fixed

**Dialog redraws were 2–3× more expensive.** `FitHeight` re-ran its whole
render-and-measure search on every `View()`, and Bubble Tea calls `View()` on every
keystroke **and** every streamed token — instrumented at **3 internal renders per
frame** for `/context`. Measured like-for-like at 100×30:

| | v0.1.44 | v0.1.45 | now |
|---|---|---|---|
| `/context` | 2.33 ms | **6.65 ms** | **2.05 ms** |
| `/help` | 1.28 | 2.70 | 1.35 |

The first version of that cache keyed on terminal size alone and only asked *"does the
remembered count still fit"*, never *"could more fit now"* — so one cramped selection
locked in a small list and **two commands became unreachable** while scrolling `/help`.
An existing reachability test caught it, not me.

**Dragging to select typed raw escape codes into the editor** — reported as
`[<32;71;41M`. The program requested cell-motion mouse tracking, which takes the mouse
from the terminal (you then need Shift to select) and reports **one event per cell
crossed**, so a single drag fires hundreds and stalls the loop until the input parser
spills raw codes. Mouse reporting is now **opt-in**; `/settings` has a row that states
the trade. Verified on the real binary under a pty: `?1002h` emitted **0 times off, once
on**. Scroll with `PageUp`/`PageDown`, already bound.

**One `/context` figure was still a guess.** Token costs are measured from real tool
schemas at startup — except `diagnostics`, which was skipped unless a language server
was configured. A schema is static, so with all servers off (supported) that one row
showed an estimate. Now measured unconditionally, with a test asserting no component
reports its declared value.

### Changed

**One prompt rule relaxed, six kept.** Anthropic's Claude 5 context-engineering
guidance reports removing 80%+ of their coding agent's system prompt with no eval loss,
and its worked example is a rule we also had. Ours now reads `comments: match
surrounding density and idiom` instead of `never explain WHAT/WHY`. The other six
`do not`/`never` lines were **kept**: five are verification and honesty rules (*never
claim unobserved success*, *do not invent paths*), and the guidance is about trusting
judgement on **style**, not about trusting an agent's account of its own work.

**The release tooling had five bugs, all found by using it.** It refused nothing before
committing, so `git add -A` would have baked an accidental deletion into a tag — nine
files of research were in exactly that state at the time. And its state detection was
wrong four ways: any binary on `$PATH` meant "installed" (so any release after the first
skipped everything), a binary in the tree meant "built" without checking its version, a
`.deb` *named* for the version meant "packaged" without checking its contents, and a tag
meant "built and packaged" — though the checklist says tag first, then build.

That third one **actually published**: a package whose control file said `0.1.46`
wrapped around a binary reporting `v0.1.45`. Caught by extracting the artifact after
upload, deleted with zero downloads. All five are fixed, and the generalisation is now
in `CLAUDE.md`: *an artifact's name is not its contents, and a side-effect is not a
state.*

### Install

```sh
sha256sum -c gorilla-opencode_0.1.46_amd64.deb.sha256   # or checksums.txt
sudo dpkg -i gorilla-opencode_0.1.46_amd64.deb
gorilla-opencode --version && dpkg -l gorilla-opencode | tail -1
```

Both must read 0.1.46. Quit any running copy first.

Launch the icon normally for the full interface. **Right-click the icon → "Plain
mode (copyable output)"** and the same program runs with no interface at all:
every line is ordinary terminal output, so `Ctrl+A` / `Ctrl+Shift+C` lifts a
five-hour session straight into a text editor.

### An honest caveat these screenshots happen to prove

Turn the reasoning display on and you see **everything** the model reasoned,
including what it should have kept to itself. Above, MiniMax M3 quotes a garbled
version of **our own instructions** back at the user:

> `Per my conduct guidelines: "match answer: simple question gets direct sentence."`

No prompt text here is secret — [`system-prompts/`](https://github.com/gorillanobakaa-dot/Gorilla.Opencode/tree/v0.1.46/system-prompts)
is in the repository. But a reasoning window is a window into the *whole*
request, not a curated summary. That is exactly the trade `/extras` exists to let
you make deliberately, in either direction.

### Known issues

- **The display corruption reported alongside the mouse leak was never reproduced.**
  Message rendering, the reasoning block, a 4,000-character unbreakable paste and the
  split layout all produce uniform widths headlessly. Attributing it to the mouse flood
  is reasoning, **not proof** — if it survives this release, that was wrong.
- The size sweep covers **8 of ~15** dialog surfaces; the rest may overflow undetected.
- **Tool descriptions are ~3,680 tokens against the system prompt's ~464** and are the
  real cost centre — but there is zero duplication between them and no prescriptive
  language left, so the safe cuts are spent. Trimming further without an eval risks a
  quietly worse agent. Not attempted.
- `layout.Fitter`'s cache key is caller-supplied; nothing enforces completeness.
- The main interface still cannot be selected or copied — `--plain` remains the answer.
