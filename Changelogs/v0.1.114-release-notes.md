# Gorilla Opencode v0.1.114 — the switch reaches the model

Released 21 August 2026. Replaces v0.1.113.

Two tracks below, both complete. Neither is a summary of the other.

---

## Plain-language track

### One bug, and it was lying to you

You pick a provider from the menu. The bar at the bottom immediately says the new
model. Your next message goes to the **old** one.

That was true until this release. Picking a provider wrote your choice into a
settings file. The bottom bar reads that file, so it updated at once. But the
part of the program that actually sends your message was never told, and kept
using whatever it was started with.

Nothing errored. Nothing looked wrong. You could work for an hour believing you
were on a free model while every message came off a different account's
allowance.

### How it was caught

Not by a test, and not by any label. By behaviour.

The owner switched to Claude, typed "hm", and got back an unrequested attempt to
fetch a website. He said: *"I have a feeling this is not Claude, only Llama does
that."*

He was right. The small grey label under the reply read **Llama 3.3 70B**, under
a bottom bar reading **Claude Sonnet 4.6**. The saved record agreed with the
label, not with the bar.

### Fixed, and checked in the database

Picking a provider now switches the running model too, and says so:

*"Now answering as Claude Sonnet 4.6 (Thinking) (Antigravity free)."*

If the switch fails, it says that plainly and names what you are **still** on.
Silence there is what caused the bug.

Checked in the saved session record, not only on screen:

| Session | Bottom bar said | What the record shows |
|---|---|---|
| Before | Claude Sonnet 4.6 (Antigravity free) | `local.meta/llama-3.3-70b-instruct` |
| After | Claude Sonnet 4.6 (Antigravity free) | `antigravity.claude-sonnet-4-6` |

The unrequested website fetch is gone too. Same question, no invented tool call.

### Two smaller repairs

**Sign-in could wait forever.** Every sign-in call used a connection with no time
limit at all, so one request that never came back would leave "Setting up your
free tier..." on screen indefinitely. They now give up after 45 seconds and say
so. The saved sign-in is kept either way and retries on first use.

**"Provider busy" now says which provider.** It used to name nobody, which let a
NVIDIA rate-limit be mistaken for a Google one — including by the author of this
program, who guessed wrong in writing. It now reads, for example:
`Gorilla.FREE.NVIDIA.NIM busy (rate-limit/5xx) on meta/llama-3.3-70b-instruct,
retrying 2/5 in 4.8s` — using the name **you** gave the endpoint.

## Developer track

### The bug

Two paths change the model. Only one told the agent.

| Path | Behaviour |
|---|---|
| `/model` | `agent.Update()` — creates the provider first, updates config, then swaps `a.provider`. Atomic since `1fecb4c`. |
| `/providers` | `config.UpdateAgentModel()` only. `app.CoderAgent` untouched. |

The footer sources the model from config; the request path sources it from
`a.provider`. They diverged permanently and silently.

`tui.go` gains `adoptPortalModel()`, which reads `cfg.Agents[AgentCoder].Model`
after the portal returns and routes through **the same** `agent.Update()` — not a
second implementation of it. On failure it reports that the session is still on
the old model and names it.

The previous message, *"Provider updated — use /models if you want a different
model from it"*, was itself part of the problem: it implied the switch was still
pending while the footer already claimed it had happened.

### `internal/auth` had no timeouts anywhere

Five call sites used `http.DefaultClient` — no timeout — from
`context.Background()` with no deadline: Antigravity, Gemini Code Assist (×2),
ChatGPT (×2). They now share `authHTTP()`, bounded at 45s, with `authTimeout` a
package var so the test can shorten it. The test stands up a server that accepts
the connection and never answers, and asserts the call returns.

### Diagnostic note worth keeping

`"Provider busy (rate-limit/5xx)"` exists **only** in the OpenAI-compatible
client. Antigravity has its own client and cannot emit it. That is how the
throttling was proven to be NVIDIA rather than Google — the code path, not a
hunch. The line now carries the provider and model, and for a local endpoint the
user's own name for it, because `local busy` identifies nothing when several are
configured.

### Verification

Confirmed on the installed binary and in `~/.local/share/gorilla-opencode`:

- Assistant message `model` column reads `antigravity.claude-sonnet-4-6` after
  the switch, `local.meta/llama-3.3-70b-instruct` before it.
- Before: `TOOL CALL: web_fetch -> {"url":"https://www.debian.org/"}`, finish
  `permission_denied`, plus a whole `tool` row. After: parts are `['text',
  'finish']`, finish `end_turn`, no tool calls.
- Tools still reach the Antigravity path: "list all the files in your working
  folder" produced a `Find` call with `view=tree` and a correct summary.

### Claim table

| Claim | Basis |
|---|---|
| The portal left the running agent on the old provider | measured — the `model` column of the saved messages, both sessions |
| The unrequested `web_fetch` came from Llama, not Claude | measured — the tool_call part is on the Llama-labelled message |
| The rate-limiting was NVIDIA, not Google | measured — that message exists only in the OpenAI-compatible client, which Antigravity does not use |
| `internal/auth` had no timeouts | measured — five `http.DefaultClient` call sites, now zero |
| A 45s bound is the right number | model inference — chosen as generous for small JSON calls, not measured |

### Not verified

- The timeout has not been seen to fire against a real provider; it is proven
  against a stub server that never answers.
- The renamed "busy" line has not been photographed against a live rate-limit.
