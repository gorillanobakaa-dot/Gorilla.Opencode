# Gorilla Opencode v0.1.87 — sign in with ChatGPT

Released 17 August 2026. One feature, done properly: OpenAI's coding models are now
reachable with a **ChatGPT account instead of an API key**, and a **free** ChatGPT
account is enough. No developer account, no payment method, no credit card.

This is the same document in two registers. The plain-language track assumes no prior
knowledge and omits nothing significant. The developer track is precise enough to audit
and rebuild from. Both end with a claim-source table saying which statements this release
measured and which it inferred — see [PHILOSOPHY.md](../PHILOSOPHY.md) for why.

Also folded in: two `install.sh` repairs that landed after the v0.1.86 tag and have not
appeared in a release until now.

---

## Plain-language track

### Why This Release Exists

Until this version, using an OpenAI model here meant an API key. An API key means an OpenAI developer account, which means a payment method, which means a credit card. For a lot of people that is where the road ends. A free ChatGPT account is something almost anyone can get, and it turns out that account can reach OpenAI's coding models directly. This release adds that route. You sign in through your browser the same way you sign in to any website, and the models appear. Nothing is charged to you, because nothing about this path is billed per use — your ChatGPT plan is what you already have, and the free plan costs nothing.

### What You Will Notice

**getting to OpenAI models**
- Before: You needed an API key, which needed a developer account and a payment method.
- After:  You sign in with the ChatGPT account you already have. A free one works.
- Affects: everyone

**the sign-in screen**
- Before: The list offered Google logins and a row of API-key providers.
- After:  A ChatGPT row sits second in the list, tagged free, describing exactly what you get.
- Affects: everyone

**what happens when you run out**
- Before: An API key that runs out of credit stops working until you pay more.
- After:  A ChatGPT plan does not run out of credit — it pauses you for a while and then lets you back in. You are never billed for going over.
- Affects: everyone using the new sign-in

**which models you see**
- Before: Not applicable — this route did not exist.
- After:  Two: GPT-5.5 for your actual work, and a smaller, quicker one the program uses quietly in the background for things like naming your conversations.
- Affects: everyone using the new sign-in

### Deliberately Not Done

- **The two newest models, GPT-5.6 Terra and GPT-5.6 Luna, are not offered.** — They expect the program to hand them tools in a shape this program does not speak yet. Listing them would mean you sign in successfully, pick one, and then watch it fail the first time it tries to read a file. An entry that looks like it works and does not is worse than no entry, so we left them out and said so on the sign-in screen itself.
- **No usage meter for ChatGPT.** — The Antigravity sign-in has a screen showing how much of your allowance is left. We have not found an equivalent for this one, and inventing a number would be worse than showing none.
- **The model list does not update itself.** — The two models are written down from what the service reported on 17 August 2026. When OpenAI changes the lineup, this list will need a new release; it does not notice on its own.

### Privacy & Security

Signing in stores a token from OpenAI at ~/.config/gorilla-opencode/chatgpt-oauth.json, readable only by you (mode 0600). It is kept in its own file so it cannot overwrite, or be overwritten by, the two Google sign-ins. The sign-in uses PKCE, the standard protection that stops another program on your machine from stealing the code your browser hands back. Your conversations are not stored on OpenAI's side by this route: every request explicitly asks the server not to keep a copy. The program identifies itself honestly to OpenAI as 'gorilla_opencode'; it does not pretend to be OpenAI's own tool. We do not add any telemetry, and this release does not change what anything else on your machine can see.

### How to Install

**Before you start:**
- A ChatGPT account. The free one is enough.
- A web browser on the same machine — signing in opens a browser page.
- Debian, Ubuntu or Mint for the .deb; Arch or CachyOS for the pacman package; any Linux for the tarball.

**Step 1:** Install the package.
```
sudo apt install ./gorilla-opencode_0.1.87_amd64.deb
```
✓ apt finishes without asking you to fix anything.

**Step 2:** Confirm you are running the version you installed, and that the system agrees.
```
gorilla-opencode --version && dpkg -l gorilla-opencode | tail -1
```
✓ Both say 0.1.87. If they disagree, an older copy is still first on your PATH.

**Step 3:** Start the program — either click the icon in your applications menu or run it from a terminal. The sign-in list appears.
```
gorilla-opencode
```
✓ A list of providers, with 'ChatGPT sign-in - GPT-5.5 (works on the FREE plan, no API key)' as the second row, tagged free.

**Step 4:** Move to the ChatGPT row with the arrow keys and press Enter. Your browser opens. Sign in to ChatGPT as normal and approve the request. The browser says you are signed in; go back to the terminal.
✓ The terminal reports 'Signed in as <your email> (plan: free)' and drops you into the chat.

**Step 5:** Ask it something that needs a file, to prove the whole path works, not only the login.
✓ It reads the file and answers about its actual contents.

**To go back:** Install the previous package over this one: sudo apt install ./gorilla-opencode_0.1.86_amd64.deb. Your saved sign-in stays on disk and is ignored by the older version; nothing is lost. To remove the ChatGPT sign-in itself, delete ~/.config/gorilla-opencode/chatgpt-oauth.json.

### If Something Goes Wrong

**Sign-in fails immediately, before the browser even asks you anything.**
Something else on your machine is already using port 1455. OpenAI registered that exact port for this sign-in, so we cannot quietly pick another one — a different port is rejected before you ever see a prompt.
What to do: Close whatever is using port 1455 and try again. The error message says so instead of failing silently.
Status: working as intended — the restriction is OpenAI's, not ours

**The model stops responding and mentions a limit.**
You have used your ChatGPT plan's allowance for now. This is a pause, not a bill.
What to do: Wait, or switch to the smaller model, or switch to one of the other free sign-ins. The message says 'this is your plan's usage cooldown, not a bill' precisely so it does not read as a charge.
Status: expected behaviour on a free plan

**GPT-5.6 is not in the model list.**
It is deliberately withheld. See 'what we deliberately did not do'.
What to do: Use GPT-5.5. It is the strongest model this route currently supports.
Status: deferred

**GPT-5.4 Mini stops working after 31 August 2026.**
OpenAI has announced it stops serving GPT-5.4 to ChatGPT sign-ins on that date. Nothing on this side breaks; OpenAI withdraws the model.
What to do: Use GPT-5.5. A later release will drop the dead entry.
Status: known, dated, and expected

**Your old conversations are not in the history list.**
Unchanged from v0.1.85 — the conversation store moved and the old files were not carried across.
What to do: The old files are safe in the old folder. This version still does not read them.
Status: deferred, no migration yet

### Common Questions

**Q: Is this actually free, or is it free until it isn't?**
A: It is your ChatGPT plan, whatever that plan is. If your plan is the free one, you pay nothing and you get the free plan's limits. There is no per-use charge on this route at all, which is why the model list shows no prices — showing API prices next to models that never charge you would be a lie.

**Q: Do I need a credit card at any point?**
A: No. That is the entire reason this exists.

**Q: Is this allowed?**
A: You are using your own account's own entitlement, and the program tells OpenAI truthfully which program it is. What we cannot promise is stability: this is not a published, supported interface, so OpenAI could change it and break this without warning. We say that plainly on the sign-in screen too.

**Q: How is this different from the Antigravity sign-in that is already there?**
A: Antigravity is a Google account reaching Claude, GPT-OSS and Gemini. This is a ChatGPT account reaching OpenAI's own models. They are separate accounts with separate allowances, so having both means when one pauses you, the other does not.

**Q: Why does the program use the smaller model sometimes without asking me?**
A: For background jobs you do not watch — naming a conversation, summarising an old one. A ChatGPT plan has one shared allowance, so spending the strong model on titling a chat brings your cooldown forward for no benefit you can see.

**Q: Do I have to use this? I already have a key.**
A: No. Nothing about your existing setup changes. This is one more row in a list you can ignore.

### Bottom Line

This release does one thing, and it does it properly: OpenAI's coding models are now reachable with a free ChatGPT account, so the price of entry drops from a credit card to an email address. We proved the whole path against a real free account instead of assuming it — the program signs in, streams an answer, calls a tool, reads a file from your disk and quotes it back. The honest limits are that the two newest models are not offered yet because they need a tool format we have not built, that the smaller model has a known death date of 31 August 2026, and that this rides an interface OpenAI does not publish, so it could break without notice. Nothing that already worked changes. If you have an API key and are happy, ignore this release entirely; if you never had one because you could not get one, this is the release that lets you in.

## Developer track

### Summary

This release adds provider `chatgpt`: OAuth 2.0 + PKCE (S256) against auth.openai.com, credentials at ~/.config/gorilla-opencode/chatgpt-oauth.json (0600), and a hand-built transport for chatgpt.com/backend-api/codex. The token is not an API key and does not authenticate against api.openai.com, so no existing client applies. The backend speaks the Responses API, so the transport carries its own message conversion, tool conversion and SSE parse instead of delegating to openai.go. Two of the five models the backend lists are registered; the other three are withheld with the reason stated on the portal row. The scope of change is additive: one new provider case, one new model file, one new transport, and label entries in the picker. No existing provider path changes behaviour.

### Known Alternatives Considered

Two alternatives are documented in the source. First, reusing OpenAIClient with WithOpenAIBaseURL, the pattern ProviderGROQ, ProviderXAI and ProviderDeepSeek all follow. The file header rejects it explicitly: 'The obvious guess is that a ChatGPT token is an API key with a different base URL... It is not', on the grounds that the token is only spendable at this backend and that the backend speaks Responses, not Chat Completions. Second, the thin-transport pattern of antigravity.go, which is 234 lines because code_assist.go already owns its envelope; the header records that 'there is nothing to share with openai.go' so this transport carries its own conversion. A third decision is recorded in the models file: registering all five advertised models was rejected because 'Registering the 5.6 models would put two rows in the picker that sign in fine and then fail on the first tool call, which is worse than not offering them.' A fourth is recorded in chatgpt_oauth_test.go: identifying as another client was considered and the originator remains the honest 'gorilla_opencode', pinned by a test whose failure message states that changing it 'is an explicit owner decision, not a code tweak'.

### Architecture Impact

One invariant is relaxed deliberately. internal/llm/provider/main_test.go redirects XDG_CONFIG_HOME so no test can write the developer's real config; the live probes must read a real OAuth token, so main_test.go now captures the original value in `realConfigHome` and the live test swaps it in around the credential read only. The comment states the constraint: 'Nothing may write through this.' Separately, internal/tui/startup/provider.go gains an exported ProviderModel type alias and NewProviderModel constructor so cmd/ can render the portal headlessly; AskProviders now builds through the same constructor, so behaviour is identical. No other architectural invariant changes: the ProviderClient interface, the agent loop, the message model and the config schema are all untouched.

### Subsystem Changes

**AUTH:** OAuth 2.0 authorization-code flow with PKCE S256 against auth.openai.com, offline_access for a refresh token, loopback redirect fixed at http://localhost:1455/auth/callback. The port cannot be randomised: OpenAI's client registration matches redirect_uri exactly, so a kernel-chosen port fails at the authorize step before any browser prompt. Account id and plan type are read from the namespaced claim https://api.openai.com/auth in the id_token, not from the top level; both readings are pinned by tests including a negative case.

**NETWORK:** New endpoint POST {backend}/responses?client_version=... with headers Authorization, originator: gorilla_opencode, and ChatGPT-Account-ID when present. client_version is a required query parameter, not a header; omitting it returns 400 naming ('query','client_version'). Streaming only, Accept: text/event-stream, 8 MB scanner buffer to accommodate whole tool-argument payloads arriving on a single output_item.done line.

**TUI:** One new provider row rendered in the startup portal; three new label branches in the model dialog. The portal model is now constructed through an exported constructor so its rendering can be asserted headlessly at a fixed width.

**STORAGE:** One new credential file, ~/.config/gorilla-opencode/chatgpt-oauth.json at mode 0600. No schema change, no migration, no change to the session database.

**OTHER:** Requests set store:false, so the backend is asked not to retain conversation content. parallel_tool_calls is false because the agent loop executes one call per turn.

- **Added:** cmd/chatgpt_portal_test.go — three tests: the row is offered with the right flags and states the 5.6 omission and the cooldown wording; both models are in SupportedModels, route to ProviderChatGPT, and carry zero cost; the portal renders with ChatGPT visible and no line exceeding 80 cells. internal/llm/provider/chatgpt_live_test.go — two opt-in live probes behind CHATGPT_LIVE=1: streamed text (asserts deltas arrived, not merely that content exists) and a two-turn tool exchange (asserts the call has a call_id, that arguments parse as JSON containing the required property, and that the replayed result reaches the second turn's answer). cmd/provider_portal_test.go — 'chatgpt' added to the handled-rows map.
- **Removed:** None.
- **Notes:** The portal tests are proven non-vacuous: deleting the row from providerPortalRows and repairing the resulting unused-variable compile error makes TestChatGPTRowIsOffered and TestChatGPTRowRenders both fail, while TestChatGPTModelsAreRegisteredAndRoutable correctly still passes because it asserts a different thing. ### Security Posture

No CVEs addressed and no dependency changes. Attack surface grows by one outbound HTTPS host (chatgpt.com) and one loopback listener bound for the duration of a login on 127.0.0.1:1455. PKCE S256 protects the authorization code against interception by another local process; the verifier is asserted to be 43-128 characters, unpadded URL-safe base64, and never reused across generations. No credential value is printed anywhere: login output reports the email and plan type only. The originator header states this client's real identity; it does not impersonate another, pinned by a test. store:false is sent on every generation request. One test-isolation guard is deliberately relaxed for reads only, documented in place.

### Known Issues

**[medium]** Login fails at the authorize step with a redirect_uri mismatch, before any browser prompt.
- Cause: Port 1455 is occupied, or a change randomised the callback port. OpenAI's client registration matches redirect_uri exactly.
- Remedy: Free port 1455. Do not substitute another port; it cannot work.

**[high]** 400 Unsupported parameter: max_output_tokens.
- Cause: Someone reintroduced max_output_tokens into cgRequest. The public Responses API accepts it; this backend rejects the whole request.
- Remedy: Remove the field. providerOptions.maxTokens is intentionally unused in this transport and the struct carries a comment saying so.

**[high]** 400 naming ('query','client_version').
- Cause: The client_version query parameter was dropped from the request URL. It is required on /responses as well as /models.
- Remedy: Append client_version=auth.ChatGPTClientVersion.

**[high]** Tool results are ignored and the model repeats the same call.
- Cause: function_call_output is echoing the output item's id instead of its call_id. They are different identifiers.
- Remedy: Pair on call_id. The live tool test asserts call_id is non-empty precisely to catch this.

**[low]** GPT-5.6 Terra or Luna fail on the first tool call. (deferred to unscheduled)
- Cause: Both report tool_mode code_mode_only, a tool presentation this transport does not implement. They are deliberately unregistered.
- Remedy: None. Implement code_mode_only before registering them.

**[medium]** GPT-5.4 Mini returns errors after 31 August 2026. (deferred to the first release after 31 Aug 2026)
- Cause: OpenAI withdraws GPT-5.4 for ChatGPT sign-ins on that date.
- Remedy: Drop ChatGPT54Mini from the catalogue and repoint backgroundModelByProvider at gpt-5.5. Do not debug the transport.

**[medium]** The whole provider stops working with no code change.
- Cause: This is an unpublished interface. An OpenAI-side change can break it without notice.
- Remedy: Run the live probes to see what the backend now says, then adjust the wire shape.

**[low]** The model list is out of date relative to what the account can reach. (deferred to unscheduled)
- Cause: ChatGPTModels is a hardcoded snapshot taken on 17 August 2026 and does not self-refresh the way BuildAntigravityModels does.
- Remedy: Re-read GET /models?client_version=... and update the file, or implement a refresher.

**[medium]** Old conversations are missing from the history list. (deferred to unscheduled)
- Cause: Unchanged from v0.1.85: the session store moved and the previous files were not migrated.
- Remedy: The old files remain in the old location. No migration exists.

**[low]** TestExactLongPromptWrapsAtTerminalWidth passes against a reverted fix. (deferred to unscheduled)
- Cause: Unchanged from v0.1.86: the test is vacuous with respect to measuredRows().
- Remedy: Write a screen-driven regression test. Re-confirmed vacuous with -count=1.
