# Gorilla OpenCode 0.1.156: Mac, Windows and Linux

**The Windows program now really carries its built-in toolbox, the AI can list every file with its owner, creation date and permissions in one go, and it can pack a folder into a zip, 7z or tar.xz archive the right way.**

## What is this program?

Gorilla OpenCode is a program you talk to by typing. You write what you want in
ordinary words, for example *find out why this program will not start*, and an
AI does the work: it opens the files on your computer, runs commands, reads what
they print, and tells you what it found.

It is free. It has no account of its own. You choose which AI it uses: one that
runs entirely on your own computer, or one from a company you have a key or a
sign-in for. It is built to work on an old laptop with slow, expensive internet.

## Should you download this version?

**Yes, if you use it on Windows.** Version 0.1.155 was meant to carry seven
helper programs inside it (the toolbox: coreutils, ast-grep, difftastic,
hyperfine, ninja, sd and pfind). The published file was built without them.
This one has them, and the build now checks for them and refuses to finish
without them. You also get two things the AI could not do well before: list
all the files in a folder with their owner, creation date and permissions,
and make an archive of a folder.

**Yes, if you use it on Linux or a Mac, for the two new file features.** The
list with details works there too (owner, group and permissions). Archiving
works as zip everywhere; 7z, tar.xz and password-protected zip need the
`bsdtar` program (Debian and Ubuntu: the package `libarchive-tools`; tar.xz
also works with ordinary GNU tar).

**Know before you update:** the Windows program is not signed. No
code-signing certificate exists yet. The Windows file is about 27 MB larger
than 0.1.155, because the toolbox is now really inside it.

## Why this matters to you

The owner typed two everyday requests into 0.1.155 with ChatGPT's lightest
model (GPT-6-Luna). *"List all your files and their attributes in the working
folder"* got back only the attribute flags (read-only, hidden), nothing about
who owns each file or when it was made. *"Archive all the files in the working
folder"* made the AI write its own little program, which put the zip file
inside the very folder it was packing, without asking anything. Both requests
now take one step each, the archive goes next to the folder, and the AI tells
you which defaults it used and what else you could have asked for. The same two
sentences were typed again into this version, with the same model: both came
out right.
